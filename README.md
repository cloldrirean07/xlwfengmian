## Recommended Top-Level Structure

  Runnable product surfaces.

  Reference visuals, screenshots, generated images, and raw source materials.

  Reusable setup, sync, and analysis scripts.
- `outputs/`
  Generated reports, exported previews, and non-source deliverables.

## Placement Rules

- Put product positioning, boundary decisions, user definitions, and milestone thinking into `docs/product/`.
- Put interview records, sample analysis, competitor notes, and validation conclusions into `docs/research/`.
- Put formal requirement documents and versioned PRDs into `docs/prd/`.
- Put code-structure notes, API contracts, and implementation decisions into `docs/architecture/`.
- Put runbooks, sync conventions, and release or maintenance notes into `docs/operations/`.
- Put reusable rule tables, case labels, and feedback mappings into `data/`.
- Put reference screenshots, ad examples, generated covers, and source images into `assets/`.
- Put final generated reports and exported artifacts into `outputs/`, not back into source folders.

## Working Principle

Use Obsidian as the primary thinking space for long-form product work.
Use this repository as the structured execution layer for anything that needs stable storage, iteration history, implementation connection, or future automation.

## Practical Rule For Next Steps

- If you are writing or changing product logic, work in `apps/web/`.
- If you are整理产品方案, put it in `docs/`.
- If you are做界面草图 or流程图, put it in `prototypes/`.
- If you are沉淀规则、案例、反馈映射, put it in `data/`.
- If you are收集封面截图、广告参考、用户素材, put it in `assets/`.
- If something is generated by scripts, store it in `outputs/`.
