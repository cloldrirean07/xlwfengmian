Decision Frame

系统当前怎么判断

这不是一句 Prompt 换写法。

当前系统会先缩小“哪种点击机制更值得优先尝试”，再决定用什么图、什么文案和什么构图去承接。

先看内容任务

这条内容更需要被“看懂”、被“相信”，还是先让人“停住并点开”。

再看现有素材

用户是只有截图、有人像、有场景，还是根本没有可用图，这决定先改现有图还是先补贴内容的图。

最后给 3 个有差异的方向

不是换同义词，而是让每张卡的主变量不同，便于用户真的做选择和迭代。

更清楚重点 更有收获感 更让人想点开 更有冲击力 更高级专业

Writeback State

写回态

汇总 UI 就绪度、跨批次摩擦点、人工结论和安全写回状态，确认门禁完整后再进入正式写回。

输入：批次证据与人工结论 产出：复盘看板、安全预览与写回状态 去向：规则修订、关键复跑或正式写回

Formal Write Gate

写回门禁工作台

基于多批次证据判断是否进入 UI 讨论、是否沉淀规则修订任务，并确认正式写回前的安全预览与人工结论。

用途：写回门禁与规则沉淀 触发：安全预览进入人工确认 产出：写回状态与承接任务
写回门禁总览 UI 时机判断 跨批次信号 复盘看板

Gate Overview

正式写回门禁总览

查看复盘看板

正式写回必须先经过安全预览、人工确认、状态检查和读回校验；当前页面只聚合入口，不替代人工判断。

刷新后将展示最新安全预览、人工确认和正式写回许可。

01 生成安全预览

先把建议改写结果导出为可编辑预览，保留当前记录原文和拟写回版本。

02 补齐人工确认

在 Obsidian 预览文档中填写人工结论、确认字段、仍需手改和写回判断。

03 检查写回状态

读回最新安全预览，确认人工结论有效且仍需手改为空。

04 执行正式写回

门禁满足后再覆盖真实批次记录，并生成规则修订与关键样例复跑任务。

UI Readiness Gate

UI 优化进入条件报告

用于判断当前是否已经积累足够真实批次证据，是否值得进入主链路 UI 优化讨论。

生成报告后将展示 UI 讨论时机、证据覆盖度和主要风险。

Cross-Batch Signals

跨批次摩擦点汇总

用于横向比较已导出的多批次试跑记录，识别重复摩擦点和更值得进入 UI 讨论的稳定问题。

生成汇总后将展示最常重复的摩擦点类别、推荐动作和 UI 讨论时机。

Review Dashboard

批次复盘看板

用于汇总最近人工结论覆盖状态、跨批次重复信号和 UI 时机判断，并形成下一批优先补齐项；正式复盘材料可通过复盘套件一次性导出。

生成看板后将展示当前最该补的批次、人工复盘趋势和 UI 讨论缺口。
