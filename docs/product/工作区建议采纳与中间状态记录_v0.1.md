# 工作区建议采纳与中间状态记录 v0.1

## 文档目的

这份文档记录：为什么在 `工作区建议已经能进入二轮上下文` 之后，下一步要继续补 `采纳 / 不采纳` 与 `中间状态记录`。

这一层的目标是把产品从：

- 会连续给建议

进一步推进到：

- 会留下过程痕迹
- 会保存用户关键决策
- 能支持后续复盘和版本追踪

## 当前实现了什么

### 1. 工作区建议支持采纳 / 不采纳

现在当工作区建议生成后，前端会提供两个明确动作：

- `采纳这次工作区建议`
- `这次建议不采纳`

这一步的意义是：

- 不再把建议默认为已经被采用
- 开始显式记录用户决策

### 2. 每次决策会保存为代码侧中间状态

当前保存后会生成：

- `result.json`
- `summary.md`

目录位置：

- `apps/web/outputs/workspace-decisions/<decision-id>/`

这样每次关键过程节点都会留下可以回看的记录。

### 3. 中间状态可导出到 Obsidian

当前已新增脚本：

- `npm run export:obsidian-workspace-decision -- --decision-id <id>`

导出位置：

- `05_验证与实验/工作区建议记录/已生成记录/`

这一步很重要，因为你前面一直要求：

- 产出内容要进入 Obsidian
- 能后续编辑
- 能成为版本化项目资料的一部分

### 4. 前端会显示这次记录是否已保存

当前工作区区域现在会显示：

- 是否已经采纳 / 不采纳
- 当前记录编号
- 对应代码侧 markdown 路径

这让用户知道这次建议不是临时结果，而是已经变成一条被记录下来的中间状态。

## 为什么这一层很关键

### 1. 建议系统第一次具备“过程记忆”

如果没有这层，用户虽然会一路走流程，但系统不会留下任何“这次为什么这么走”的痕迹。

有了这层后，产品开始能记录：

- 你看到了什么建议
- 你采纳了还是没采纳
- 当时的工作区内容是什么

### 2. 它为复盘和规则修正提供基础数据

未来你很容易围绕这些记录去看：

- 哪类建议更常被采纳
- 哪类工作区更容易被否定
- 哪些规则需要重写

### 3. 它让产品更像真实 PM 项目，而不是 demo

真正的产品系统，不只是有页面和生成结果，还需要：

- 过程记录
- 决策记录
- 可追踪中间状态

这一层正是往这个方向推进。

## 当前故意没有做什么

这一版还没有做：

- 一个用户多次采纳记录的汇总看板
- 采纳/不采纳原因的强制填写
- 自动把中间状态回写到案例库
- 中间状态和二轮结果的自动关联图谱

这些都适合后续继续扩，但当前先把“保存能力”和“导出能力”打通更重要。
