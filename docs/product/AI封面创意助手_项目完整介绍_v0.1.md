# AI封面创意助手项目完整介绍 v0.1

## 1. 项目定位

AI封面创意助手是一个面向成长型内容创作者的垂直 AI 产品，聚焦内容发布前的封面点击率提升问题。它不是泛创作助手，也不是自动剪辑或自动发稿工具，而是围绕封面图、标题和点击心理，帮助用户更快做出更容易被点开的封面方案。

产品核心目标是：帮助用户把已有内容想法、已有图片内容和模糊的封面感觉，转化为更有点击欲的封面方向、标题建议与构图建议。

## 2. 目标用户

- 抖音、小红书等内容平台上的成长型创作者
- 刚起号但在持续更新的人
- 已经有内容想法，但不知道封面该怎么做的人
- 对点击率、播放率和内容起量有明确期待的人

这类用户的共性不是不会做内容，而是不知道什么封面更容易吸引点击，往往只能依靠刷对标、模仿热门或凭个人感觉完成封面判断。

## 3. 核心问题与用户痛点

这个项目要解决的核心问题是：当用户已经有内容和发布意图时，如何更快判断什么封面、什么标题配法、什么视觉方向更容易让人点开。

当前用户痛点主要集中在以下几类：

- 不知道什么封面更吸引点击
- 现有方案过于泛化，缺少对平台点击心理的理解
- 通用 AI 能生成内容，但不够懂封面创意与内容适配
- 用户往往说不清“想要什么封面感觉”，导致创作起点模糊
- 封面、标题和图片之间缺乏统一判断逻辑

## 4. 产品价值主张

AI封面创意助手的价值不在于“生成一张图”本身，而在于提供一套围绕点击率提升的封面判断系统。它的目标不是优化完播率或内容满意度，而是提高点开前的吸引力。

核心价值包括：

- 帮用户做出更像平台热门内容的封面方向
- 帮用户减少“该做什么封面”的判断成本
- 将模糊需求转化成可执行的封面策略
- 提供建议与结果并重的产出形式，兼顾新手与进阶用户

## 5. 产品差异化

与通用 AI 或普通封面模板工具相比，这个产品的差异化主要体现在四层：

### 5.1 更懂点击心理

产品不是简单推荐图片，而是围绕风险损失、结果承诺、好奇悬念、反差冲突、信息清单等点击诱因进行判断。

### 5.2 更懂内容适配

产品会结合用户内容主题、内容目标、素材类型、素材描述和封面倾向来判断什么图更适合这条内容，而不是给一个泛泛的热门模板。

### 5.3 更懂封面这个独立问题

大部分 AI 更擅长写文案、写脚本或写标题，而这个项目将封面作为独立高价值场景来解决。

### 5.4 更像顾问而不是纯生成器

产品不是只给一句建议，也不是一步全自动包办，而是通过“建议 + 结果包”的方式支持用户判断、比较与调整。

## 6. 产品形态与使用方式

第一版最适合的产品形态是网页 / H5 工作台，后续可演进为小程序。它既要满足手机端的便利化使用，又要保留电脑端的专业化空间。

典型使用方式如下：

1. 用户输入内容主题、内容目标和平台
2. 用户上传截图、现有图片，或补充素材描述
3. 系统判断当前内容更适合的封面效果方向
4. 系统输出 3 个封面方向及对应标题、配图和构图建议
5. 用户选择一个方向并给出一句反馈
6. 系统进入二轮修订，进一步贴近用户意图

### 6.1 素材来源体系

产品中的封面创意素材来源分为四层：

1. 用户自己的素材：实拍照片、内容截图、产品图、口播画面、手机相册里的内容相关图片。
2. 平台热门封面样本：小红书、抖音等平台上的同类热门封面、标题和视觉结构。
3. 创意参考素材库：优质摄影作品集、摄影师作品页、海报设计、品牌大片、广告视觉、构图和氛围参考。
4. 经典广告创意案例：广告灵感案例、创意奖项案例、品牌传播案例和专业拆解。

这四层不是等价素材池。用户自己的素材负责贴合内容，平台样本负责贴合平台语境，创意参考素材库负责提供更高级的视觉方向，经典广告案例负责沉淀创意机制和判断依据。

## 7. MVP 范围

### 7.1 第一版要做的内容

- 第一轮输入与方向判断
- 三个封面方向输出
- 每个方向的标题建议、配图建议、构图建议和风险提醒
- 工作区深化建议
- 一句话反馈触发的二轮修订
- 真实案例记录与复盘沉淀

### 7.2 第一版不做的内容

- 自动剪视频
- 全自动代发
- 多平台分发
- 复杂账号数据分析
- 大而全创作后台
- 完整自动生图闭环

## 8. 方法论与规则体系

这个项目的方法论核心不是“接一个大模型”，而是三层能力的组合：

### 8.1 规则系统

产品已将 5 类封面效果方向沉到规则层：

- 强信息感
- 强结果感
- 强悬念感
- 强冲突感
- 强质感感

每个方向都包含用户可见标签、点击机制、适用内容、风险边界、封面大字模板、标题模板、按素材类型拆分的配图策略和构图建议。

### 8.2 案例库

案例体系包含广告灵感案例、平台优质封面案例、真实案例和人工复盘记录。案例的作用不是展示数量，而是沉淀判断依据、反馈模式与误判样本。

其中，创意参考素材库属于案例体系与素材体系之间的桥梁：它不直接等于用户要发布的封面素材，而是用来提炼构图、主体关系、光影氛围、视觉质感和创意表达方式。

### 8.3 大模型生成

大模型主要负责把规则和案例转化成用户可用的结果，而不是脱离约束自由生成。未来的优势来自“规则系统 + 案例库 + 大模型生成”的组合，而不是单一模型能力。

## 9. 当前产品主链路

当前产品主链路已经收束为：

输入准备 -> 首轮方向判断 -> 工作区深化 -> 建议采纳反馈 -> 二轮修订 -> 案例沉淀与复盘

在这个过程中，系统会逐步帮助用户完成：

- 输入结构整理
- 点击机制判断
- 三方向结果比较
- 配图策略排序
- 反馈映射与二轮修订
- 真实案例记录和复盘导出

## 10. 当前工程与代码架构

当前 Web 应用已形成稳定分层：

- application：用例编排层
- domain：业务能力核心层
- infrastructure：外部资源接入层
- server：HTTP 服务入口层
- shared：通用基础层

其中 domain 已按子域拆分为：

- analysis
- cards
- directions
- effects
- refinement
- review
- cases
- workspace
- ui

这说明项目已经不是单页 demo，而是一个可持续扩展的工作台式产品。

## 11. 当前阶段判断

项目当前已经具备：

- 第一轮输入与方向判断
- 三张方向卡输出
- 第二轮 refinement
- Prompt / LLM Draft 预览
- 真实案例录入与重读概览
- 案例回填、批次复盘和写回链路

但以下部分仍在收敛：

- 输入字段边界
- 规则系统与案例映射
- 真实案例链路
- 更真实的模型输出与结果解释

因此当前更适合继续补主链路、补案例与补规则，而不是立刻做大规模 UI 重写。

## 12. UI 优化时机判断

UI 并不是不做，而是需要在主链路稳定后进入。

建议在以下条件同时满足后，再专门进入系统性 UI 优化讨论：

- 已跑通至少 2 到 3 条真实案例完整链路
- 输入字段与方向卡核心字段基本稳定
- 二轮 refinement 的输入输出结构稳定
- 可以区分高频使用区和低频运维区
- 已经知道用户最容易卡在哪一步
- 前端状态管理和 API 返回结构短期内不会大改

当前阶段更适合做轻量 UI 收口，例如：

- 分区命名更清楚
- 高频动作前置
- 结果区更易扫描
- 按钮语气更明确

## 13. 验证与后续路线

这个项目后续的验证重点不是单次主观好看，而是“是否比通用 AI 更有帮助”。

建议的验证方式包括：

- 真实案例试跑
- 自测账号验证
- A/B 对比不同封面方案的点击偏好
- 用户主观评分
- 对误判样本进行规则修订与关键案例复跑

后续路线建议为：

1. 继续稳住规则层和案例闭环
2. 扩充真实案例与反馈映射
3. 接入更真实的模型输出
4. 在主链路稳定后进入系统性 UI 优化
5. 再判断是否需要更完整的 Web v2 或视觉重构

## 14. 一句话总结

AI封面创意助手是一个面向成长型内容创作者的垂直 AI 产品，聚焦内容发布前的封面点击率提升，通过规则系统、案例库和大模型生成，为用户输出更有点击欲的封面方向、标题建议和构图方案，并支持基于反馈的二次优化与案例复盘沉淀。
