# 平台案例单案例复核与字段质量检查 v0.1

## 目标

这份能力是给单个平台案例用的，不只是判断“有没有填”，而是进一步判断“填的内容能不能拿去生成和 sync”。

它解决的是 4 个问题：

- 当前平台案例完整度到了哪一步
- 当前关键字段哪些还缺失
- 哪些字段虽然写了，但质量还不够
- 当前是否值得进入 sync

## 当前脚本

- `npm run report:platform-case-review -- --platform-case-id P-01`
  生成单案例复核 JSON 和 Markdown 底稿。
- `npm run export:obsidian-platform-review -- --platform-case-id P-01`
  把单案例复核底稿导出成可继续编辑的 Obsidian 草稿。

## 输出位置

代码仓库：

- `apps/web/outputs/reports/platform-case-review/P-01.json`
- `apps/web/outputs/reports/platform-case-review/P-01.md`

Obsidian：

- `05_验证与实验/平台案例复核总览/已生成记录/`

## 当前质量检查逻辑

重点检查 10 个生成前高价值字段：

- 内容主题
- 内容目标
- 来源链接或素材路径
- 主体描述
- 视觉焦点
- 主点击机制
- 主封面方向
- 正向反馈词
- 可能调整方向
- 一句话结论

当前会区分三种状态：

- `missing`
  完全未填
- `weak`
  已填，但仍像占位词、太短或格式不足
- `usable`
  当前可直接用于后续生成或 sync 判断

## 为什么这一步重要

- 只看完整度，很容易把“写了两个词”的字段误判成可用
- 单案例复核稿比批量看板更适合你真实推进 `P-01`
- 这也是后续做“回填建议”与“自动补全顺序”的基础层

## 当前最适合怎么用

1. 先跑单案例复核，确认当前最优先缺口。
2. 根据复核稿补 `P-01` 的关键字段。
3. 再跑一次复核，看质量状态是否提升。
4. 当完整度和质量都过线后，再进入 sync。
