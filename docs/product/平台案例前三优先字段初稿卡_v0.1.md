# 平台案例前三优先字段初稿卡 v0.1

## 目标

这层能力比“补写草稿”更聚焦。

它不是把所有字段都展开，而是只抓当前最重要的前 3 个字段，给出：

- 为什么先补
- 修改提醒
- 候选提示
- 可编辑初稿

## 当前结构

- `src/domain/cases/buildPlatformCasePriorityDrafts.js`
  负责从当前补全顺序中抽出前 3 个字段，生成字段初稿卡。
- `src/domain/cases/buildPlatformCasePriorityDraftsMarkdown.js`
  负责把字段初稿卡整理成可读的 Markdown。
- `src/domain/cases/buildObsidianPlatformCasePriorityDraftsRecord.js`
  负责包装成 Obsidian 可继续编辑记录。
- `src/application/runPlatformCasePriorityDrafts.js`
  负责整合复核、候选填写与初稿卡。

## 当前输出位置

代码仓库：

- `apps/web/outputs/draft-cards/platform-cases/P-01.md`
- `apps/web/outputs/draft-cards/platform-cases/P-01.json`

Obsidian：

- `05_验证与实验/平台案例前三字段初稿卡/已生成记录/`

## 当前对 P-01 的意义

系统已经把前三优先字段明确收敛成：

1. 内容主题
2. 来源链接或素材路径
3. 主体描述

并且每项都不再只是“提示”，而是给出一条可直接改的初稿句子。

## 为什么这一步重要

- 当字段很多时，人容易继续拖延
- 收缩成 3 张卡，执行阻力更低
- 这也是后续做真正的表单式录入 UI 的前一步

## 下一步建议

- 把这 3 张卡直接映射到原始平台案例笔记相应段落
- 增加“改写后重新复核”按钮
- 增加字段卡之间的联动，例如主题变了时同步刷新主体描述提示
