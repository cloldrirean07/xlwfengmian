# 真实批次试跑执行模板 v0.1

## 适用场景

当你准备正式拿 2 到 3 批真实案例来验证产品时，可以直接按这份模板执行。

它不是“复盘总结”，而是“实际试跑前就可以照着做”的操作模板。

## 一批的建议规模

建议每批：

- `2-5` 条真实案例
- 同一内容赛道或相近赛道
- 同一阶段目标

不要一批里混太多差异极大的内容类型，否则很难判断问题到底来自：

- 规则系统
- 输入结构
- 工作流设计
- 还是赛道本身差异

## 一次试跑前要先确定的 5 件事

1. 这批案例来自哪个赛道  
例：知识口播、情绪观点、生活建议、经验分享

2. 这批案例当前共同目标是什么  
例：验证封面建议是否更有点击欲、验证批量工作单是否真有用

3. 这批案例当前共同卡点是什么  
例：不会做封面、不会选图、不知道标题怎么搭

4. 这批试跑最想回答什么问题  
例：比通用 AI 是否更有帮助

5. 这批试跑结束后，你准备依据什么决定下一步  
例：继续补规则、改输入、还是进入 UI 优化

## 建议执行顺序

### 第 1 步：整理一批案例输入

每条案例至少准备：

- 内容主题
- 内容目标
- 素材描述或截图信息
- 平台案例编号
- 你当前觉得最卡的点

### 第 2 步：在批量真实案例工作区录入

使用当前页面能力：

- 加载批量模板
- 修改为这一批案例
- 预览批量骨架

### 第 3 步：看批量结构质量

关注：

- 缺失字段总数
- 最常缺的字段
- 每条案例下一步任务

如果这一步已经明显混乱，不要急着继续导出工作单，先回头收缩输入结构。

### 第 4 步：生成并导出批量回填工作单

关注：

- 推荐动作是否合理
- 工作单是否真能指导下一步补字段
- Obsidian 导出是否顺畅

### 第 5 步：生成批次试跑记录

关注：

- 这批案例最卡在哪
- 哪些字段最难补
- 和通用 AI 相比哪里更强、哪里还不够
- 这些问题主要落在哪类摩擦点里

## 建议按 5 类摩擦点来记录

每批不要只写“感觉哪里不顺”，建议固定按下面 5 类记：

1. 输入准备与案例结构  
   例如：哪些字段用户最难准备、哪些输入项太重。

2. 补写建议与优先顺序  
   例如：系统有没有真的告诉用户下一步该先做什么。

3. 结果阅读与选择判断  
   例如：用户看完结果后，能不能立刻知道先做哪条。

4. 导出沉淀与后续接力  
   例如：导出后文档是否真能继续补，还是只是存档。

5. 是否进入 UI 优化讨论  
   例如：当前问题到底是功能逻辑、输入结构，还是界面组织。

## 每批必须回答的 8 个问题

1. 这批案例是否真的适合放在一起验证？
2. 这批案例最常缺的是哪些字段？
3. 产品给的“先补什么”是否合理？
4. 批量工作单是否真的节省了整理时间？
5. 哪一步最费脑力？
6. 哪一步最机械、最适合后续优化成更强引导？
7. 和通用 AI 相比，这个产品真正多了什么价值？
8. 这批跑完后，是更该补规则，还是更该优化 UI？

## 建议记录格式

每批至少记录：

- 批次标签
- 案例数
- 赛道
- 共同目标
- 最卡环节
- 产品最有价值的输出
- 最没价值或最啰嗦的步骤
- 是否进入 UI 优化讨论

如果你想更严格一些，建议每批再补：

- 哪个摩擦点类别最重
- 哪个类别最可能通过规则改进解决
- 哪个类别更像 UI 问题

## 什么时候适合进入 UI 优化讨论

建议满足以下至少 3 条：

- 已跑完 `2-3` 批真实案例
- 每批都有结构化试跑记录
- 你已经能明确说出“哪一步最卡”
- 你已经能明确说出“哪个模块应该前置/后置”
- 你已经能区分这是“功能问题”还是“界面问题”

## 当前建议

你现在下一步最适合的动作不是继续加很多新功能，而是：

1. 选第一批真实案例
2. 跑完整批量链路
3. 导出工作单
4. 导出批次试跑记录
5. 连续跑 2 到 3 批
6. 再正式进入 UI 优化讨论
