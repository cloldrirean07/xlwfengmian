# 工作区内下一轮建议 v0.1

## 文档目的

这份文档记录：为什么在 `首轮分支工作区` 已经生成之后，下一步要继续补 `工作区内输入控件 + 路径内建议生成`。

当前目标不是把工作区一次做成完整编辑器，而是先完成一个关键闭环：

- 用户进入某个工作区
- 填写该路径下的关键信息
- 系统返回一条更具体的下一轮建议

这意味着工作区第一次真正“活起来”。

### 前端

- `apps/web/public/app/renderers.js`

## 当前实现了什么

### 1. 每类工作区有自己的输入 schema

当前三类工作区已经各自有独立输入字段：

- `optimize-current`
  例如：想保留的主体、想弱化的部分、当前图最不满意的问题
- `search-matched`
  例如：最适合补什么主体、不要什么风格、想强化什么点击点
- `concept-first`
  例如：第一眼主体、情绪/冲突、要避免的廉价感

这一步的意义是：

- 工作区开始真正有“自己的任务”
- 不再只是静态说明块

### 2. 新增工作区建议生成接口

当前已新增：

- `POST /api/action-workspace`

接口输入：

- `analysis`
- `workspaceInputs`

接口输出：

- `workspace`
- `suggestion`

其中 `suggestion` 目前包含：

- `summary`
- `refinedTask`
- `nextSuggestion`
- `riskChecks`
- `draftPromptLine`
- `recommendedFollowUp`
- `linkedDirection`

### 3. 前端工作区已经能填写并生成结果

现在页面里的 `下一步工作区` 不只是看板，还已经包含：

- 路径内输入表单
- 生成建议按钮
- 工作区建议结果区

这意味着用户在首轮之后，已经能继续往下走一步。

## 为什么这一层很关键

### 1. 它让产品第一次具备“连续操作流”

之前产品的主要路径是：

- 输入
- 出 3 张方向卡
- 看解释

现在变成：

- 输入
- 出 3 张方向卡
- 进入路径工作区
- 补路径信息
- 生成路径内建议

这已经明显更接近真实产品体验。

### 2. 它让工作区从“展示结构”变成“交互结构”

如果工作区只展示：

- 目标
- 检查点
- 建议输入

用户看完仍然要自己想下一步怎么做。

现在系统开始能够接住这一步。

### 3. 它为后续更多层级生成留好了接口

以后很自然可以继续扩成：

- 工作区输入后自动生成更具体卡片
- 工作区输入后生成图像建议
- 工作区输入后产生可保存中间状态

## 当前三类工作区分别会生成什么

### 1. 现有图提炼工作区

当前会根据：

- 保留什么主体
- 弱化什么噪音
- 当前最不满意的问题

输出：

- 优先处理哪类画面问题
- 一条可直接用于后续生成的提示语
- 两条风险检查

### 2. 补图推荐工作区

当前会根据：

- 想补什么主体/场景
- 不要什么风格
- 想强化什么点击点

输出：

- 补图方向总结
- 应优先围绕什么去找图
- 后续应如何回到版式决策

### 3. 概念主体生成工作区

当前会根据：

- 第一眼主体
- 情绪/冲突
- 要避免的廉价感

输出：

- 概念主体建议
- 核心冲突表达
- 继续往生图/真实图方向推进的建议

## 当前故意没有做什么

这版仍然没有做：

- 工作区输入保存
- 工作区建议回写首轮分析
- 多轮工作区连续状态管理
- 工作区建议直接触发生图或找图

这些都适合后续继续加，但当前先把：

- schema
- session
- API
- 前端交互

这条链打通更重要。

## 下一步最适合继续做什么

在这层基础上，下一步最值得继续做的是：

1. 让工作区建议可以进入后续二轮反馈
2. 给工作区结果增加“采纳 / 不采纳”反馈
3. 给不同工作区增加可保存的中间状态
