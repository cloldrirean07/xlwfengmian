# 平台案例到真实案例同步说明 v0.1

## 文档目的

这份文档说明当前新增的 `platform note -> real-case` 同步能力是做什么的。

它解决的问题是：

- 平台案例笔记在 Obsidian 里补了一次
- 代码侧 `real-case JSON` 还要不要再手工补一遍

当前答案是：开始不需要完全手工双写了。

## 当前代码落点

- 平台案例笔记解析：`apps/web/src/domain/cases/parsePlatformCaseNote.js`
- 字段映射构建：`apps/web/src/domain/cases/buildRealCaseUpdateFromPlatformNote.js`
- 同步脚本：`apps/web/scripts/sync-platform-note-to-real-case.js`

## 当前第一版同步范围

这一版先只同步最关键、最稳定的字段：

- `content_topic` -> `contentTopic`
- `content_goal_guess` -> `contentGoal`
- `link_or_asset_path` -> `evidence.sourceLink / evidence.screenshotPath`
- `subject_description + visual_focus` -> `assetDescription`
- `composition_features + color_mood_features + title_cover_relationship` -> `assetNotes`
- `likely_positive_feedback` -> `referencePreference / mockUserSelection.preserveElement`
- `possible_adjustment_direction` -> `mockUserSelection.feedback`

## 为什么先只做这部分

因为这批字段最直接影响：

- readiness 状态
- fill sheet 的缺失项
- 后续方向分析的输入质量

先把这批字段打通，比一开始追求“所有字段都自动同步”更稳。

## 当前命令

先看预览，不落盘：

```bash
cd /Users/xlw/Documents/shige/ai-cover-creative-assistant/apps/web
npm run sync:platform-note -- --case-id real-001
```

如果确认预览没有问题，再写回：

```bash
cd /Users/xlw/Documents/shige/ai-cover-creative-assistant/apps/web
npm run sync:platform-note -- --case-id real-001 --write
```

如果你希望写回后顺手刷新后续产物，也可以直接：

```bash
cd /Users/xlw/Documents/shige/ai-cover-creative-assistant/apps/web
npm run sync:platform-note -- --case-id real-001 --write --refresh-artifacts --export-obsidian
```

## 当前行为说明

默认是 `dry-run`：

- 不会改 JSON
- 只打印提取到的字段
- 只展示合并后的预览结果
- 会展示同步前后哪些字段发生变化
- 会展示 readiness 前后状态和完成项数量
- 会生成一份本地 sync log
- 如果带 `--export-obsidian`，还会生成一份 Obsidian 同步记录

只有加了 `--write` 才会真的更新 `real-case JSON`。

## 当前阶段的意义

这层能力加上后，真实案例开始形成更顺的路径：

1. 先在 Obsidian 平台案例里回填
2. 用 `sync:platform-note` 预览同步结果
3. 没问题再写回 `real-case`
4. 可选：用 `--refresh-artifacts --export-obsidian` 一次性刷新后续状态
5. 再继续做验证或规则修订

这样后续你补案例，会越来越接近“在一个地方主填，另一边自动承接”。
