# 平台案例初稿安全回填器 v0.1

## 目标

这层能力解决的是最后一公里问题：

- 前面系统已经能生成复核结果、补写草稿、前三字段初稿卡
- 但如果不能安全写回原始平台案例笔记，推进仍然会断在“看建议”

所以这次增加的是：

- 只回填前三优先字段
- 统一加上 `待确认草稿` 标记
- 避免把草稿误写成最终事实

## 当前结构

- `src/domain/cases/applyPlatformCaseDraftUpdates.js`
  负责把指定字段值安全替换回平台案例 Markdown。
- `scripts/apply-platform-case-priority-drafts.js`
  负责读取前三字段初稿卡，并写回原始平台案例笔记。

## 当前策略

- 只写入前三优先字段
- 只写可编辑初稿，不写“系统已确认”的措辞
- 所有写回值都带 `[待确认草稿]`

## 当前对 P-01 的实际效果

这次已经成功写回：

- `content_topic`
- `link_or_asset_path`
- `subject_description`

写回后系统重新复核，状态变成：

- 完整度：`5/12`
- 质量：`3/10`

## 为什么这一步重要

- 它让系统第一次真正推动了原始案例笔记本身
- 不是只在验证目录里生成草稿，而是能影响主工作文件
- 这也是后续做“一键回填 + 一键复核”闭环的基础

## 下一步建议

- 增加回填前后的 diff 记录
- 增加只回填空字段 / 强制覆盖两种模式
- 增加回填后自动重新生成复核与初稿卡
