# 工作区建议接入二轮上下文 v0.1

## 文档目的

这份文档记录：为什么在 `工作区内下一轮建议` 已经可以生成之后，下一步要继续把它接入 `第二轮优化上下文`。

这一层的核心目标是：

- 用户不需要在工作区里写完后，再自己手动把那层信息重复输入到二轮
- 系统能直接把工作区的路径内建议带入二轮判断、Prompt 和结果解释

这一步会让产品从“几个能力并列”进入“多阶段连续协作”。

## 当前实现了什么

### 1. 二轮现在可以接收 `workspaceResult`

当前当用户：

- 先完成首轮
- 再在工作区里生成建议
- 再进入二轮修改

前端会把 `workspaceResult` 一起带给：

- `createRefinementSession`
- `createPromptPreview`
- `createLlmDraft`

### 2. 工作区建议会进入二轮反馈映射

现在 `mapFeedbackToAdjustment` 的输入不再只有：

- `selectedCard`
- `feedback`
- `preserveElement`

还会包含：

- `workspaceContext`

也就是说，反馈映射时，系统不再只看用户一句反馈，而会同时参考：

- 工作区总结
- 工作区 refined task
- 工作区 next suggestion

### 3. 二轮结果开始显示“工作区建议是否接入”

当前二轮结果区已经新增：

- `工作区建议是否接入`

这不是多余字段，而是为了把链路状态显式化：

- 用户知道这次二轮有没有利用上工作区补充信息

### 4. Prompt 二轮上下文已经携带工作区信息

当前第二轮 Prompt 已新增：

- `工作区上下文`
- `工作区补充提示`

这意味着后续即使切换到真实模型，这一层上下文也已经自然进入生成链路。

## 为什么这一层很关键

### 1. 避免用户重复劳动

如果没有这层，用户会遇到一个很典型的问题：

- 先在工作区里想清楚了
- 但到二轮还要再手动重复一遍

这会让链路显得断裂，也削弱工作区存在的价值。

### 2. 让多阶段体验真正连起来

现在链路开始变成：

1. 首轮分析
2. 首轮分支工作区
3. 工作区路径内建议
4. 二轮优化

这已经不是单点功能，而是阶段间有上下文传递的产品流程。

### 3. 为后续“状态保存”和“阶段记录”打基础

只要工作区建议已经进入二轮上下文，后续就很容易继续扩：

- 保存某次工作区结果
- 回看它如何影响了某次二轮优化
- 形成产品内部的阶段日志

## 当前故意没有做什么

这一版还没有做：

- 工作区结果回写到分析主对象
- 工作区结果保存历史版本
- 用户手动选择“是否接入工作区建议”
- 多个工作区建议并行进入二轮

这些都适合后续继续扩，但当前先把“单条工作区建议进入单次二轮”打通更合理。
