# 平台案例复核与同步预览 v0.1

## 目标

这一版补的是一个更像真实产品工作台的中间层：

- 先读 Obsidian 里的平台案例笔记
- 判断当前笔记是否足够完整
- 找到代码侧已映射的真实案例草稿
- 预览如果执行 sync，会把真实案例哪些字段补进去

这让 `方法论案例库` 和 `代码侧可运行样例` 不再分离。

## 本轮新增能力

- `GET /api/platform-review?platformCaseId=P-01`
  返回单个平台案例的完整度、映射关系和同步预览摘要。
- `GET /api/platform-batch-review`
  返回当前所有已映射平台案例的批量复核看板。
- `GET /api/platform-sync-preview?caseId=real-001`
  返回一个真实案例的 dry-run 同步预览，不直接写回文件。

## 结构拆分

- `src/infrastructure/obsidian/resolveObsidianRoot.js`
  统一解析 Obsidian 根目录。
- `src/infrastructure/obsidian/loadPlatformCaseNote.js`
  负责读取平台案例笔记并做结构化解析。
- `src/application/runPlatformCaseReview.js`
  单案例复核编排层。
- `src/application/runPlatformCaseBatchReview.js`
  批量复核编排层。
- `src/application/runPlatformSyncPreview.js`
  平台案例到真实案例的 dry-run 预览编排层。

## 为什么这一步重要

- 之后你补一个平台案例，不需要手动判断“现在能不能进代码”
- 你可以先在工作台里看完整度和同步影响，再决定是否正式 sync
- 后续如果接 LLM 或规则评分器，也有了明确插入点
