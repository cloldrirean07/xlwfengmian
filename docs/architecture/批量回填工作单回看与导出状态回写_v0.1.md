# 批量回填工作单回看与导出状态回写 v0.1

## 本次目标

在“批量回填工作单可生成、可导出”基础上，再补一层“回看与状态回写”，让同一批案例后续可以：

- 查看最近一次导出状态
- 查看最近几次导出记录
- 确认读回一致性

这样批量工作单不再是一次性产物，而是进入可持续维护状态。

## 为什么这一步重要

如果没有回看层，工作单导出后就会变成：

- 不知道是否成功导出
- 不知道是否被覆盖
- 不知道最新一版在哪里
- 不知道历史上导过几次

加上这一层后，产品链路就更像真实工作台：

1. 生成工作单
2. 导出到 Obsidian
3. 后续重新打开同一批案例
4. 查看最近导出记录与一致性状态

## 设计原则

### 不重新解析 Obsidian 文档正文

本次回看完全依赖导出日志，不直接读取和解析 Obsidian 文档正文来判断状态。

原因是：

- 日志结构稳定
- 状态字段明确
- 读回结果已在导出时记录

这比后续再从 Markdown 反推状态更可靠。

### 批次身份以 normalized label 为主

同一批案例的工作单回看，基于：

- `batchLabel`
- `normalizedLabel`

进行归档和读取，保持与导出路径、日志目录一致。

## 代码结构

### 新增基础设施层

- `src/infrastructure/exports/loadLatestRealCaseBatchFillExportStatus.js`

负责读取某个批次最近一次导出状态，包括：

- 导出时间
- 导出目标路径
- 动作类型
- 读回一致性
- 日志路径

### 新增应用层

- `src/application/loadRealCaseBatchFillWorksheetHistory.js`

负责：

- 根据当前批量输入构造批次标签
- 读取最近一次导出状态
- 读取最近几次导出记录
- 返回可直接给前端展示的历史摘要

### Server API

- `POST /api/real-case-batch-fill-history`

### 前端接入

- `public/index.html`
  - 新增按钮：
    - `查看最近工作单记录`
- `public/app/api.js`
  - 新增批量工作单 history API
- `public/app/createApp.js`
  - 新增 history 加载交互
- `public/app/renderers.js`
  - 在批量工作单结果区新增：
    - 最近一次导出状态
    - 最近导出记录

- 录入
