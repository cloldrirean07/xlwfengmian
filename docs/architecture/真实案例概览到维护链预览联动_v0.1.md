# 真实案例概览到维护链预览联动 v0.1

## 1. 这轮补的是什么

前一轮已经做到：

- 真实案例写入后
- 页面能重新读到真实案例概览

但那时概览区还只是“看得到”。

这轮继续补了一步：

- 从真实案例概览直接进入这条案例的同步预览

也就是说，真实案例概览区开始不只是展示区，而是已经成为维护链入口的一部分。

## 2. 当前联动方式

在：

- `public/app/renderers.js`

的 `renderRealCaseLibrary` 中，为每条真实案例增加了：

- `查看这条的同步预览`

按钮。

按钮会携带：

- `data-case-id`
- `data-platform-case-id`

## 3. 前端编排怎么接

在：

- `public/app/createApp.js`

中新增了对 `realCaseLibraryResult` 的事件代理。

当前动作流程是：

1. 用户点击某条真实案例的“查看这条的同步预览”
2. 前端读取该条案例的 `caseId`
3. 同步把 `platformCaseId` 回填到平台案例输入框
4. 调用 `loadPlatformSyncPreview(caseId)`
5. 渲染到已有的 `platformSyncSummary`
6. 页面自动滚动到同步预览结果区

## 4. 为什么这样接是对的

这一步的价值不只是省一次输入。

它真正解决的是：

- 真实案例写进来了
- 但下一步怎么进入维护链

现在这个答案已经更顺了：

- 从概览直接去同步预览

这意味着当前主链已经越来越接近真实工作流，而不是几个互相孤立的功能块。

## 5. 为什么还不急着做完整管理台

这一步仍然保持克制。

当前没有继续扩：

- 编辑真实案例
- 删除真实案例
- 多条件筛选
- 批量进入维护链

因为现在更重要的是先验证：

- 单条真实案例进入维护链的路径是否自然

这个点一旦稳定，后面做完整台子会更有方向。

## 6. 当前结论

到现在，真实案例相关路径已经形成：

- 录入
- 预览
- 写入
- 重读
- 从概览进入同步预览

这已经不是单点功能，而是一条开始闭合的产品链。
