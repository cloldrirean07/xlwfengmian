# 跨批次摩擦点汇总_v0.1

## 1. 本次补的能力

在单批次试跑记录和结构化摩擦点模板基础上，再补一层：

- 自动读取已经导出的多批次试跑记录
- 汇总哪些摩擦点类别在重复出现
- 汇总哪些推荐动作在多批次里反复出现
- 给出当前是否接近正式讨论 UI 的跨批次判断

它的作用不是替代 `UI 优化进入条件报告`，而是给那份判断补一层更具体的“重复问题证据”。

## 2. 为什么要有这层

只看单批次，会有两个问题：

1. 你看到的问题可能只是这一批的偶然现象  
2. 很难判断一个问题是不是已经稳定重复到值得单独改 UI

所以现在补的是“跨批次摩擦点汇总”，让后续的 UI 讨论建立在：

- 多批次重复问题
- 多批次重复推荐动作
- 多批次一致的摩擦点类别

之上。

## 3. 输入来源

当前直接复用：

- `apps/web/outputs/batch-run-records/<batch-label>/run-record.json`

也就是此前导出的批次试跑记录 JSON 底稿。

这意味着这层不需要新的人工输入，只要已经导出过试跑记录，就能被纳入汇总。

## 5. 当前汇总内容

汇总会输出：

1. 批次数
2. 案例总数
3. 重复摩擦点类别数
4. 缺少工作单导出记录的批次数
5. 最常重复的摩擦点类别
6. 最常重复的推荐动作
7. 各批次对照表
8. 当前是否接近正式讨论 UI 的判断

## 6. 当前判断信号

目前分三档：

- `strong-signal`
  - 至少 3 批
  - 至少 2 类摩擦点在重复出现
  - 可开始系统讨论 UI 优化

- `emerging-signal`
  - 至少 2 批
  - 至少 1 类摩擦点在重复出现
  - 接近可以讨论 UI，但证据还不算特别稳

- `insufficient-signal`
  - 批次不够或重复类别不明显
  - 暂不建议正式讨论 UI

## 7. 页面展现

页面新增独立面板：

结果区会显示：

- 各批次对照
- Markdown 预览

## 8. 对 UI 讨论时机的价值

这层补完后，后续讨论 UI 不再只是：

- “我觉得页面有点乱”

而是更接近：

- “输入准备与案例结构已经连续 3 批都是最高频摩擦点，所以先别急着做视觉层。”
- “结果阅读与选择判断已经连续 2 批都重复出现，所以开始值得单独重构结果区信息架构。”

## 9. 和现有 UI readiness 的关系

推荐理解为两层：

1. `UI 优化进入条件报告`
   先判断批次数、导出链路、试跑记录证据够不够。

2. `跨批次摩擦点汇总`
   再判断重复出现的具体问题到底是什么。

前者回答：

- 现在能不能开始聊 UI？

后者回答：

- 如果开始聊，最该聊哪一类问题？

## 10. 下一步建议

下一步最有价值的不是再补更多静态文档，而是：

1. 再补 1 到 2 批真实案例试跑
2. 每批导出工作单和试跑记录
3. 回到这份跨批次汇总里看：
   - 哪类问题已经重复出现
   - 哪类更像规则问题
   - 哪类更像 UI 问题

到那时再系统讨论 UI，会更接近真实产品推进节奏。
