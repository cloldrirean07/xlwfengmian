# 真实案例概览到回填预览联动 v0.1

## 1. 这轮把什么接上了

上一轮已经做到：

- 从真实案例概览直接进入同步预览

这轮继续补了一层更直接的维护动作：

- 从真实案例概览直接查看“这条案例当前最该先补什么”

这意味着真实案例概览不再只是一个“进入同步链”的入口，也开始承担：

- 回填优先级提示入口

## 2. 当前新增能力

### 2.1 应用层

新增：

- `src/application/runRealCaseFillPreview.js`

职责：

- 加载指定真实案例
- 运行 `inspectRealCaseReadiness`
- 运行 `buildRealCaseFillSheet`
- 返回单条真实案例的回填预览结果

它的定位不是完整工作单导出，而是：

- 单条案例在前端可即时查看的维护提示

### 2.2 服务层

新增接口：

- `GET /api/real-case-fill-preview?caseId=...`

位置：

- `src/server/server.js`

### 2.3 前端概览卡片动作

在：

- `renderRealCaseLibrary`

中，为每条真实案例新增：

- `查看这条先补什么`

按钮。

### 2.4 前端编排层

在：

- `public/app/createApp.js`

中新增：

- 对 `fill-preview` 动作的事件处理
- 调用 `loadRealCaseFillPreview(caseId)`
- 渲染单条案例的回填预览

### 2.5 前端渲染层

新增：

- `renderRealCaseMaintenancePreview`

它会展示：

- 当前就绪度
- 已完成检查数
- 缺失字段数
- 平台案例 ID
- 当前最该先补的字段及提示语

## 3. 这一步为什么有价值

如果只有同步预览，用户会知道：

- 这条案例和平台笔记怎么比

但还不一定知道：

- 当前应该先补哪个字段

这轮补的其实是更“产品经理视角”的问题：

- 我现在先做哪一步，最有效

所以它比简单展示缺失字段更有价值，因为已经开始给出：

- 任务顺序
- 字段提示
- Obsidian 对应位置

## 4. 当前主链已经更接近真实工作流

到现在，真实案例相关路径已经形成：

- 录入
- 预览
- 写入
- 重读概览
- 从概览进入同步预览
- 从概览查看回填优先项

这已经不是孤立功能，而是逐渐变成一个真正可操作的内部工作流。

## 5. 自动化验证

本轮新增验证：

- `runRealCaseFillPreview returns top fill tasks for one real case`

并额外运行了应用层命令验证，结果显示：

- `caseId: real-001`
- `status: 待回填`
- `topPriorityItems`
  - `来源链接或截图路径`
  - `内容主题`
  - `素材描述`

这证明单条真实案例的回填优先级链路已经可用。

## 6. 关于 UI 最佳讨论时机的判断

这轮再次说明，UI 还不适合现在大改。

因为你可以看到核心块仍在继续增加：

- 同步预览入口
- 回填预览入口

这些入口的关系和优先级，需要先通过真实使用再稳定。

所以更合适的 UI 讨论节点仍然是：

- 至少 2~3 条真实案例完整跑过
- 你已经实际感受到哪些操作顺、哪些地方信息太重
- 我们已经基本知道哪些模块最终要长期保留

到那时再讨论 UI，优化会更准。
