# 关键样例复跑差异报告机制 v0.1

## 1. 本轮解决的问题

上一轮已经有了：

- 关键样例复跑计划
- 批量复跑脚本
- 复跑结果报告

但如果只有“复跑成功”，仍然缺一个关键层：

**这次规则改动到底让哪些样例变了，哪些没有变。**

如果没有差异报告，你只能知道脚本执行过，却无法快速判断：

- 首轮主方向有没有变
- 命中信号有没有变
- 二轮映射有没有变
- 误判样本数和任务单有没有变

所以这轮新增的是“复跑前后差异报告”。

## 2. 本轮新增能力

### 2.1 差异报告领域层

新增文件：

- `src/domain/cases/buildKeyCaseRerunDiffReport.js`
- `src/domain/cases/buildKeyCaseRerunDiffMarkdown.js`
- `src/domain/cases/buildObsidianKeyCaseRerunDiffRecord.js`

职责：

- 比较复跑前后的关键样例快照
- 比较复跑前后的下游报告摘要
- 输出结构化 diff JSON 与 Markdown

## 3. 比较哪些字段

当前差异报告重点比较：

- `ruleVersion`
- `topDirectionLabel`
- `topMatchedSignals`
- `selectedDirectionLabel`
- `refinementMappingId`

下游则比较：

- `reviewed-misclassified.summary.eligibleExportCount`
- `rule-revision-task-sheet.summary.taskCount`

这套字段是当前最有产品意义的一层变化，而不是追求全量 JSON diff。

## 4. 接入点

### 4.1 复跑脚本中增加“前后快照”

文件：

- `scripts/rerun-key-cases.js`

做法：

1. 在复跑前先读取已有 `result.json`
2. 在复跑后拿到新的 `result`
3. 对同一 case 做 before/after 对比
4. 对下游报告做 before/after 对比
5. 产出：
   - `key-case-rerun-diff.json`
   - `key-case-rerun-diff.md`

### 4.2 Obsidian 导出

新增脚本：

- `scripts/export-obsidian-key-case-rerun-diff.js`

命令：

- `npm run export:obsidian-key-case-rerun-diff`

## 5. 当前输出含义

差异报告会告诉你：

- 哪些关键样例发生了变化
- 每条样例具体变了哪些关键字段
- 哪些样例没有变化
- 下游误判样本和规则任务单数量是否变化

这对规则迭代特别重要，因为很多时候：

- 你以为改了很多
- 实际关键样例没有变化

或者：

- 你只改了一个规则
- 结果误判导出和任务单数量一起变了

## 7. 当前验证结果

本轮再次复跑关键样例时，diff 报告显示：

- 2 个样例都没有关键字段变化
- 下游误判样本数和规则任务数也没有变化

这本身就是有价值的结果，说明当前规则没有继续漂移。

## 8. 下一步建议

### 8.1 增加“变化原因注释”

当前 diff 只告诉你变了什么，下一步可以继续加：

- 这次规则升级主要改了哪一层
- 理论上应该影响哪些样例

### 8.2 增加“重点变化排序”

如果后面关键样例变多，可以按：

- 方向变化
- 映射变化
- 下游任务变化

做高优先级排序。

### 8.3 接真实高频误判样例

一旦真实误判样本积累起来，这个 diff 报告会比 sample 更有价值。
