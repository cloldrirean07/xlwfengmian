# 第一轮结果区与第二轮决策UI优化_v0.1

## 1. 这轮为什么继续做 UI

上一轮已经把：

- 首屏价值主张
- 页面跳转入口
- 第一轮输入工作台

做到了更像真实产品入口的状态。

接下来最自然的下一步，不是回头再修首屏，而是继续优化用户真正做决策的地方：

- 第一轮方向结果区
- 第二轮优化入口

因为对这个产品来说，真正的核心体验不是“表单填得顺不顺”，而是：

1. 用户能不能快速看懂 3 张卡有什么差异
2. 用户能不能明确知道该选哪张继续做
3. 用户选中后，能不能顺畅进入第二轮优化

## 2. 原来的结果区问题

### 2.1 信息是完整的，但不够像决策界面

原来的卡片把很多字段都平铺出来了：

- 封面大字
- 标题建议
- 配图主策略
- 构图建议
- 色彩/气质
- 点击逻辑
- 风险提醒
- 判断信号
- 反馈触发词
- 边界提醒
- 优先顺序

这些内容本身有价值，但在首轮比较阶段全部同时出现，会让卡片更像“分析报告”，而不是“可选方向”。

### 2.2 3 张卡的比较成本偏高

用户在第一轮其实最关心的是：

- 这张卡核心想法是什么
- 为什么值得先试
- 它和另外两张最主要的差别在哪里
- 如果选它，接下来会怎么走

如果这些问题不能在卡片上半屏内回答，用户就需要滚动很多内容再决定，选择成本会偏高。

### 2.3 第二轮入口有了，但推进感还不够强

原来的选中摘要已经存在，但还比较轻。

它告诉了用户“当前选中方向是什么”，但没有更强地说明：

- 这张卡最值得保留的是什么
- 进入第二轮时应该怎么提反馈
- 现在为什么适合先改这个方向

所以从“选卡”到“进入第二轮”的过渡还不够像一个连贯流程。

## 3. 这轮设计原则

这一轮采用的是“先比较，再展开”的结构，而不是继续堆信息。

核心原则有 3 个：

1. 先让卡片适合横向比较
2. 详细依据放进按需展开层
3. 选中后的第二轮入口要更有推进感

这更符合真实产品里的决策节奏，也符合当前阶段“先验证是否愿意用”的目标。

## 4. 这轮具体改动

## 4.1 卡片上半区改成高可比较结构

每张卡现在先展示：

- 方向标题
- 方向说明
- 命中信号标签
- 建议先试的封面大字
- 一个首条标题建议
- 4 个关键比较项

关键比较项被收束成：

- 建议先做什么
- 点击逻辑
- 风险提醒
- 更适合的内容

这样用户不用先读完整卡片，就能先做一次快速比较。

## 4.2 把“素材与执行路径”提到更前面

原来很多执行信息散在卡片中部，现在单独整理成一个更清晰的小块：

- 素材类型建议
- 配图主策略
- 构图建议
- 色彩/气质

这一块让用户更快判断：

- 这张卡是不是能落地
- 是否适合自己当前素材

## 4.3 完整判断依据改成折叠层

原来的判断依据不是删掉，而是进入 `details` 折叠层。

折叠层里仍然保留：

- 方向判断信号
- 候选配图方向
- 建议优先顺序
- 常见反馈触发词
- 边界提醒

这样既保留专业度，也降低首轮比较时的信息压力。

## 4.4 选中卡状态更明确

当一张卡被选中后，现在会出现：

- 卡片内明显的 `当前已选`
- 底部 CTA 从“选择这张做第二轮”切成“已选中，继续二轮优化”

这让用户更容易确认当前状态，不会怀疑自己到底有没有点成功。

## 4.5 第二轮选中摘要增强

`renderSelectedCardSummary` 不再只是一个轻量标题块，而是补充了：

- 建议先试的封面大字
- 二轮最适合先改什么
- 进入第二轮时的反馈写法提醒

这让第二轮不再只是“你已经选中”，而是：

- 你为什么选它
- 你现在最适合怎么继续改

## 5. 本轮涉及文件

- `apps/web/public/app/renderers.js`
- `apps/web/public/styles.css`

这轮没有改：

- 分析逻辑
- 第一轮 / 第二轮返回数据结构
- 后端 API
- Obsidian 导出链路

## 6. 样式与交互调整

主要新增或强化了这些前端结构：

- `card-hero`
- `card-selection-state`
- `card-copy-preview`
- `card-summary-grid`
- `card-summary-item`
- `card-details`
- `card-details-body`
- `selected-card-grid`

交互上新增的是：

- 方向卡详细信息按需展开
- 已选中状态更明显
- 第二轮摘要区更像“继续决策”的入口

## 7. 当前效果

这一轮之后，方向卡更像“可比较的方案卡”，而不是单纯“分析信息卡”。

最直接的提升是：

- 比较 3 张卡更快
- 第一眼就能看出主差异
- 选择一张后状态更清楚
- 进入第二轮的心理路径更顺
- 详细判断依据仍然保留，没有牺牲专业度

## 8. 下一步建议

继续做 UI 时，下一步最值得做的是：

1. 优化第二轮结果展示区，让“改前 / 改后”更容易对比
2. 优化工作区建议区与第二轮区之间的视觉衔接
3. 再考虑是否需要把结果区做成更强的分步流程

当前还不建议做的是：

- 结果区一次性改成复杂标签页系统
- 提前做全局设计 token 抽象
- 在还没继续验证前就做大范围动画和高级动效
