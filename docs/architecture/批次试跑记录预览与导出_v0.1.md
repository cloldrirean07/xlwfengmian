# 批次试跑记录预览与导出 v0.1

## 本次目标

在批量真实案例已经具备：

- 批量录入
- 批量校验
- 批量推荐动作
- 批量工作单导出
- 工作单回看

的基础上，再补一份专门用于沉淀“真实批次试跑观察”的记录。

## 为什么要有这层

如果你后面真的拿 2 到 3 批真实案例去跑：

- 你会看到哪里卡
- 你会知道哪些字段最难补
- 你会判断什么时候适合进入 UI 优化

这些内容如果只停留在聊天或零散笔记里，后续就很难系统复盘。  
所以本次补的是“批次试跑记录”，让真实试跑本身也能结构化沉淀。

## 设计原则

### 不重复计算已有结果

批次试跑记录不重新生成一套判断逻辑，而是复用：

- `runRealCaseBatchFillPreview`
- `loadRealCaseBatchFillWorksheetHistory`

已有结果来组织试跑记录。

### 记录要服务 UI 决策

这份记录不是纯技术日志，它会显式包含：

- 当前最卡的环节
- 和通用 AI 相比的差异
- 是否已经到 UI 优化时机

这样它能直接服务你后续的产品判断。
