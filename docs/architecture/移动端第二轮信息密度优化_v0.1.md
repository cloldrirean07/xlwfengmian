# 移动端第二轮信息密度优化_v0.1

## 1. 这轮为什么继续优化第二轮

在已经完成：

- 工作区到第二轮的流程衔接
- 第二轮轻量步骤感

之后，桌面端的主流程已经越来越顺。

但从移动端视角看，第二轮区域仍然有一个明显问题：

- 信息没有缺失
- 流程也已经清楚
- 但在手机宽度下，纵向高度偏长，阅读节奏容易被拉散

最典型的表现是：

1. 步骤条在手机上仍然占比较高
2. 第二轮关键摘要被拉成很长的一列
3. 改前 / 改后对比卡中的信息块在手机上层层堆叠，容易显得重

这说明当前 UI 优化已经从“补流程断点”进入了“压信息密度”的阶段。

## 2. 这轮要解决的问题

本轮不改逻辑，不减信息，而是只解决移动端第二轮区域的 3 个体验问题：

1. 手机上步骤提示是否过高
2. 关键摘要是否能更快扫读
3. 改前 / 改后卡里最重要的信息是否能在更短视线内读完

换句话说，本轮要做的是“压缩但不丢层级”。

## 3. 设计原则

本轮采用的原则非常明确：

- 不砍信息
- 不新增交互
- 不做移动端专属流程分支
- 只通过样式层压缩第二轮区的纵向占用

优先级是：

1. 保留流程连续性
2. 保留对比结构
3. 再压缩视觉高度

## 4. 本轮具体改动

## 4.1 移动端步骤条改成更紧凑的状态

在 `@media (max-width: 720px)` 下，对步骤条做了专门压缩：

- 保持 3 列结构
- 缩小 `gap`
- 缩小单步卡片的 `padding`
- 缩小状态标签尺寸
- 隐藏步骤说明文字，只保留状态 + 标题

这样做的原因是：

- 桌面端的说明文字有帮助
- 但在手机宽度下，说明文字会把步骤条拉得过高

所以移动端保留“步骤感”，但把它从“说明卡”压成了“状态条”。

## 4.2 第二轮关键摘要改成双列密度

对以下区域，在手机下改成双列布局：

- `selected-card-grid`
- `refinement-kicker-grid`
- `#second-round-result > .data-list`
- `refinement-mini-grid`

这一步的目标不是让信息更密，而是让：

- 关键信息不再全部纵向排开
- 同一层级的信息能在更短的屏幕高度内被扫读

对应到第二轮场景，用户能更快看到：

- 保留内容
- 改动变量
- 这轮目标
- 规则版本
- 是否接入工作区建议

而不是一项一项往下翻。

## 4.3 第二轮卡片与块级容器整体收紧

在移动端下，对以下区块统一收紧：

- `selected-card-box`
- `result-highlight`
- `sub-block`
- `refinement-copy-box`

收紧内容包括：

- 减少 `padding`
- 稍微缩小圆角
- 缩小标题字号
- 调整正文行高

这让移动端的第二轮区在不失去产品感的前提下，看起来更利落。

## 4.4 改前 / 改后核心文案继续保留高优先级

虽然整体做了压缩，但仍然保留：

- `refinement-copy-box strong` 在移动端的较高字号

只是控制在比桌面端更适中的范围。

因为在第二轮对比里，“原始封面大字 / 新的封面大字”依然是最值得保留的第一视觉锚点。

也就是说：

- 容器压缩了
- 说明层收紧了
- 但最关键的比较焦点没有被压弱

## 7. 这轮带来的价值

这轮完成后，移动端第二轮区域的阅读方式更接近“快速扫重点”，而不是“完整看说明”。

最直接的提升是：

- 手机上步骤条不再过高
- 第二轮关键摘要更容易快速浏览
- 改前 / 改后信息块的层级仍在，但纵向压力更小
- 页面在移动端下更像真实产品，而不是桌面版的直接压缩

## 8. 对后续 UI 的意义

这轮说明当前项目的 UI 优化已经进入一个更细的阶段：

- 不是单纯补功能块
- 也不是立刻做大视觉统一
- 而是开始针对端侧阅读成本做更有针对性的收口

所以下一步如果继续推进 UI，更值得观察的是：

1. 第二轮结果区是否还需要一个更轻的继续优化入口
2. 第一轮方向卡在移动端下是否也存在类似密度问题
3. 等移动端和桌面端的主流程都收顺后，再进入更完整的视觉统一讨论
