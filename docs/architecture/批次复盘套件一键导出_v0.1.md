# 批次复盘套件一键导出_v0.1

## 1. 本次补的是什么

把已经存在的 3 份复盘正式产物收成一个“一键导出复盘套件”能力：

- 跨批次摩擦点汇总
- UI 优化进入条件报告
- 批次复盘看板

用户不需要再逐份点击导出，而是可以在同一轮复盘结束后，一次性把这 3 份正式记录和一份总览套件草稿一起写入 Obsidian。

## 2. 为什么这一步重要

前面我们已经逐个补齐了：

- 结构化摩擦点汇总
- UI 时机判断
- 批次复盘看板

但它们仍然偏“分散可用”。

如果每次复盘都要分别导出、分别回看，会出现两个问题：

1. 同一轮复盘的正式材料不够聚合
2. 进入 UI 讨论前，判断链路容易分散在多份记录里

所以这一轮补的不是新判断逻辑，而是把已经形成的判断资产收成同一轮复盘的“套件出口”。

## 4. 当前导出内容

这次导出分两层：

### 第一层：沿用原本 3 份正式产物

1. 跨批次摩擦点汇总
2. UI 优化进入条件报告
3. 批次复盘看板

### 第二层：新增一份总览套件草稿

1. 代码侧 JSON
   - `outputs/batch-review-suite/batch-review-suite.json`

2. 代码侧 Markdown
   - `outputs/batch-review-suite/batch-review-suite.md`

3. Obsidian 草稿
   - `05_验证与实验/批次试跑记录/批次复盘套件/批次复盘套件_YYYY-MM-DD.md`

4. 导出日志
   - `outputs/obsidian-export-logs/batch-review-suite/*.json`

## 5. 套件草稿的结构

当前套件草稿包含：

- 当前导出概览
- 3 份正式产物路径
- 当前最关键判断
- 当前最该补的批次
- 下一步动作
- 复盘后操作清单
- 人工补充区

这样做的目的，是让你进入 Obsidian 后不是看到“又一份报告”，而是看到：

- 这一轮复盘到底产出了什么
- 当前最该补哪里
- 是否还不应该进入 UI 优化
- 补完后应该按什么顺序继续推进

## 8. 新增的复盘后操作清单

这轮又补了一层更贴近真实 PM 推进动作的结构：

- 先确认这轮复盘材料
- 先补当前最关键缺口
- 补完后立刻重跑复盘判断
- 决定是否进入 UI 讨论

这不是简单把“下一步动作”换种说法，而是把导出后的执行顺序也固定下来。

这样无论你在页面里看复盘，还是在 Obsidian 中回看，都能沿着同一套推进顺序继续做，而不是每次重新判断“现在先补哪一步”。

这次又往前补了一步：

- 页面中的复盘后操作清单，已经可以直接触发对应入口
- 导出的 Markdown 里，也会保留“页面入口”提示
- 页面内会记录这轮已经触发过哪些复盘动作
- 页面会明确提示“当前推荐下一步”
- 页面会补一块“本轮执行记录”，按时间倒序显示最近完成的动作
- 前端已经抽出独立的推进摘要 helper，统一计算下一步与最近完成动作
- 页面会显示阶段完成数、当前阶段，以及“刚完成 -> 切到下一步”的摘要
- 当前推荐下一步已经升级成更明显的行动卡，并补充“完成这步后进入哪个阶段”的提示
- 动作执行后，页面会自动把推荐下一步行动卡滚到更明显的位置
- 推荐下一步行动卡本身增加了更明确的聚焦样式

当前已经接通的典型动作包括：

- 生成跨批次摩擦点预览
- 生成 UI 就绪度预览
- 生成批次试跑记录
- 重跑 UI 报告和复盘看板
- 一键导出复盘套件

这让它从“看得懂下一步”继续升级成“可以顺手去做下一步”。

同时，这一层状态记录仍然只发生在当前工作台会话里，不会反向污染正式复盘结论。

也就是说：

- 正式报告继续保持可沉淀、可回看的判断结果
- 页面内额外提供“这轮我已经执行过什么”的推进反馈
- 页面会把第一个尚未完成的可执行动作提示为“当前推荐下一步”
- 页面会把最近完成的动作单独列成“本轮执行记录”，减少用户回忆成本
- 页面会汇总可执行动作总数、已完成数、剩余数和最近完成动作
- 页面会把“最近完成动作”和“当前阶段切换”连起来，形成更明确的顺序推进感
- 页面会在推荐动作里提前说明“完成这步后会进入哪个阶段”，减少跳转后的迷失感
- 页面在动作执行后会主动聚焦到新的推荐下一步，减少用户自己回找入口的成本
- 页面会让推荐下一步行动卡在视觉上更明显，降低视线切换成本

这符合当前阶段的节奏：先把真实工作流跑顺，再决定哪些交互值得固化成更正式的 UI 方案。

## 9. 和 UI 优化时机的关系

这一步依然不是开始做 UI 美化，而是继续强化“什么时候该做 UI”的判断链路。

它的价值在于：

- 把 UI 之前的证据链收成一轮复盘套件
- 让你后续判断 UI 节奏时，不再只看单个模块
- 让“先补数据和人工结论，后谈 UI”这件事更容易执行

## 10. 当前价值

这轮之后，复盘系统从“多份正式记录并存”升级成“单轮复盘可以一次收口”。

对你现在这个项目阶段来说，这比提前做大 UI 更重要，因为它直接提升了：

- 复盘效率
- 项目记录完整度
- UI 讨论前的证据聚合能力
- 复盘结果到下一步执行的衔接效率
- 页面内连续操作时的上下文连续性
- 页面内下一步判断的清晰度
- 前端推进状态逻辑的可复用性与可测试性
- 阶段推进感与工作流连续性
- 本轮操作回看能力
- 推荐动作本身的可执行性与预期清晰度
- 动作执行后的视线连续性
- 下一步行动卡的可见性

## 11. 下一步建议

下一步更值得做的是：

1. 用这版工作台实际导出一轮复盘套件
2. 在 Obsidian 中补完“这轮最该先补的批次”
3. 再补一句“这轮之后还不该进入 UI 的原因”
4. 等新增真实批次后，再回看套件里重复出现的信号
5. 到那时再讨论 UI 调整优先级会更稳
