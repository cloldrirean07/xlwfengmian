# 第二轮轻量步骤感接入_v0.1

## 1. 这轮为什么继续补 UI

在前几轮优化之后，当前主流程已经有了：

- 第一轮输入工作台
- 工作区建议
- 方向卡比较
- 第二轮反馈
- 改前 / 改后对比结果

但是从真实使用角度看，用户虽然能“走完”，却不一定能一眼知道自己当前走到哪一步。

尤其是在：

- 已经选中一张方向卡，准备进入第二轮的时候
- 刚看到第二轮结果，需要理解自己现在位于哪一层的时候

页面仍然更像几个大区块顺序堆叠，而不是一条有节奏的产品流程。

所以这轮不再补新模块，而是补“轻量步骤感”。

## 2. 这轮要解决的问题

本轮核心要解决的是 3 个认知问题：

1. 用户是否能一眼看出当前主流程有哪几步
2. 用户是否知道自己现在处在“选卡 / 提反馈 / 看对比”的哪一步
3. 用户看到第二轮结果后，是否知道如果还要继续改，应该怎么回到下一轮

换句话说，这轮优化的是流程感，不是功能数。

## 3. 设计原则

本轮继续保持小步推进原则：

- 不增加新的页面层级
- 不增加 tabs 或复杂导航
- 不做全站设计系统重构
- 只在最关键的两个区块补上流程提示

这两个区块分别是：

1. 已选方向摘要区
2. 第二轮结果区

因为这两个地方正好对应：

- 用户准备进入第二轮
- 用户刚完成第二轮

它们是最适合补“步骤感”的节点。

## 4. 本轮具体改动

## 4.1 新增轻量流程条渲染函数

在 `renderers.js` 中新增：

- `renderFlowProgress(currentStep)`

这一层没有引入独立组件系统，只是生成一个三步式的轻量流程条，包含：

1. 选方向
2. 提二轮反馈
3. 看改前改后

并为每一步区分三种状态：

- `done`
- `active`
- `pending`

这样流程条既能解释全流程，也能解释当前所在位置。

## 4.2 在“当前选中方向”里接入流程条

在 `renderSelectedCardSummary` 中，已选方向摘要区新增流程条。

这里使用：

- `renderFlowProgress("refine")`

意味着当前界面明确告诉用户：

- 第一步“选方向”已经完成
- 当前正在进行“提二轮反馈”
- 后面还会进入“看改前改后”

这个变化的价值是，第二轮表单不再像突然出现的一块输入区，而更像流程中的当前步骤。

## 4.3 在第二轮结果区接入流程条

在 `renderRefinementResult` 中，结果区新增流程条。

这里使用：

- `renderFlowProgress("compare")`

意味着当前界面明确告诉用户：

- 方向选择已完成
- 二轮反馈已完成
- 当前正在看改前 / 改后的结果

这让第二轮结果区从“结果展示区”更进一步变成“流程完成节点”。

## 4.4 在第二轮结果区补“继续迭代时的最短路径”

除了流程条，本轮还在第二轮结果区增加了一个更轻的循环提示块：

- `继续迭代时的最短路径`

它强调的是：

- 不要一口气把当前结果全推翻
- 先保留这轮最对的一点
- 再只改一个主问题

这一块不是新增功能，而是把产品使用方法继续嵌进结果页里。

它的作用是把第二轮结果页和后续第三轮可能发生的迭代，再轻轻地接起来。

## 5. 样式层调整

本轮新增了以下样式结构：

- `flow-progress`
- `flow-step`
- `flow-step-status`
- `flow-step-done`
- `flow-step-active`
- `flow-step-pending`
- `refinement-next-loop-box`

设计思路不是做“重导航”，而是做一种很轻的流程辅助层：

- 已完成步骤更收敛
- 当前步骤更突出
- 待进行步骤更弱化

并且保留移动端下自动压成单列的能力。

## 8. 这轮带来的价值

这一轮之后，页面主流程的体验又更像“产品流程”，而不是“多个结果区顺序堆叠”。

最直接的提升是：

- 用户更容易理解自己处在哪一步
- 第二轮表单更像当前任务，而不是突然出现的输入框
- 第二轮结果更像一个阶段性完成节点
- 如果继续迭代，用户更容易知道下一轮该怎么提反馈

## 9. 对后续 UI 的意义

这轮完成后，当前主流程已经逐步具备：

- 首页说明
- 第一轮输入
- 工作区辅助判断
- 方向卡选择
- 二轮反馈
- 改前改后对比
- 轻量步骤感

所以下一步如果继续优化 UI，更值得观察的就不是“还缺不缺一步说明”，而是：

1. 移动端下步骤条是否还需要进一步压缩
2. 第二轮结果区是否需要更轻的“继续优化入口”
3. 是否等更多真实批次证据后，再进入更完整的视觉统一讨论

也就是说，这轮之后，UI 优化开始从“补流程断点”逐步转向“打磨节奏和层次”。
