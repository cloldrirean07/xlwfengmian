# 移动端第一轮方向卡密度优化_v0.1

## 1. 这轮为什么继续优化第一轮卡片

在已经完成：

- 第二轮轻量步骤感
- 移动端第二轮信息密度优化

之后，第二轮链路在手机下已经比之前更稳。

但回到第一轮会发现，方向卡虽然已经适合桌面端比较，在移动端下仍然有一个典型问题：

- 信息足够完整
- 决策结构也已经清楚
- 但单张卡在手机上仍然偏长，比较三张卡时需要反复纵向滚动

这会直接影响第一轮最核心的事情：

- 快速比较
- 快速决定先选哪张

所以这轮继续沿着上一轮的方法，只处理移动端阅读密度，不改卡片结构。

## 2. 这轮要解决的问题

本轮针对的是第一轮卡片在手机下的 3 个阅读压力点：

1. 卡片本体留白偏大，导致单卡高度偏高
2. 封面大字预览块与四宫格摘要区在手机下纵向占用偏多
3. 折叠详情区即使没展开，也会因为头部尺寸和容器节奏显得偏重

本轮目标不是减少信息，而是缩短“看完一张卡的最短路径”。

## 3. 设计原则

本轮继续坚持：

- 不改卡片字段结构
- 不砍专业内容
- 不新增新的展开层
- 只通过样式层压缩移动端阅读成本

对应策略是：

1. 收紧卡片容器
2. 保留最重要的信息视觉锚点
3. 压缩次级信息的外层节奏

## 4. 本轮具体改动

## 4.1 收紧卡片本体容器

在移动端媒体查询下，对以下容器统一收紧：

- `cards`
- `card`

主要调整包括：

- 缩小卡片间距
- 缩小卡片内边距
- 收紧内部 `gap`
- 收紧圆角

这样做的目的是在不牺牲卡片感的前提下，让 3 张卡在手机中更像“可快速比较的列表”。

## 4.2 收紧标题区与选中状态

对以下元素做了移动端压缩：

- `card h3`
- `card-top`
- `card-selection-state`
- `card-description`

具体策略是：

- 缩小标题字号
- 缩小顶部辅助信息字号
- 收紧选中状态胶囊尺寸
- 去掉 `card-description` 的固定最小高度

这一点很关键，因为桌面端为了保持卡高对齐保留了固定高度，但在手机下，固定高度会明显拉长单卡。

## 4.3 收紧封面大字预览块

移动端下对：

- `card-copy-preview`
- `card-copy-preview strong`
- `card-copy-preview p`

做了压缩。

策略是：

- 收紧外层容器 `padding`
- 缩小文案块圆角
- 维持封面大字仍然足够醒目
- 收紧说明文字的上下间距

这意味着：

- 核心比较锚点仍然保留
- 但不会再因为预览块过大而拉高整张卡

## 4.4 收紧四宫格摘要区

对以下元素做了移动端压缩：

- `card-summary-item`
- `card-summary-item strong`

做法是：

- 缩小摘要卡 `padding`
- 缩小大字字号
- 控制行高

这块的目标是保留“快速比较”的价值，但减少每个摘要项的高度浪费。

## 4.5 收紧折叠详情入口

移动端下对：

- `card-details`
- `card-details summary`
- `card-details-body`
- `card-top-blocks`

进行了收紧。

这样处理的好处是：

- 没展开时，折叠层入口不会显得过重
- 展开后，也不会因为内边距过大导致信息显得散

本质上，这是把“完整专业依据”继续留在卡里，但让它在手机下更像“按需查看”而不是“默认压迫主流程”。

## 5. 涉及文件

## 7. 这轮带来的价值

这一轮之后，第一轮方向卡在手机下会更接近“快速比较卡片”，而不是“被压缩后的桌面报告卡”。

最直接的提升是：

- 单张卡的阅读高度更短
- 三张卡之间来回比较的成本更低
- 选中前的决策节奏更快
- 专业信息仍然保留，但不再默认抢占太多空间

## 8. 对后续 UI 的意义

到这一步，当前项目已经开始形成比较清楚的 UI 推进顺序：

1. 先把流程走顺
2. 再补步骤感
3. 再分别压第二轮和第一轮的移动端密度

所以下一步如果继续推进 UI，更值得讨论的就不是“哪里再多加一个说明块”，而是：

1. 第二轮结果区是否需要一个更轻的继续优化入口
2. 第一轮和第二轮之间是否需要更统一的视觉节奏
3. 当移动端和桌面端的主流程都稳定后，再进入更完整的视觉统一讨论
