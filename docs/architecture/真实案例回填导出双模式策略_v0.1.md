# 真实案例回填导出双模式策略 v0.1

## 1. 本次改动解决什么问题

此前真实案例回填导出已经具备：

- 确认导出
- 写后读回确认
- 覆盖判断
- 导出历史

但当时仍然只有一种导出行为：

- 默认写到固定目标路径

这意味着如果用户不想覆盖旧稿，就没有明确分支。

这次补的是：

**真实案例回填导出支持两种显式模式：**

- `overwrite`
- `copy`

## 2. 两种模式分别解决什么场景

### 2.1 `overwrite`

适合：

- 当前草稿就是这条案例的主工作版本
- 需要不断迭代同一份知识库文档

行为：

- 写入固定目标路径
- 如果目标已存在，则视为覆盖

### 2.2 `copy`

适合：

- 想保留旧稿
- 想做多个版本试跑
- 想先导出副本再人工挑选

行为：

- 基于默认目标路径派生一个带导出编号的副本文件名
- 不影响当前主文件

## 3. 代码实现

### 3.1 应用层增加导出模式解析

更新：

- `src/application/exportRealCaseFillSheetToObsidian.js`

新增逻辑：

- `resolveExportMode`
- `buildTargetPath`

当 `exportMode=copy` 时，最终写入路径会变成：

- `原路径__副本_<exportId>.md`

### 3.2 覆盖语义继续保留

即使支持副本模式，当前导出结果仍会继续返回：

- `overwrite.requestedMode`
- `overwrite.actionLabel`
- `overwrite.targetAlreadyExisted`

也就是说：

- 副本模式不是取消覆盖语义
- 而是让导出策略本身变成显式可追踪的输入

### 3.3 导出日志也记录模式

导出日志仍然写入：

- `outputs/obsidian-export-logs/real-case-fill-sheets/<caseId>/`

但现在每条记录都能区分：

- 这次是覆盖导出
- 还是新建副本

## 4. 前端接入

更新：

- `public/app/renderers.js`
- `public/app/createApp.js`
- `public/app/api.js`

真实案例概览卡片现在提供两个显式动作：

- `覆盖导出到 Obsidian`
- `新建副本到 Obsidian`

前端不会自己推断模式，而是把按钮上的模式值直接传到 API。

这能保证：

- 前端语义清楚
- 后端日志一致
- 后续 UI 重构时不容易丢失行为含义

## 5. 当前价值

这次改动把真实案例回填导出从“单一路径写入”推进到“显式导出策略”层。

它的价值主要在三点：

1. 防止用户被迫覆盖旧稿
2. 让版本试跑更自然
3. 为后续更完整的维护工作台保留结构空间

## 6. 当前结论

现在真实案例回填导出链已经支持：

1. 预览草稿
2. 选择导出模式
3. 写入目标文件
4. 写后读回确认
5. 记录覆盖语义与导出历史

这说明这条链路已经具备更接近真实内容维护工具的导出能力。
