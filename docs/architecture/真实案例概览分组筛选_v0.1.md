# 真实案例概览分组筛选 v0.1

## 1. 本次改动解决什么问题

此前真实案例概览已经具备：

- 最新导出状态
- 概览优先级
- 分组标签

但用户仍然需要在列表里自己看卡片，才能找到“当前最该先处理”的案例。

这次补的是：

**真实案例概览支持按分组筛选。**

## 2. 为什么这一步比先做大 UI 更重要

你当前还没有真正跑够 `2-3` 条真实案例，所以现在最关键的不是视觉精修，而是：

- 高频操作路径能不能更短
- 维护信息能不能更快聚焦

按分组筛选正好属于“信息结构优化”，这比过早调整视觉样式更贴当前阶段目标。

## 3. 前端实现

### 3.1 增加筛选状态

更新：

- `public/app/state.js`

新增：

- `realCaseLaneFilter`

默认值：

- `all`

### 3.2 列表渲染支持筛选

更新：

- `public/app/renderers.js`

`renderRealCaseLibrary` 现在支持：

- 接收 `laneFilter`
- 动态渲染筛选按钮
- 根据所选分组过滤卡片

### 3.3 事件收口

更新：

- `public/app/createApp.js`

点击分组按钮时：

- 更新 `state.realCaseLaneFilter`
- 复用 `refreshRealCaseLibrary`

这样不需要单独维护另一套列表刷新逻辑。

## 4. 当前效果

现在真实案例概览已经具备：

- 分组数量汇总
- 当前筛选状态
- 按分组聚焦列表

这意味着后续当你真实补到 `2-3` 条案例后，可以先只看：

- `优先补写并导出`
- 或 `已导出副本待收敛`

而不是每次从全部卡片中找。

## 5. 当前结论

这次改动属于典型的“先优化信息结构，而不是先改视觉皮肤”。

它进一步验证了我们之前对 UI 节奏的判断：

- 在主链路稳定前，优先做结构性可用性增强
- 等真实案例链真正跑起来后，再进入系统性 UI 讨论
