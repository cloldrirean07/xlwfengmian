# 人工覆盖持续性信号接入UI时机判断_v0.1

## 1. 本次补的是什么

把“人工复盘是不是在持续变完整”正式接入：

- 跨批次摩擦点汇总
- UI 优化进入条件报告

这意味着系统现在不只看：

- 有几批试跑
- 有几批导出
- 有没有重复摩擦点

还会看：

- 有几批已经写了人工结论
- 有几批关键人工字段已经补完整
- 有几批还处于“写了一半”的状态

## 2. 为什么这一层重要

之前的问题是：

- 试跑记录数量可能够了
- 重复摩擦点也可能开始出现

但如果人工复盘一直是半填状态，那么 UI 讨论仍然容易失真。

因为这说明：

- 人工最卡点还没有稳定表达出来
- 问题类型判断可能还在摇摆
- “最该前置模块”还没有形成可操作共识

所以这次补的是“复盘质量信号”，不是再多堆一层数量统计。

## 3. 当前新增的核心指标

在跨批次汇总中新增：

- `fullyCoveredBatchCount`
  - 关键人工字段已完整覆盖批次数
- `partiallyCoveredBatchCount`
  - 已写人工结论但关键字段仍未补齐批次数

当前关键字段仍然统一为：

- 最卡环节
- 问题类型判断
- 最该前置模块
- UI 时机判断

## 4. 当前接入位置

领域层：

- `apps/web/src/domain/cases/buildBatchRunFrictionSummaryReport.js`
- `apps/web/src/domain/cases/buildBatchRunFrictionSummaryMarkdown.js`
- `apps/web/src/domain/ui/buildUiOptimizationReadinessReport.js`
- `apps/web/src/domain/ui/buildUiOptimizationReadinessMarkdown.js`

前端渲染：

- `apps/web/public/app/renderers.js`

## 5. UI 时机判断现在怎么变了

当前 UI readiness 不再只看：

- 工作单批次
- 工作单读回
- 试跑记录批次
- 试跑记录读回
- 跨批次重复信号

现在还新增一条：

- 至少 1 批关键人工判断字段补完整

这条规则的含义是：

- 哪怕样本数看起来够了
- 只要人工复盘一直没补完整
- 也不应该太早把问题归到 UI 层

## 6. 当前产品含义

现在“还不进入 UI 优化”的原因可以更清楚地拆开：

1. 样本还不够
2. 跨批次重复信号不够稳
3. 人工复盘质量还没达标

这能帮助后续决策避免混淆：

- 不是所有没到 UI 时机，都是因为批次太少
- 有时是因为复盘还不完整

## 7. 当前前端会多显示什么

跨批次摩擦点汇总现在会多显示：

- 关键人工字段已完整覆盖批次数
- 关键人工字段仍未补齐批次数

UI 就绪度报告现在会多显示：

- 已写人工结论批次
- 人工完整覆盖批次
- 人工仍未补齐批次

## 8. 当前判断

这层补完后，UI 时机判断开始更接近真实产品推进逻辑。

也就是：

- 不是“只要跑了几批就能改 UI”
- 而是“既有重复信号，也有人类复盘开始收敛”时才更适合进入 UI 专题

## 9. 下一步建议

下一步最有价值的是：

1. 真实补完至少 1 批关键人工判断字段
2. 再补 1 批新试跑
3. 重新看跨批次汇总中的完整覆盖批次是否增长
4. 如果增长且重复摩擦点稳定，再正式讨论 UI 优化
