# 复盘看板人工待补任务卡接入_v0.1

## 1. 目标

这次不是再新增一层“提醒要补人工复盘”的说明，而是把待补动作本身收成一张可直接执行的任务卡。

接入目标是：

- 当复盘看板已经知道哪一批最该补
- 就不要只显示“还差人工复盘”
- 而要直接显示“这一批要补哪些字段、每个字段该怎么写”

## 2. 为什么这一步有必要

前一轮我们已经补了：

- `人工复盘补齐后的再判断链路`

它解决的是：

- 补完人工复盘之后，要按什么顺序重新判断 UI 时机

但它还没有完全解决另一个更前置的问题：

- 现在具体该补什么

如果系统只说“先补 batch-b 的人工复盘”，用户仍然需要自己回忆：

- 哪几个字段最重要
- 每个字段到底要回答什么
- 写成什么样才有利于后续 UI 判断

所以这一步补的是“人工待补任务卡”，把这层摩擦再往前收一点。

## 3. 当前接入原则

这块不新开独立页面，也不单独做一个后台功能。

而是直接挂在：

- `批次复盘看板`

原因很明确：

1. 这里已经能算出当前最该补的批次
2. 这里已经能看到当前最强摩擦点和优先补信息
3. 这里本来就是“下一步先做什么”的决策台

所以任务卡应该跟判断卡放在一起，而不是分散到别处。

## 4. 当前数据结构

代码侧新增：

- `manualReviewTaskCard`

它会基于当前优先级最高的待补批次，整理出：

- 当前状态
- 目标批次
- 当前最强摩擦点
- 当前最该先补的信息
- 待补字段列表

每个字段还会补：

- 字段提示问题
- 填写提示

## 5. 当前字段范围

当前任务卡主要围绕 4 个关键人工字段：

1. 最卡环节
2. 问题类型判断
3. 最该前置模块
4. UI 时机判断

这和前面整条 UI readiness 逻辑是一致的。

也就是说：

- 不是任意人工备注都同等重要
- 这 4 项是当前最该优先补的判断输入

## 7. 前端现在会多展示什么

复盘看板现在除了：

- 当前判断
- 最该补的批次
- UI 再判断链路

还会新增：

- `人工复盘待补任务`

它会把“补人工复盘”从一句提醒，变成一张更接近任务单的内容块。

## 8. 这对后续推进的价值

这一步的价值在于，它让系统推进更像一个真实产品工作台，而不是一堆判断结果。

后续你看到复盘看板时，不只是知道：

- 还差人工复盘

而是会直接看到：

1. 先补哪一批
2. 补哪几个字段
3. 每个字段该怎么回答

这会明显降低你下一步实际执行时的来回切换成本。

## 9. 当前结论

可以把这一步压缩成一句话：

**复盘看板现在开始不只负责“判断”，也开始负责把人工复盘待补动作收成可直接执行的任务卡。**
