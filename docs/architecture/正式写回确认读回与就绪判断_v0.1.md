# 正式写回确认读回与就绪判断_v0.1

## 1. 目标

前一轮我们已经有：

- 人工复盘安全写回预览
- 建议态 patch

这次继续往前补一层：

- 正式写回确认读回
- 正式写回就绪判断

它解决的问题是：系统不只要能导出安全写回预览，还要能读回你是否已经在预览里确认“可以正式写回”。

## 2. 当前新增产物

领域层：

- `parseBatchReviewManualSafeWritePreviewNote.js`

应用层：

- `loadLatestBatchReviewManualSafeWritePreviewStatus.js`
- `runBatchReviewManualFormalWriteReadinessPreview.js`

服务端接口：

- `GET /api/batch-review-manual-formal-write-readiness`

前端 API 接线：

- `apps/web/public/app/api.js`

## 3. 当前判断逻辑

系统当前会读回安全写回预览文档里的 3 个确认字段：

- 哪几行你确认可以正式写回
- 哪几行仍需手改
- 是否已经可以进入正式写回

判断规则当前保持简单：

1. 如果还没有安全写回预览：
   - 返回 `no-safe-preview`

2. 如果已经明确写了“可以进入正式写回”，并且“仍需手改”为空：
   - 返回 `ready-to-formal-write`

3. 其他情况：
   - 返回 `awaiting-safe-write-confirmation`

## 4. 为什么要先做这层

因为正式写回已经接近真正修改真实记录的边界。

如果没有一层明确的、可读回的确认状态，后续就会出现两个问题：

1. 系统不知道是“还没确认”，还是“已经确认但没执行”
2. UI 和流程判断都只能靠口头描述，不够稳定

所以这层更像正式写回前的一个 gate。

## 5. 当前结论

可以把这次接入压缩成一句话：

**系统现在已经能从安全写回预览里读回人工确认，并判断是否进入正式写回。**
