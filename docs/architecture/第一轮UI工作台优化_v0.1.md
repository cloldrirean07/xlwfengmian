# 第一轮UI工作台优化_v0.1

## 1. 这轮为什么开始动 UI

这次开始做 UI，不是因为功能已经完全做完，而是因为当前已经具备了足够稳定的真实工作流骨架：

- 首页输入链路已经能跑通
- 第一轮方向卡、第二轮优化、工作区建议已经接通
- 真实案例录入、批量回填、UI 时机判断、复盘看板都已经有实际模块

也就是说，现在页面不再只是一个“占位壳子”，而是已经开始承载真实产品路径。

在这个时点继续完全不动 UI，会出现两个问题：

1. 首屏价值主张不够像成熟产品，难以支撑后续判断
2. 输入入口、验证范围和后续模块之间的层级关系不够清楚

所以这一轮适合做的是：

- 先补首屏与第一轮输入区的专业感
- 先补页面信息层级
- 先让用户更容易理解“这产品当前验证什么、不验证什么、从哪开始用”

而不是：

- 直接进入全站视觉重构
- 一次重做所有面板
- 提前做复杂后台风格或设计系统

## 2. 这轮改动边界

本轮只动：

- `apps/web/public/index.html`
- `apps/web/public/styles.css`
- `apps/web/src/server/server.js`

不动：

- 应用层分析逻辑
- 第一轮 / 第二轮核心输出结构
- Obsidian 导出链路
- 真实案例结构
- 复盘判断逻辑

这样做的目的，是把这轮 UI 明确控制在“前端展现优化 + 一个真实使用中暴露的健壮性修补”范围内。

## 3. 这轮实际解决的问题

### 3.1 首屏像介绍，不像工作台

原来的首屏虽然文案完整，但更像“说明文字 + 几块卡片”，缺少这三个层次：

- 这产品当前要验证什么
- 这产品先不做什么
- 用户现在最该点哪里开始

这会让页面更像一个 demo，而不是一个正在推进中的 AI 产品工作台。

### 3.2 输入区虽然完整，但进入成本偏高

原来的第一轮输入区是直接开始填表。

对于第一次进入页面的人来说，虽然字段不复杂，但缺少两个关键提示：

- “最小可用输入”到底是什么
- 为什么这些字段足以触发一次有效判断

所以本轮没有删字段，而是先补了一层“输入前解释”。

### 3.3 页面很长，但缺少快速定位

随着真实案例录入、批量写入、UI 时机判断、复盘看板都接进来，页面本身已经不是单一首轮 demo。

如果没有简单的页面跳转入口，用户很难快速从首屏切到：

- 第一轮输入
- 真实案例录入
- UI 时机判断
- 复盘看板

所以这轮补了轻量跳转导航，而不是提前做完整侧栏系统。

### 3.4 浏览器请求 favicon 会让服务崩掉

这不是视觉问题，但它是在真实 UI 验证过程中暴露出的阻塞项。

浏览器访问页面后会自动请求 `/favicon.ico`，原来的静态文件读取没有处理 `ENOENT`，导致本地服务直接退出。

这个问题会反复打断页面调试，所以本轮顺手修正。

## 4. 本轮 UI 结构调整

### 4.1 Hero 从单列说明升级成双区结构

现在首屏分成：

1. 左侧主叙事区
   - 产品标题
   - 价值主张
   - 当前能力标签

2. 右侧验证范围区
   - 当前验证目标
   - 首轮输出 / 最轻输入 / 当前价值
   - 当前明确不做的事项

这样用户进入页面后，不再只看到“这是个什么产品”，而会同时看到：

- 它现在聚焦什么
- 它不打算做什么
- 它是不是一个有边界的产品，而不是泛 AI 工具

### 4.2 新增跳转导航

在 hero 下新增轻量 jump nav，直接跳到：

- 第一轮输入
- 真实案例录入
- UI 时机判断
- 复盘看板

这是当前阶段更合适的做法，因为：

- 页面已经足够长
- 但还没有长到必须做全局 sticky 导航系统

### 4.3 第一轮输入区前置解释增强

在第一轮输入表单上方新增两块解释卡：

- 先输入什么
- 最小可用输入

这一层不改变业务逻辑，只是把“用户为什么现在就能开始试跑”讲得更清楚。

### 4.4 判断框架面板强化

右侧 `Decision Frame` 区增加高亮解释块，并在桌面端设置为 sticky：

- 让它更像“陪伴判断”的侧边说明
- 在输入区滚动时，用户仍然能看到当前系统是怎么判断的

这比单纯堆更多说明文字更有效。

## 5. 本轮视觉方向

这轮没有换掉既有主色，而是在原有暖色调基础上做了更明确的“工作台质感”强化：

- hero 侧卡增加层次和阴影
- 指标块更像产品状态卡，而不是普通说明文案
- jump nav 增加更明确的交互感
- 输入区说明卡与主表单建立层级区别
- `Decision Frame` 增强成更有存在感的判断说明区

整体目标不是“设计感越强越好”，而是：

- 更清晰
- 更专业
- 更像真实产品，而不是单纯演示页

## 6. 本轮技术实现点

主要新增的前端结构类包括：

- `hero-grid`
- `hero-side`
- `hero-side-card`
- `hero-metrics`
- `jump-nav`
- `workbench-intro-grid`
- `workbench-callout`
- `guide-highlight`

并补充了两个锚点区：

- `#ui-readiness-section`
- `#review-dashboard-section`

以及一个已有工作台区锚点：

- `#first-round-workbench`

## 7. 健壮性修补

在 `apps/web/src/server/server.js` 中，对静态文件读取增加了缺失文件保护：

- 如果静态资源不存在，返回 `404 Not found`
- 不再因为 favicon 缺失导致本地服务退出

这让页面验证链更稳定，也更适合后续继续做 UI 调整。

## 8. 当前结果

这一轮之后，页面的变化不是“更花”，而是更像一个有边界、有验证目标、有下一步入口的 AI 产品工作台。

最直接的提升在于：

- 首屏更有产品定位感
- 当前验证目标更清楚
- 不做什么更清楚
- 第一轮输入更容易开始
- 长页面里的关键入口更容易定位
- 判断框架的陪伴感更强
- 本地 UI 调试稳定性更高

## 9. 下一步建议

在 UI 上，下一步更值得继续做的是：

1. 优化第一轮结果区的卡片层级与选中态
2. 优化复盘看板与真实案例模块的模块分组关系
3. 再决定是否需要引入更系统的页面导航或折叠结构

不建议下一步立刻做的，是全站统一大改视觉风格。

当前更好的节奏仍然是：

- 先把真实工作流中的重点区块逐步做顺
- 再决定哪些模式值得固化成更正式的设计系统
