# 前端按钮层级与动作语气规范_v0.1

## 1. 文档目的

这份文档不是记录某一次按钮修改，而是把当前已经稳定下来的 CTA 经验，整理成后续可复用的前端规范。

目标有 3 个：

1. 新增页面能力时，按钮不会重新长回“各说各话”
2. 主按钮、次按钮、阶段性按钮的职责更清楚
3. 动作文案能始终服务于“当前在哪一步、下一步做什么”

这份规范适用于当前 `apps/web` 工作台，也为后续新页面、新链路、新后台能力预留统一标准。

## 2. 当前规范要解决的问题

在这次项目推进中，我们已经看到一个很明显的规律：

- 业务逻辑可以是对的
- 页面结构也可以是顺的
- 但如果按钮语气发散，用户还是会感觉页面不够像一个完整产品

典型问题包括：

- 有的按钮在说“进入”
- 有的按钮在说“选择”
- 有的按钮在说“生成”
- 有的按钮在说“继续优化”

如果这些动作没有统一规则，页面会出现两个后果：

1. 用户不知道某个按钮是“当前主动作”还是“辅助动作”
2. 不同分区的按钮会像不同人写的，而不是同一套产品语言

## 3. 规范范围

本规范当前覆盖：

- 第一轮输入区
- 工作区建议区
- 第一轮方向卡
- 第二轮反馈区
- 第二轮结果区

暂不强行覆盖：

- 真实案例维护后台类按钮
- 批量导出与平台运维类按钮
- 开发/实验型一次性脚本入口

原因是当前高频主链路已经相对稳定，而运维区仍然还在继续收敛。

## 4. 按钮层级定义

当前建议把前端按钮分为 3 类。

## 4.1 主按钮

定义：

- 当前步骤最核心、最应推进流程的动作

表现特征：

- 使用主按钮视觉样式
- 在一组动作中优先被看到
- 文案直接回答“点完会发生什么”

当前典型例子：

- `生成 3 张方向卡片`
- `生成这一步建议`
- `采纳并继续下一步`
- `生成第二轮优化结果`

使用规则：

- 每个关键阶段最好只有一个主按钮
- 主按钮要表达明确结果，而不是抽象动作
- 文案里优先写“生成 / 继续 / 进入下一步”这类推进语言

## 4.2 次按钮

定义：

- 可选路径、补充路径、查看路径

表现特征：

- 使用 `ghost-button` 或 `secondary-button`
- 不与主按钮争夺注意力
- 更适合承担“预览、加载、补充查看、暂不采纳”类动作

当前典型例子：

- `运行完整样例`
- `这一步先不采纳`
- `生成 Prompt 预览`
- `加载批量模板`
- `查看最近工作单记录`

使用规则：

- 当动作不会直接推进主流程时，优先使用次按钮
- 次按钮文案不应伪装成主动作
- 如果一个次按钮经常成为真正高频入口，应重新评估是否升级为主按钮

## 4.3 阶段性主按钮

定义：

- 某个对象已经进入“当前处理中”状态时，对它继续推进的动作

表现特征：

- 在局部上下文里是主动作
- 但只在对象被选中、被激活、被承接时出现

当前典型例子：

- 已选方向卡上的 `继续填写第二轮反馈`
- 第二轮结果区里的 `继续填写下一轮反馈`

使用规则：

- 只有在用户已经做完上一步选择时才出现
- 文案要明确“继续做什么”，而不是泛泛说“继续”
- 这类按钮最适合承接状态明确的对象，如“已选卡”“已生成结果”

## 5. 动作语气规范

## 5.1 优先使用结果导向语言

按钮文案优先回答：

- 点完会生成什么
- 点完会进入哪一步
- 点完会不会带着当前结论继续

推荐表达：

- `生成 3 张方向卡片`
- `生成这一步建议`
- `生成第二轮优化结果`
- `采纳并继续下一步`

不推荐表达：

- `处理一下`
- `继续做`
- `开始优化`
- `执行`

因为这些词太抽象，不能帮助用户预判结果。

## 5.2 优先使用阶段语言，而不是模块语言

当按钮属于主链路的一部分时，优先强调“当前这一步”，而不是模块名本身。

推荐：

- `生成这一步建议`
- `这一步先不采纳`

相对弱一些的表达：

- `生成工作区建议`
- `这次建议不采纳`

原因是：

- 模块语言更像系统内部叫法
- 阶段语言更像用户当前正在进行的任务

## 5.3 “继续”必须带宾语

如果按钮里出现“继续”，原则上要让用户知道：

- 继续什么

推荐：

- `继续填写第二轮反馈`
- `继续填写下一轮反馈`

不推荐：

- `继续优化`
- `继续下一步`

除非上下文已经极其清楚，否则“继续”单独出现太空泛。

## 5.4 “进入”用于跨阶段，不用于提交结果

当前规则建议：

- 当动作是跨阶段切换时，可以用“进入”
- 当动作是提交输入、生成结果时，用“生成”更清晰

例如：

- `用这张进入第二轮`
  这是从首轮卡片进入下一阶段

- `生成第二轮优化结果`
  这是在第二轮表单里提交反馈并得到结果

这样“进入”和“生成”就不会混用。

## 6. 当前主链路推荐口径

根据目前已经稳定的页面链路，推荐统一口径如下。

### 第一轮输入

- 主按钮：`生成 3 张方向卡片`

### 工作区建议

- 主按钮：`生成这一步建议`
- 次按钮：`这一步先不采纳`
- 推进按钮：`采纳并继续下一步`

### 第一轮方向卡

- 未选中卡：`用这张进入第二轮`
- 已选中卡：`继续填写第二轮反馈`

### 第二轮反馈

- 主按钮：`生成第二轮优化结果`

### 第二轮结果

- 阶段性主按钮：`继续填写下一轮反馈`

## 7. 样式与层级映射

当前样式层建议继续沿用：

- 主按钮：默认 `button`
- 次按钮：`ghost-button`
- 卡片内阶段性主按钮：`card-primary-cta`
- 卡片内次按钮：`secondary-button`

推荐原则：

- 不要只靠颜色区分按钮层级，文案也要同步表达层级
- 同一层级按钮尽量保持尺寸一致
- 局部主按钮可以满宽，但不要让一个区域出现多个视觉同级的满宽主按钮

## 8. 新增按钮时的判断清单

后续加新按钮时，先回答这 5 个问题：

1. 这个动作是不是当前步骤最重要的动作
2. 点完之后会不会推进主流程
3. 用户能不能只看按钮文案就知道结果
4. 这里应该强调模块名，还是强调“这一步”
5. 文案里如果有“继续”，是否明确写出了继续什么

如果这 5 个问题里有 2 个以上答不清，说明按钮文案或层级还不够稳定。

## 9. 当前不建议做的事

现在先不建议：

- 为每类按钮建立过度复杂的设计 token 体系
- 把所有运维区按钮也立即拉进同一规范
- 在还没稳定使用频率前，先做过细的按钮组件库抽象

当前阶段更适合的是：

- 先让主链路按钮规范稳定
- 再逐步向运维与后台区扩散

## 10. 当前结论

当前这套按钮规范可以概括成一句话：

**主按钮负责推进当前阶段，文案负责说明点完后的结果，所有阶段尽量说同一种动作语言。**

这会让页面在功能继续扩张时，仍然保持一致的产品感。
