# 真实案例概览待处理快捷筛选 v0.1

## 1. 本次改动解决什么问题

此前真实案例概览已经支持：

- 分组标签
- 分组筛选

但对于真实使用来说，用户最常见的问题仍然是：

- 我现在先处理哪几条

如果每次都先理解全部分组，再手动切换，会增加认知成本。

这次补的是：

**一键只看待处理案例。**

## 2. 为什么这是高频入口

在真实使用中，很多时候用户并不想先学习分组体系，而是只想知道：

- 当前还有哪些案例没收尾

所以“待处理”是一个比“全部分组”更贴近高频任务的快捷入口。

## 3. 代码实现

### 3.1 在概览元信息里补充可行动标记

更新：

- `src/domain/cases/buildRealCaseOverviewMeta.js`

新增：

- `isActionable`

当前会被视为待处理的分组包括：

- `优先补写并导出`
- `导出待确认`
- `已导出待继续补写`
- `已导出副本待收敛`

### 3.2 前端筛选支持特殊视图

更新：

- `public/app/renderers.js`

现在除了：

- `all`
- 各具体分组

还支持：

- `actionable`

并在筛选按钮中显示：

- `只看待处理`

## 4. 当前结论

这次改动进一步说明，当前阶段更适合做：

- 信息结构增强
- 维护路径压缩

而不是过早做大规模 UI 视觉重构。

它会直接帮助后续真实跑 `2-3` 条案例时，把注意力集中在当前未收尾的案例上。
