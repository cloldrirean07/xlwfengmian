# 批次试跑结构化摩擦点模板_v0.1

## 1. 这次补的是什么

在已有“批次试跑记录”能力上，再补一层固定的摩擦点分类模板。

目标不是让记录更长，而是让每一批真实试跑都按同一套结构留下证据，方便后面判断：

- 哪类问题最常出现
- 哪些更像规则问题
- 哪些更像输入结构问题
- 哪些才真的值得进入 UI 优化讨论

## 2. 为什么现在要补这层

当前批次试跑记录已经可以写：

- 最卡环节
- 最难补字段
- 与通用 AI 的差异
- 是否进入 UI 优化讨论

但如果完全自由填写，会有两个问题：

1. 不同批次之间难比较  
   每次写法不同，后面很难横向看出重复摩擦。

2. 容易过早把问题归因到 UI  
   很多“不顺手”其实是输入结构重、推荐动作不清楚，未必真是视觉问题。

所以这次补的是“结构化摩擦点模板”。

## 3. 模板分类

代码位置：
- `apps/web/src/domain/cases/buildBatchRunFrictionTemplate.js`

当前固定为 5 类：

1. 输入准备与案例结构
2. 补写建议与优先顺序
3. 结果阅读与选择判断
4. 导出沉淀与后续接力
5. 是否进入 UI 优化讨论

每类都包含：

- `label`
- `whyItMatters`
- `priorityReason`
- `priorityScore`
- `prompts`
- `signals`

## 4. 当前优先级生成方式

不是纯静态模板，而是会根据当前批次状态生成优先原因和信号。

主要依据：

- `validationSummary.summary.totalMissingFields`
- `validationSummary.summary.avgMissingFields`
- `validationSummary.recommendedBatchActions`
- `validationSummary.rows`
- `latestWorksheetHistory.latestExportStatus`

例如：

- 缺失字段很多时，`输入准备与案例结构` 会被排得更前。
- 推荐动作很多时，`补写建议与优先顺序` 会更值得重点观察。
- 没有稳定导出或读回确认时，`导出沉淀与后续接力` 会被前置。

## 6. Markdown 记录结构变化

批次试跑记录从原来的：

- 人工试跑记录
- 对产品的影响

升级为：

- `## 5. 结构化摩擦点记录`
- `## 6. 人工试跑结论`
- `## 7. 对产品的影响`
- `## 8. 下一步动作`

其中结构化摩擦点记录会自动展开每类：

- 为什么看这块
- 当前优先原因
- 观察信号
- 试跑记录问题
- 本批结论

## 7. 前端展示变化

试跑记录预览区新增：

- `推荐先记录的摩擦点类别`

它的目的不是替代完整 Markdown，而是先告诉用户：

- 这批最值得优先观察哪几类问题

这样真实试跑时不容易无从下手。

## 8. 对后续 UI 优化讨论的价值

这层模板补完后，后续判断 UI 时机会更稳：

- 如果重复出现的是“输入准备与案例结构”，优先改输入链路。
- 如果重复出现的是“补写建议与优先顺序”，优先改规则说明和行动引导。
- 如果重复出现的是“结果阅读与选择判断”，才更像需要重组结果区信息架构。
- 如果重复出现的是“导出沉淀与后续接力”，优先改导出文档和接力链路。

也就是说，UI 讨论会从“感觉哪里乱”变成“哪类摩擦反复出现”。

## 9. 下一步建议

建议先连续跑 1 到 2 批真实试跑，再观察：

- 哪两类摩擦点最常出现
- 哪一类最稳定、最值得先做产品改动

等这些证据更稳定后，再进入真正的 UI 优化讨论，会更扎实。
