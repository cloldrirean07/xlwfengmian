# 批次试跑人工结论回流_v0.1

## 1. 本次补的是什么

在已有：

- 单批次试跑记录
- 结构化摩擦点模板
- 跨批次摩擦点汇总

基础上，再补一层“人工结论回流”。

也就是说，系统不再只看自动生成的摩擦点类别和推荐动作，还会尝试读取你在 Obsidian 里手填的试跑结论字段。

## 2. 为什么要补这层

自动信号能回答：

- 缺哪些字段
- 推荐补什么
- 哪类摩擦点理论上更值得关注

但它回答不了：

- 你真实觉得最卡的是哪一步
- 你主观判断它更像功能问题还是界面问题
- 你是否已经觉得 UI 到时机

这些内容对后续 UI 决策非常关键，所以需要从人工结论里读回来。

## 3. 当前解析字段

代码位置：
- `apps/web/src/domain/cases/parseBatchRunRecordReviewNote.js`

当前可稳定解析的字段：

- `这批案例最卡的环节`
- `哪些字段最难补`
- `哪个输出最有价值`
- `和通用 AI 相比更有帮助的点`
- `和通用 AI 相比仍然不够好的点`
- `哪个按钮或模块最该前置`
- `哪段说明文字太多`
- `哪个步骤最值得做成更强引导`
- `当前更像功能问题，还是界面问题`
- `这批试跑最关键的结论`
- `下一批还要不要继续同样赛道`
- `UI 优化是否已经到时机`

## 4. 解析来源

当前不是直接读代码侧 `run-record.json`，而是优先：

1. 读取批次试跑记录最新导出日志
2. 找到对应的 Obsidian Markdown 路径
3. 解析 Obsidian 文档里人工填写的字段

这意味着后续你只要在 Obsidian 里补充这些字段，系统就能逐步把人工判断接回汇总层。

## 5. 当前接入位置

应用层：
- `apps/web/src/application/runBatchRunFrictionSummaryPreview.js`

领域层：
- `apps/web/src/domain/cases/parseBatchRunRecordReviewNote.js`
- `apps/web/src/domain/cases/buildBatchRunFrictionSummaryReport.js`
- `apps/web/src/domain/cases/buildBatchRunFrictionSummaryMarkdown.js`

## 6. 当前汇总里新增的内容

跨批次汇总现在新增：

- `已填写人工结论的批次数`
- `人工试跑结论回看`

汇总会尽量展示：

- 哪一批最卡什么
- 更像功能问题还是界面问题
- 是否已经到 UI 讨论时机

## 7. 为什么这层重要

有了这层之后，后续 UI 决策不再只是：

- 自动信号说这里该优先

而是能变成：

- 自动信号说这里反复出现
- 人工结论也说这里最卡

这两层叠加，才更适合真的开始做 UI 优化。

## 8. 当前限制

目前这层只解析固定字段，还没有做：

- 对“本批结论”自由文本的更深归纳
- 对不同写法的同义归一
- 对模块名称的自动聚类

所以现阶段更建议你在 Obsidian 里尽量按模板原字段填写，系统读取会更稳定。

## 9. 下一步建议

下一步最有价值的是：

1. 真正手动填写 1 到 2 批试跑结论
2. 观察跨批次汇总里，人工判断是否开始稳定指向相同问题
3. 再决定是否正式开始 UI 优化讨论
