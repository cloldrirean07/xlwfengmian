# 第一轮到第二轮视觉节奏统一_v0.1

## 1. 这轮为什么继续做 UI

在已经完成：

- 第一轮结果区优化
- 第二轮对比优化
- 工作区到第二轮的衔接优化
- 第二轮继续优化入口

之后，主链路从功能上已经比较完整了。

但页面仍然有一个更细的体验问题：

- 第一轮方向卡区有自己的表达语气
- 已选方向摘要区有另一种表达语气
- 第二轮结果区又是另一种结果语气

虽然逻辑已经连通，但视觉上仍然会让人感觉：

- 这是几个“功能块”
- 而不是一条连续的产品流程

所以这轮要处理的，不再是流程有没有，而是流程的“语气是不是统一”。

## 2. 这轮要解决的问题

本轮主要解决 3 个问题：

1. 从第一轮选中卡进入第二轮时，是否能感到自己在同一条链路上
2. 第二轮结果页是否能明确告诉用户“这是承接刚才那张卡和那次反馈的结果”
3. 第一轮摘要与第二轮结果区是否能共享一套更稳定的节奏表达

也就是说，这轮优化的是“连续感”，不是信息量。

## 3. 设计原则

本轮没有重做区块结构，而是采用最轻的统一方式：

- 不新增页面层级
- 不新增复杂导航
- 不新增新的折叠系统

只增加一层统一的承接条：

- 在第一轮已选方向摘要区出现一次
- 在第二轮结果区再出现一次

这样两个关键节点会开始说同一种“阶段语言”。

## 4. 本轮具体改动

## 4.1 抽出统一承接条渲染函数

在 `renderers.js` 中新增：

- `renderJourneyBridge(stageLabel, carryText, nextAction)`

这不是新的业务模块，而是一层轻量的阶段提示组件。

它统一包含三部分：

1. 阶段标签
2. 当前阶段最重要的动作
3. 这一步承接自什么 / 接下来该怎么想

这样可以让不同阶段的提示，不再只是零散的一句说明，而是共用一套语法。

## 4.2 在已选方向摘要区加入承接条

在 `renderSelectedCardSummary` 中新增：

- `首轮选择已完成`
- `下一步：只说一个最想改的主问题`

并明确说明：

- 你现在不是重新选方向
- 而是在已选卡基础上继续缩小修改重点

这一步的价值是让第二轮表单前的区域，不再只是“选中结果回显”，而更像一个正式的过渡节点。

## 4.3 在第二轮结果区加入承接条

在 `renderRefinementResult` 中新增：

- `第二轮结果已生成`
- `下一步：确认保留点，再决定是否继续优化`

并明确说明：

- 这一屏不是新的随机结果
- 它承接的是你刚才选中的方向和那次反馈

这样第二轮结果页就不再只是“展示改后结果”，而开始承担“解释当前所处阶段”的作用。

## 4.4 为承接条补统一样式

在样式层新增：

- `journey-bridge`
- `journey-bridge-top`
- `journey-chip`

设计目标不是做一个强导航，而是做一个柔和但稳定的视觉承接层：

- 与方向卡、结果卡共享同一配色语气
- 比普通说明块更有存在感
- 但不抢过主内容

同时也补了移动端下的尺寸适配，避免它在手机上显得过高。

## 5. 涉及文件

- `apps/web/public/app/renderers.js`
- `apps/web/public/styles.css`

- 业务逻辑
- 方向判断规则
- 二轮结果结构
- API / 数据链路
- Obsidian 导出逻辑

## 7. 这轮带来的价值

这轮之后，第一轮和第二轮之间开始共享一套统一的节奏语言。

最直接的提升是：

- 页面更像一条连续产品链路
- 第二轮前后的“阶段感”更明确
- 已选方向区和第二轮结果区不再像两套不同的说明体系
- 产品整体的专业感和稳定感更强

## 8. 对后续 UI 的意义

到这一步，当前 UI 已经不是简单地在“补按钮、补提示”，而开始进入更细的产品节奏打磨。

所以下一步更值得看的将是：

1. 第一轮与第二轮之间是否还需要更统一的按钮层级
2. 第二轮结果区中是否要进一步强调“保留点”
3. 等真实案例证据再多一些后，再进入更完整的系统级视觉统一讨论
