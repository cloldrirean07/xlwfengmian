# 真实案例概览接入最新导出状态 v0.1

## 1. 本次改动解决什么问题

此前真实案例概览已经能显示：

- 平台
- 平台案例 ID
- 复跑优先级
- 维护标签

但如果不点进单条案例，页面并不知道：

- 这条案例是否已经导出到 Obsidian
- 最近一次导出是覆盖还是副本
- 最近一次读回是否成功

这次补的是：

**把最新导出状态直接挂回真实案例概览。**

## 2. 为什么这一步重要

如果真实案例列表只是静态信息，它更像“数据清单”。

一旦把最新导出状态回挂进去，它就开始更接近真正的维护入口，因为用户能先快速判断：

- 哪些案例还没进入知识库维护
- 哪些案例最近刚导出过
- 哪些案例最近一次导出是一份副本

## 3. 代码实现

### 3.1 新增导出状态读取器

新增：

- `src/infrastructure/exports/loadLatestRealCaseFillExportStatus.js`

职责：

- 读取 `outputs/obsidian-export-logs/real-case-fill-sheets/<caseId>/`
- 找到最新一条导出日志
- 返回最新导出摘要

当前返回字段包括：

- `exportId`
- `exportedAt`
- `targetPath`
- `actionLabel`
- `requestedMode`
- `readbackOk`
- `matchedExpectedContent`
- `logPath`

### 3.2 在案例列表应用层统一收口

更新：

- `src/application/listAvailableCases.js`

现在真实案例列表返回时，会自动附带：

- `latestExportStatus`

这样前端无需自己去扫导出日志目录。

## 4. 前端表现

更新：

- `public/app/renderers.js`

真实案例卡片现在会额外展示：

- 最近导出动作
- 导出一致性状态
- 最近导出时间

这让真实案例概览在不展开详情的情况下，也能先承担一部分维护看板作用。

## 5. 当前结论

现在真实案例概览已经不只是“写入后重读列表”，而是开始具备：

- 基础案例信息
- 维护优先级信息
- 最新导出状态信息

这说明真实案例链正在从“单条操作集合”继续推进到“轻量维护总览”阶段。
