# 首页三组使用场景微说明接入_v0.1

## 1. 本轮为什么继续补这一层

前面已经完成了两层基础：

- 首页三组的结构分层
- 首页三组的默认展开 / 收起策略

但这还不够。

因为用户现在虽然能看出：

- 这里分成了几组
- 哪组默认展开

却还不一定能立刻理解：

- 这组更适合谁用
- 什么时候该打开它
- 为什么它默认展开或默认收起

所以这一轮补的不是新的功能，而是把“结构理由”变成用户一眼可读的微说明。

## 2. 本轮要解决的问题

当前首页三组如果只有标题和一段说明，会有两个问题：

1. 用户需要自己推断“我现在是不是应该点开这组”
2. 默认显隐策略虽然存在，但理由没有显性表达

这会让首页依然带一点“内部人才懂”的感觉。

所以这轮的目标是：

- 让每组都明确回答“适合谁 / 何时用 / 默认策略”

## 3. 本轮实际改动

## 3.1 为三组统一补 `group-meta-row`

在每个 `group-intro` 下新增：

- `group-meta-row`

它不是新的业务结构，而是一层轻量的说明带。

## 3.2 为每组补 3 个微说明标签

每组固定补三类信息：

1. `适合谁`
2. `何时用`
3. `默认策略`

这让三组不只是“看起来分开”，而是真正具备一致的解释语法。

## 3.3 三组当前说明口径

### 主链路辅助验证工具

- `适合谁：你自己做链路验证时`
- `何时用：想快速看 Prompt / 样例是否跑通时`
- `默认策略：先收起，按需打开`

### 案例维护工作台

- `适合谁：你做案例库建设与维护时`
- `何时用：准备录入、回填、复核真实案例时`
- `默认策略：保持展开，作为当前高频工作区`

### 验证与复盘工作台

- `适合谁：你做阶段复盘和决策判断时`
- `何时用：积累多批次记录后准备讨论 UI 时`
- `默认策略：先收起，阶段性集中查看`

## 4. 为什么这样设计

这层设计的价值不在于信息更多，而在于：

- 帮助用户快速建立“现在该去哪组”的判断
- 让默认显隐策略不再像拍脑袋决定
- 让首页从“结构清楚”再往前走到“使用时机也清楚”

这对当前项目特别重要，因为首页不是普通单一产品页，而是一个过渡期总览工作台。

## 5. 涉及文件

- `apps/web/public/index.html`
- `apps/web/public/styles.css`

本轮没有修改：

- `createApp.js`
- `renderers.js`
- 任何应用层或领域层逻辑

## 6. 视觉实现方式

样式层新增：

- `group-meta-row`
- `group-meta-chip`

这层采用的是：

- 轻标签
- 同一组内并列展示
- 移动端下改为整行堆叠

目标不是抢过主标题，而是用最轻的视觉成本补足“谁用 / 何时用”的决策提示。

## 8. 这轮带来的价值

这轮之后，首页三组终于具备三层完整表达：

1. 这组是什么
2. 这组是否默认展开
3. 这组适合谁、什么时候用

这样首页的入口优先级不再只是“界面层控制”，而开始变成真正的产品引导。

## 9. 对后续 UI 优化的意义

这一步做完后，后续 UI 优化就可以更自然地进入下一层：

- 不只是继续加说明
- 而是开始判断首页是否需要更轻的组内导航、层级收口和节奏强化

换句话说，这轮是在为“结构化 UI 优化”继续清路。
