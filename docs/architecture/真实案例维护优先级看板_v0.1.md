# 真实案例维护优先级看板 v0.1

## 1. 本轮解决的问题

现在系统已经有两条与真实案例有关的能力：

- `real-case-readiness`
  - 看字段是否补全
- `key-case-rerun-plan`
  - 看哪些案例进入关键复跑链

但它们各自只回答一部分问题。

真正做产品推进时，你还需要一个更直接的判断：

**当前哪条真实案例最值得优先维护，为什么。**

所以这轮新增了“真实案例维护优先级看板”。

## 2. 这张看板看什么

它同时综合两层信息：

### 2.1 维护优先级

来源：

- `operations.keyCaseRerunPriority`
- `operations.maintenanceTags`

回答的是：

- 这条案例值不值得被优先维护
- 它为什么在维护链里重要

### 2.2 就绪度

来源：

- `inspectRealCaseReadiness`

回答的是：

- 这条案例现在能不能直接进验证
- 如果不能，还缺什么

## 4. 当前规则设计

### 4.1 优先级分层

根据 `keyCaseRerunPriority` 映射：

- `P1`
  - `>= 8`
- `P2`
  - `>= 4`
- `P3`
  - `> 0`
- `Backlog`
  - `= 0`

### 4.2 动作建议

当前按“优先级 + 就绪度”给出一句建议，例如：

- `P1` 且未就绪
  - 优先补齐关键缺失字段，再进入验证
- `P1` 且已就绪
  - 优先进入手动验证与复跑
- `P2` 且待回填
  - 先完成基础字段回填

## 5. 当前看板价值

这张看板的作用不是替代就绪度报告，而是把：

- 维护价值
- 回填状态
- 推荐动作

放到同一个视图里。

这很适合你后面开始补多条真实案例时，决定：

- 先补哪条
- 哪条继续留在 Backlog
- 哪条值得提到关键复跑链

## 6. 当前结果

本轮生成后，`real-001` 当前显示为：

- `P2 / 6`
- 就绪度：待回填
- 当前建议动作：先完成基础字段回填

也就是说：

- 它不是最低优先级
- 但现在最重要的不是反复复跑，而是先把基础字段补齐

## 7. 下一步建议

### 7.1 补更多真实案例

现在这张看板已经准备好了，后续最有价值的不是继续加结构，而是让更多真实案例进来。

### 7.2 增加“人工调整优先级”记录

后续可考虑把：

- 代码侧推荐优先级
- 人工最终优先级

分开记录，便于复盘。

### 7.3 与关键复跑计划联动

后续可以增加：

- 看板中一键筛选 `P1/P2`
- 按维护标签生成复跑计划

这样真实案例维护链会更顺。
