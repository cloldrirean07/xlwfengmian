# 工作区建议到第二轮衔接优化_v0.1

## 1. 这轮为什么要补这一步

在已经完成：

- 首屏与第一轮输入工作台优化
- 第一轮结果卡比较优化
- 第二轮结果对比优化

之后，页面主流程已经基本成形。

但还有一个很明显的断点：

用户在“工作区建议”里看完一轮中间建议后，不一定知道这条建议和后面的三张方向卡、第二轮优化到底是什么关系。

这会带来两个问题：

1. 工作区建议像一段额外说明，而不是主流程的一部分
2. 用户采纳建议后，不容易自然进入“选卡 -> 二轮反馈”的下一步

如果这个断点不补上，页面虽然功能齐了，但体验上还是会像几个模块拼在一起，而不是一条连续的产品链路。

## 2. 这轮要解决的核心问题

这轮不是新增新能力，而是补清 3 个认知问题：

1. 这份工作区建议会不会进入第二轮
2. 我看完建议后下一步应该做什么
3. 采纳建议以后，页面会不会自然把我带到下一个动作

也就是说，这轮优化的重点不是“更好看”，而是“更连续”。

## 3. 设计原则

本轮继续保持之前的 UI 推进原则：

- 不新增复杂模块
- 不提前做大范围视觉重构
- 只补真实使用里最容易断掉的节点

对应到这一步，就是：

1. 在工作区建议结果里直接解释它与第二轮的关系
2. 在采纳 / 不采纳状态里直接给出下一步动作
3. 用滚动联动把用户带到当前最该看的区域

## 4. 本轮具体改动

## 4.1 工作区建议结果区补上“怎么进入第二轮”

在 `renderActionWorkspaceResult` 中，保留原有：

- summary
- refinedTask
- nextSuggestion
- linkedDirection
- draftPromptLine
- recommendedFollowUp
- riskChecks

之外，新增两块明确说明：

### 这份建议会怎么进入第二轮

直接告诉用户：

- 这次建议先帮助缩小本轮最值得改什么
- 选中方向卡后，第二轮会自动带上这次建议
- 如果不采纳，也不会污染正式结果

这样用户不需要自己猜这条建议是不是“只是参考”。

### 建议你接下来怎么做

直接给出顺序：

1. 先判断这次建议里有没有一句真的愿意执行
2. 再回到 3 张方向卡做选择
3. 二轮只提一个主修改点

这让工作区建议从“建议说明”变成“带路提示”。

## 4.2 工作区决策状态补上“当前下一步”

在 `renderWorkspaceDecisionStatus` 中，新增：

- `当前下一步`

并区分两种情况：

### 采纳

明确告诉用户：

- 回到下方 3 张方向卡
- 第二轮会继承这次建议
- 反馈时优先只说一个主变量

### 不采纳

明确告诉用户：

- 这次建议不会带入第二轮
- 可以直接按自己的判断继续选卡
- 如果方向仍不贴，可以重新生成一次工作区建议

这一步的目的，是让“采纳 / 不采纳”不只是记录动作，而是立即变成流程分流提示。

## 4.3 第二轮提示区补上“已接入的工作区建议”

在 `renderRefineWorkspaceHint` 中，把原来较轻的一句提示升级成完整结构：

- 已接入的工作区建议摘要
- 会自动带入二轮的提示
- 这会怎么影响第二轮
- 当前更适合怎么提反馈

这样用户在进入第二轮时，不需要回忆：

- 我前面工作区里到底说了什么
- 系统会怎样理解那条建议
- 我接下来反馈时要怎么说才更有效

这一步本质上是在给第二轮做“上下文解释层”。

## 4.4 提交与决策后的滚动联动

在 `createApp.js` 中补了两个关键滚动动作。

### 工作区建议生成后

提交工作区表单后，页面会自动滚到：

- `actionWorkspaceResult`

用户会立即看到刚生成的建议，而不是还停留在表单位置。

### 保存工作区决策后

如果当前还没选方向卡，则自动滚到：

- `cardsContainer`

如果当前已经选了方向卡，则自动滚到：

- `refinePanel`

这意味着页面开始具备一种更接近产品流程的“你现在该去哪里”的引导，而不是让用户自己找下一块内容。

## 7. 这一轮带来的价值

这一轮之后，工作区建议不再像一个旁支功能，而开始成为主流程的一部分。

最直接的提升是：

- 用户更容易理解工作区建议的角色
- 采纳 / 不采纳不再只是记录，而是流程控制点
- 从工作区到选卡、再到第二轮的链路更顺
- 页面更像“真实产品流程”，而不是“多个模块并列”

## 8. 对后续 UI 优化的意义

这轮完成后，首页到第二轮的主流程连续性进一步变强。

所以接下来如果继续做 UI，更值得看的将不是再补文案解释，而是：

1. 是否需要给“选卡 -> 第二轮 -> 结果对比”增加更轻的步骤感
2. 是否要在移动端进一步压缩工作区与二轮之间的视觉跳跃
3. 等真实批次证据再多一些后，再讨论更大范围的视觉统一

换句话说，这一步仍然属于“先把流程走顺”，而不是“先把视觉做满”。
