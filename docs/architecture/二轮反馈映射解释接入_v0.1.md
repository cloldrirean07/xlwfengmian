# 二轮反馈映射解释接入 v0.1

## 本次目的

把二轮优化从“只看到结果”推进到“能解释为什么这样改”，并且让这层解释可进入记录体系。

## 本次实现

### 1. 反馈映射增加稳定 ID

- 在 `apps/web/data/rules/feedback-catalog.json` 中为：
  - `negativeMappings`
  - `positiveMappings`
  增加 `id`

这样后续做规则修订、实验记录、误判复盘时，可以稳定引用具体映射，而不是只看中文文案。

### 2. 二轮解释结构化输出

- 新增 `src/domain/refinement/buildFeedbackMappingExplanation.js`
- `createRefinementSession` 现在会额外返回：
  - `ruleMeta`
  - `mappingExplanation`

其中包含：

- 命中的负向映射 ID
- 命中的正向保留信号 ID
- 规则版本
- 命中关键词
- 是否使用兜底规则
- 可直接显示或导出的解释摘要

### 3. 前端二轮结果页解释接入

- 二轮结果页新增展示：
  - 命中负向映射
  - 命中正向保留信号
  - 规则版本
  - 这轮为什么这样改

### 4. 记录链路补充

- `buildCaseRunMarkdown` 现在会把：
  - 首轮规则版本
  - 二轮规则版本
  - 命中映射 ID
  - 命中关键词
  - 二轮解释摘要
  一起写入端到端运行记录

## 这样做的价值

- 二轮优化开始具备“可复盘性”，不再只是结果型建议
- 后续做误判样本、规则修订、实验分析时，有明确映射 ID 可追踪
- 让 UI、记录、方法论文档逐步共享同一套解释结构

## 当前边界

- 目前解释仍然是规则驱动说明，还没有接入用户实际效果反馈闭环
- 还没有把这层解释单独导出到 Obsidian 验证记录中

## 下一步建议

1. 把二轮解释写入独立实验记录导出。
2. 建立“命中映射 -> 误判样本 -> 规则修订任务”的闭环。
3. 后续在前端增加“是否接受这次二轮修正解释”的轻量反馈入口。
