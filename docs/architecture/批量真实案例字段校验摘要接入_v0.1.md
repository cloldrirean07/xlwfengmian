# 批量真实案例字段校验摘要接入 v0.1

## 本次目标

在“批量真实案例录入预览与确认写入”链路上，补一层批量字段校验摘要，让用户在写入前先看到：

- 这一批案例整体缺多少关键字段
- 哪些字段最常缺
- 每条案例当前大概卡在哪

这样真实案例库不只是“能写入”，而是“写入前就能判断质量”。

## 为什么这一步重要

如果没有这层摘要，批量录入只是把多条 JSON 一次性写进去：

- 对产品经理视角不够专业
- 对后续回填优先级没有帮助
- 对真实案例库质量没有约束

加上这层后，产品链路会更像一个内部工作台：

1. 先批量准备案例
2. 再看这一批的结构质量
3. 最后决定是否写入，或者先补字段

## 设计原则

### 复用单条规则，不另起一套口径

本次没有为批量场景重新发明规则，而是直接复用现有：

- `inspectRealCaseReadiness`
- `buildRealCaseReadinessReport`

这样可以保证：

- 单条案例检查
- 批量预览检查
- 回填工作单
- 后续维护链

都建立在同一套“字段是否完整”的判断口径上。

### 摘要只做决策支持，不替代人工判断

这层摘要不会替你判断“案例值不值得做”，它只回答：

- 当前结构完整度如何
- 哪些字段最影响后续回填
- 这批案例该先补什么

## 代码结构

### 新增领域层

- `src/domain/cases/buildRealCaseBatchValidationSummary.js`

负责：

- 对批量预览中的每条 `record` 运行就绪度检查
- 汇总整批案例的 readiness 分布
- 汇总最常缺字段
- 生成逐条案例的缺失摘要

输出结构分三层：

1. `summary`
2. `missingFieldStats`
3. `rows`

### 应用层接入

- `src/application/createRealCaseBatchScaffoldPreview.js`
- `src/application/commitRealCaseBatchScaffold.js`

在批量预览和批量确认写入结果中，都挂出：

- `validationSummary`

这样前端不需要再额外调第二个接口。

### 前端展示

- `public/app/renderers.js`

新增批量校验摘要展示块，显示：

- 案例数
- 可进入手动验证数
- 部分回填数
- 待回填数
- 缺失字段总数
- 平均每条缺失字段数
- 本批次最常缺字段 Top 5
- 每条案例的缺失风险摘要

## 当前交互效果

在批量预览时，用户会先看到：

1. 本次批量新增数
2. 写入后索引总数
3. 批量字段校验摘要
4. 本次待创建案例列表
5. 第一条案例 record 预览
6. 索引尾部预览

这意味着用户现在可以在“写入前”就知道：

- 这批案例是否都只是占位骨架
- 是否应该先补字段再写入
- 哪些字段最值得先收敛成模板

## 下一步建议

这一步完成后，更合理的下一步不是做大范围 UI 美化，而是继续补：

1. 批量字段校验后的“推荐动作”

3. 真实案例批次试跑记录
