# 真实案例概览优先级与分组规则 v0.1

## 1. 本次改动解决什么问题

此前真实案例概览已经能显示：

- 基础案例信息
- 最新导出状态

但列表本身还是“平铺展示”，缺少明确的维护顺序语义。

这次补的是：

**为真实案例概览增加分组标签与排序分值。**

## 2. 为什么要做这一步

你后面真正跑 `2-3` 条真实案例时，最需要的不是更多字段，而是：

- 哪条该先补
- 哪条已经进入导出维护
- 哪条已经可以接近验证

如果没有优先级和分组，真实案例列表只会越来越像资料堆积区。

## 3. 代码实现

### 3.1 新增概览规则构造器

新增：

- `src/domain/cases/buildRealCaseOverviewMeta.js`

职责：

- 根据 `readinessStatus`
- 根据 `keyCaseRerunPriority`
- 根据 `latestExportStatus`

生成概览级元信息：

- `laneLabel`
- `laneOrder`
- `priorityScore`
- `exportActionLabel`
- `exportMode`
- `readbackOk`

### 3.2 当前分组语义

当前主要分成几类：

- `优先补写并导出`
- `导出待确认`
- `已导出待继续补写`
- `已导出副本待收敛`
- `已可进入验证`

这些标签不是 UI 文案装饰，而是列表排序和后续维护策略的基础语义。

### 3.3 当前排序逻辑

在真实案例内部，当前按下面原则排序：

1. 更高优先的分组先排
2. 同分组内，结合回填状态与复跑优先级算 `priorityScore`
3. 分值接近时，再看 `keyCaseRerunPriority`

## 4. 前端表现

更新：

- `public/app/renderers.js`

真实案例卡片现在会显示：

- 分组标签
- 当前回填状态
- 回填完成进度

概览顶部还会显示各分组数量。

这使得概览开始更像一个轻量维护看板，而不是单纯的卡片列表。

## 5. 当前价值

这次改动最直接的价值是：

1. 为真实案例跑通 `2-3` 条完整链路提供更清楚的先后顺序
2. 让后续 UI 优化时，有稳定的信息结构依据
3. 避免未来案例变多后再临时补排序语义

## 6. 当前结论

现在真实案例概览已经具备三层能力：

1. 基础案例信息
2. 最新导出状态
3. 概览优先级与分组语义

这说明它已经从“列表展示”进一步推进到“维护入口排序层”。
