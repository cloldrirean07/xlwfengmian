# 首页主导航与组内轻导航层级规则_v0.1

## 1. 文档目的

这份文档要解决的不是“导航好不好看”，而是首页当前已经同时存在两种导航后，它们之间的职责边界和层级关系应该怎么定义。

当前首页里已经有：

- Hero 下的首页主导航 `jump-nav`
- 工作台内部的组内轻导航 `group-shortcut-row`

如果不把这两层关系讲清楚，后续很容易出现两个问题：

1. 导航越来越多，但用户不知道应该先看哪一层
2. 不同层级的导航视觉和语义混在一起，页面会越来越像控制台

所以这份规范的目标，是把“主导航”和“组内轻导航”正式区分开。

## 2. 当前为什么必须补这层

到现在为止，首页已经完成了两类导航验证：

### 2.1 首页主导航

当前作用：

- 从 Hero 区快速跳到首页主要区域

当前入口包括：

- `先做第一轮输入`
- `看真实案例录入`
- `看 UI 时机判断`
- `看复盘看板`

### 2.2 组内轻导航

当前已经在两个工作台验证成立：

- 案例维护工作台
- 验证与复盘工作台

它们的作用是：

- 在一个已经进入的工作台里，继续跳到更细的层级

也就是说，这两层导航不是竞争关系，而是父子关系。

## 3. 当前层级定义

## 3.1 首页主导航

定义：

- 页面级导航

职责：

- 帮助用户快速从 Hero 区到达首页主要工作区
- 回答“我应该先去哪一大块”

适用范围：

- 首页跨区块跳转

当前对应实现：

- `jump-nav`

## 3.2 组内轻导航

定义：

- 工作台级导航

职责：

- 当用户已经决定进入某个工作台后，帮助他更快到达组内细层
- 回答“我已经进来了，现在先看哪一段”

适用范围：

- 单个工作台内部的二级结构跳转

当前对应实现：

- `group-shortcut-row`

## 4. 两层导航的核心区别

当前建议把两层导航的区别固定成下面 4 条。

### 4.1 主导航回答“去哪一组”

例如：

- 去第一轮输入
- 去真实案例录入
- 去 UI 时机判断

这说明主导航面对的是页面级决策。

### 4.2 组内轻导航回答“组里先去哪一段”

例如：

- 先看单条录入
- 直接去批量维护
- 先看时机判断
- 直接去复盘看板

这说明组内导航面对的是工作台内决策。

### 4.3 主导航曝光更强

因为它承担的是“页面入口分流”。

所以它应该：

- 更早出现在首屏
- 视觉上略强
- 数量更少、更概括

### 4.4 组内轻导航曝光更弱

因为它承担的是“进入工作台后的精细分流”。

所以它应该：

- 只有进入对应工作台时才显得有意义
- 视觉层级低于主导航
- 文案更具体

## 5. 当前文案规则

## 5.1 首页主导航文案

建议特点：

- 面向整组区域
- 更概括
- 更像入口提示

当前合理写法：

- `先做第一轮输入`
- `看真实案例录入`
- `看 UI 时机判断`
- `看复盘看板`

## 5.2 组内轻导航文案

建议特点：

- 面向具体分流
- 更像行动路径
- 更明确“先 / 再 / 直接去”

当前合理写法：

- `先看单条录入`
- `直接去批量维护`
- `先看时机判断`
- `再看跨批次信号`
- `直接去复盘看板`

## 6. 当前视觉层级规则

当前页面实现上，应该继续保持下面的关系：

### 6.1 主导航更强

当前通过这些方式体现：

- 出现在 Hero 区
- `jump-nav` 位置更靠前
- 胶囊更高、更亮
- 默认带更强的卡片感

### 6.2 组内轻导航更轻

当前通过这些方式体现：

- 只出现在具体工作台组头部
- 胶囊更轻、更小
- 文案更具体
- 颜色更偏辅助强调

## 7. 为什么主链路区暂时不再继续加导航

这里要特别说明一条边界：

- 首页主导航已经足够承担主链路入口分流
- 当前主链路内部不建议再补更多导航层

原因是：

1. 主链路需要顺着体验走
2. 主链路不是工作台式的二级面板集合
3. 当前主链路更需要流程感，而不是跳转感

所以当前导航体系最健康的状态是：

- 主链路靠流程和按钮推进
- 工作台靠组内轻导航加速

## 8. 当前统一结论

可以把这份规则压缩成一句话：

**首页主导航负责跨工作区分流，组内轻导航负责工作台内部加速，两者既不能抢角色，也不能做成同一层强度。**

## 9. 这对后续 UI 讨论意味着什么

到这一步，我们已经不再只是“有没有导航”的问题，而开始具备了真正的导航架构基础。

后续讨论首页统一 UI 时，可以明确分成两层：

1. 页面级入口分流怎么做
2. 工作台级快速到达怎么做

这比直接讨论“要不要再加几个按钮”清楚得多。

## 10. 下一步建议

下一步最适合继续做的是：

1. 基于这两份导航规范，判断首页是否已经具备进入系统 UI 讨论的前提
2. 如果成立，再开始整理首页统一 UI 方案的讨论框架
3. 那时再讨论视觉强化、导航重构或拆页，才更稳
