# 正式写回状态面板持久化展示_v0.1

## 1. 目标

前一版已经有：

- `检查正式写回状态` 按钮

但它仍有一个真实使用问题：

- 结果只在顶部状态栏短暂出现
- 回到复盘面板后，看不到刚才到底检查出了什么

这次补的是：

- 把正式写回状态直接留在复盘面板中

## 2. 当前新增内容

前端状态层：

- `state.latestFormalWriteReadiness`

前端数据透传：

- `buildDashboardRenderPayload`

前端展示层：

- `renderBatchReviewDashboardResult`

## 3. 当前页面行为

现在点击 `检查正式写回状态` 后，结果不只会更新顶部状态提示，还会在复盘面板内新增一块：

- 正式写回状态
- 当前状态
- 状态码
- 目标批次
- 最近安全预览
- 状态摘要

这样你后续回看时，不需要再次点击按钮才能知道：

- 现在是否已进入正式写回
- 还卡在哪一层
- 最近对应的是哪份安全写回预览

## 4. 为什么这一步必要

当前项目不是一次性 demo，而是在走真实验证链路。

在这种链路里，状态如果只闪一次，很快就会丢上下文，尤其是当你：

- 中途切换到 Obsidian
- 回来继续看页面
- 或者后面要根据这一步决定是否进入正式写回

所以这次不是视觉优化，而是流程记忆能力的补强。

## 5. 这一步和 UI 优化的关系

它仍属于“流程收口”，不是首页大改版。

它的作用是先让验证链路更稳定、更可追溯，再决定什么时候进入真正的 UI 优化讨论。

## 6. 当前结论

可以把这次补充压缩成一句话：

**正式写回状态现在不再只是顶部短提示，而是会留在复盘面板里，方便后续持续推进。**
