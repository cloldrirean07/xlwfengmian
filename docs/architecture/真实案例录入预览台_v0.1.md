# 真实案例录入预览台 v0.1

## 1. 本轮新增了什么

这轮在现有 MVP 工作台里新增了一个前端入口：

- `真实案例录入预览台`

它不是最终的后台，也不是正式写入器，而是一个更接近真实产品操作的中间层：

- 允许先填写一条真实案例的最小录入信息
- 调用代码侧脚手架预览能力
- 直接看到会生成什么 `indexEntry` 和 `record`

## 2. 为什么先做“预览台”，不是直接做写入

当前阶段最需要先确认的是：

- 真实案例录入字段是否够用
- 默认路径、默认状态、优先级、维护标签是否合理
- 后续“真实写入”前，产品经理自己是否看得懂生成结果

如果现在直接把“写入”接进 UI，反而会让调试成本变高。

所以这一步故意先做：

- 前端录入
- API 预览
- 不落库

这更适合你当前还在边做边收口产品结构的阶段。

## 4. 当前输入字段范围

这版预览台支持的最小字段包括：

- `id`
- `platformCaseId`
- `title`
- `platform`
- `status`
- `keyCaseRerunPriority`
- `maintenanceTags`
- `obsidianCasePath`
- `sourceLink`
- `screenshotPath`

这些字段都是为了服务后续真实案例维护链，而不是一次就补齐全部业务内容。

也就是说，这个面板现在更像：

- 真实案例登记入口

而不是：

- 完整内容标注后台

## 5. 当前输出结果是什么

预览后，页面会显示两层结果：

### 5.1 index 层

告诉你：

- 会生成哪个 `fileName`
- 会往 `index.json` 追加什么 `indexEntry`

### 5.2 record 层

告诉你：

- 会生成哪条真实案例骨架
- 默认会补哪些待填写字段
- 当前优先级、标签、追踪路径会是什么

这能帮助你在真正写入之前先判断：

- 结构对不对
- 字段名是否合适
- 默认模板是否符合你的产品推进节奏

## 7. 当前产品意义

这一步把项目从：

- 只有脚本和 API

推进到了：

- 有一个最小可操作的产品入口

它的价值不在于界面多完整，而在于：

- 你可以开始从产品视角试用
- 你可以反复改录入字段和默认规则
- 后续正式做“真实案例写入页”时，不需要从零开始

## 8. 后续最顺的扩展方向

下一步最自然的是三层递进：

### 8.1 补正式写入动作

从“预览”走到：

- 确认后写入 `data/real-cases/index.json`
- 确认后写入 `data/real-cases/items/*.json`

### 8.2 增加内容层字段录入

在当前登记字段之上，再补：

- `contentTopic`
- `contentGoal`
- `assetDescription`
- `referencePreference`
- `assetNotes`

这样就不只是“登记”，而是更接近完整真实案例录入。

### 8.3 接入 Obsidian 草稿输出

后续可以让这一步同时生成：

- Obsidian 待补草稿
- 真实案例回填任务单

这样产品侧和代码侧会更紧密联动。
