# AI封面创意助手产品线重做架构计划 v0.1

## 1. 目标

本计划用于承接 `AI封面创意助手_MVP重做_主路径与工作台重做.md`，把项目从功能集合收束为稳定的产品主路径。

本轮架构目标不是推倒重写，而是在保留现有规则、案例、导出和测试资产的基础上，完成第一段可验证闭环：

```text
输入准备 -> 首轮方向判断 -> 工作区深化 -> 建议采纳反馈 -> 二轮修订承接
```

## 3. 维护模式判断

当前项目已有页面、状态、接口、规则、案例和测试体系，因此按 PI Engine 判定为：

**维护模式。**

本轮不新建 `apps/web-v2`，不切换 React + TypeScript + Vite，不引入新依赖。

## 4. 分层改造策略

### 4.1 `public/index.html`

职责：

1. 重排主工作台第一屏说明。
2. 用更产品化的文案表达主路径。
3. 明确工作区建议的采纳反馈入口。

边界：

1. 不新增路由。
2. 不删除案例复盘、导出和验证区。
3. 不改接口契约。

### 4.2 `public/app/createApp.js`

职责：

1. 控制工作区建议是否可被采纳。
2. 将已采纳建议作为二轮修订上下文。
3. 暂不采纳时不把建议带入二轮。

边界：

1. 不改服务端接口。
2. 不改规则引擎。
3. 不改变首轮方向卡生成逻辑。

### 4.3 `public/app/renderers.js`

职责：

1. 优化工作区建议结果表达。
2. 明确“已采纳 / 暂不采纳 / 尚未处理”三种状态。
3. 优化二轮承接提示。

边界：

1. 不新增复杂原因表单。
2. 不新增持久化字段。
3. 不改变结果数据结构。

### 4.4 `public/styles.css`

职责：

1. 补齐第一段闭环所需的轻量样式。
2. 保持现有视觉体系。

边界：

1. 不做整站视觉重写。
2. 不引入新字体或新资源。

## 5. 第一段实现范围

本轮只实现：

1. 主工作台首屏和流程说明的产品化收束。
2. 工作区建议采纳反馈的状态表达。
3. 已采纳建议进入二轮修订上下文。
4. 暂不采纳建议不进入二轮修订上下文。
5. 相关按钮禁用态和提示状态。

本轮不实现：

1. 新建 Web v2。
2. 完整视觉翻修。
3. 真实生图模型。
4. Obsidian 导出底层重写。
5. 案例复盘后台化。
