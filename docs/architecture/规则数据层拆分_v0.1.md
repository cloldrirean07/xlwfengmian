# 规则数据层拆分 v0.1

## 本次目的

把 `apps/web` 中原本写死在 JS 文件里的封面方向规则、方向派生信息、二轮反馈映射，拆成可维护的数据层。

## 本次调整

- 新增 `apps/web/data/rules/cover-effect-catalog.json`
  作为 5 类封面效果方向的单一配置源。
- 新增 `apps/web/data/rules/feedback-catalog.json`
  作为负向反馈映射、正向保留信号、变量标签映射的单一配置源。
- 新增 `src/infrastructure/rules/loadRuleCatalog.js`
  负责读取并缓存规则数据。
- `src/domain/effects/coverEffectCatalog.js`
  改为从规则 JSON 读取，不再手写对象。
- `src/domain/directions/directionCatalog.js`
  改为基于 `coverEffectCatalog` 派生，避免两份方向定义重复维护。
- `src/domain/refinement/feedbackMappings.js`
  改为从反馈 JSON 读取。
- `src/domain/refinement/mapFeedbackToAdjustment.js`
  改为消费映射层导出的变量字典。

## 这样做的价值

- 产品规则与业务逻辑解耦。
- 后续调 5 类方向、补反馈词、改标签时，不需要直接改推理逻辑代码。
- 更适合把 Obsidian 中的方法论逐步同步为结构化规则。
- 后续如果要做后台规则编辑、版本化规则、实验对比，更容易扩展。

## 当前边界

- 这次只处理“规则数据源”拆分，没有改动首轮/二轮生成算法本身。
- 规则仍然是本地静态 JSON，还没有接入管理后台或远程配置。

## 下一步建议

1. 给 `data/rules` 增加 schema 校验，避免手改 JSON 时出错。
2. 把案例标注库里的高频反馈词，逐步回填到 `feedback-catalog.json`。
3. 在前端工作台补一个“当前规则版本”展示，方便你复盘实验结果时知道命中的是哪套规则。
