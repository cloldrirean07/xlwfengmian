## 2. 模式判断

当前项目已有：

- 单页首页：`apps/web/public/index.html`
- 分组容器：`workspace-group-tools`、`workspace-group-cases`、`workspace-group-validation`
- 分组跳转逻辑：`data-workspace-group-link`、`openWorkspaceGroupTarget`
- 真实案例、平台案例、批次复盘与正式写回能力
- 覆盖主链路和复盘链路的测试基线

因此下一阶段仍按 PI Engine 判定为：

**维护模式。**

本阶段不新建 `apps/web-v2`，不引入正式路由，不替换框架，不改接口契约。

## 3. 本阶段目标

把当前首页从“所有能力纵向平铺”调整为“单页三视图”：

```text
创作主线 / 案例维护 / 复盘驾驶舱
```

本阶段要解决的问题是：

- 首页第一感仍像总控制台
- 用户主链路与内部维护链同权显示
- 案例维护和复盘驾驶舱抢占主链路注意力

本阶段不解决：

- 正式多路由拆页
- UI 全面重绘
- 真实模型接入
- Obsidian 导出底层重写
- 规则引擎重构

## 4. 三视图定义

### 4.1 创作主线

包含：

- Hero 与主路径说明
- 输入准备
- 素材预览
- 首轮方向结果
- 工作区深化
- 建议采纳反馈
- 二轮修订
- 二轮结果
- 主链路辅助验证工具的弱入口

默认状态：

- 页面首次进入时显示
- 作为产品主入口

不包含：

- 真实案例批量维护表单
- 平台案例复核台
- UI 就绪度与批次复盘看板

### 4.2 案例维护

包含：

- 案例沉淀工作台
- 单条真实案例录入与写入
- 批量真实案例录入与写入
- 批量回填工作单
- 批次试跑记录
- 真实案例概览
- 平台案例复核台

默认状态：

- 不在首屏展开
- 用户从二轮结果记录案例或顶部视图切换进入

不包含：

- 首轮方向生成主表单
- 工作区建议生成
- 二轮修订主输入

### 4.3 复盘驾驶舱

包含：

- UI 优化进入条件报告
- 跨批次摩擦点汇总
- 批次复盘看板
- 人工待补任务
- 安全写回预览
- 正式写回确认与后续任务

默认状态：

- 不在首屏展开
- 用户从“生成复盘看板”或顶部视图切换进入

不包含：

- 真实案例录入表单
- 首轮方向生成主表单

## 5. 现有结构映射

## 7. 交互规则

### 7.1 默认进入

首次打开页面：

- 显示创作主线
- 案例维护和复盘驾驶舱不平铺展示
- 主路径辅助工具保持折叠或弱显示

### 7.2 切换到案例维护

触发来源：

- 顶部“案例维护”
- 二轮结果里的记录案例入口
- `#real-case-form` 深链

系统行为：

- 显示案例维护视图
- 展开案例维护组
- 定位到目标锚点
- 保留已有案例读取逻辑

### 7.3 切换到复盘驾驶舱

触发来源：

- 顶部“复盘驾驶舱”
- Hero 或二轮结果里的复盘看板入口
- `#review-dashboard-section` 深链

系统行为：

- 显示复盘驾驶舱视图
- 展开验证与复盘组
- 定位到复盘看板
- 若入口语义是生成看板，则沿用 `generateBatchReviewDashboardPreview`

### 7.4 返回创作主线

触发来源：

- 顶部“创作主线”
- 用户重新点击主路径入口

系统行为：

- 显示创作主线视图
- 不清空首轮结果、工作区建议或二轮结果
- 不重置案例维护或复盘驾驶舱状态

## 8. 状态边界

必须保留：

- 已上传本地素材预览
- 首轮方向结果
- 当前选中方向
- 工作区建议及采纳状态
- 二轮修订结果
- 真实案例预览和批量案例预览
- 批次复盘看板与正式写回状态

不得新增：

- 新业务状态流转
- 新接口字段
- 自动导出或自动写回
- 自动规则修改

## 9. 风险与确认点

### 9.1 需要确认的产品决策

1. 三个视图名称是否确定为：
   - 创作主线
   - 案例维护
   - 复盘驾驶舱
2. 默认是否只显示创作主线。
3. 案例维护和复盘驾驶舱是否允许通过顶部视图切换进入。
4. 是否保留 Hero 中“沉淀案例资产”“进入规则复盘”的入口。

### 9.2 工程风险

- 锚点跳转和视图切换需要同时生效。
- 旧测试会依赖部分 HTML 字符串，需要同步更新断言。
- 隐藏非当前视图时，不能破坏内部表单状态。
- 移动端视图切换必须有足够点击区域。

## 10. 推荐执行顺序

1. 先改 `index.html`：增加三视图容器和入口，不删除旧内容。
2. 再改 `createApp.js`：增加视图切换状态，接入原有分组跳转。
3. 再改 `styles.css`：让非当前视图隐藏，视图入口清晰可见。
4. 最后改测试：覆盖视图入口、深链跳转和旧功能保留。
5. 执行 `node --test apps/web/tests/coverAssistantService.test.js`。
6. 验证 `http://127.0.0.1:3080/`、`/api/health`、`/app/createApp.js`。

## 11. 本轮不执行代码的原因

准拆页会影响首页信息架构、锚点跳转和用户主路径入口，属于多处结构性改动。

根据工程纪律，应先确认方案与边界，再进入实现。

本文件即为进入代码实现前的确认版本。
