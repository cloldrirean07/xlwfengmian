# 真实案例回填导出历史与覆盖策略 v0.1

## 1. 本次改动解决什么问题

上一轮已经支持：

- 确认导出到 Obsidian
- 导出后读回确认

但仍然缺两类信息：

1. 这次导出到底是“新建草稿”还是“覆盖旧稿”
2. 最近几次导出发生了什么

这次补的是：

**单案例真实案例回填导出时，同时返回覆盖判断与最近导出历史。**

## 2. 为什么需要这两层信息

如果页面只显示“导出成功”，用户仍然很难知道：

- 今天是不是已经导出过一次
- 这次是否覆盖了同一路径下的旧文件
- 最近几次导出的结果是否一致

而这些信息，后续不论 UI 是否重构，都会是维护工作台的基础数据。

## 3. 代码实现

### 3.1 导出前先读目标文件

更新：

- `src/application/exportRealCaseFillSheetToObsidian.js`

在正式写入前，先读取目标路径当前状态，得到：

- 是否已存在
- 旧首行
- 旧长度
- 旧内容是否已经与本次预期一致

然后生成：

- `overwrite.targetAlreadyExisted`
- `overwrite.actionLabel`
- `overwrite.previousHeading`
- `overwrite.previousLength`
- `overwrite.previousMatchedExpectedContent`

### 3.2 导出日志落到代码仓库

新增导出日志目录：

- `outputs/obsidian-export-logs/real-case-fill-sheets/<caseId>/`

每次导出都会生成一条 JSON 记录，包含：

- `exportId`
- `exportedAt`
- `targetPath`
- `overwrite`
- `readback`

这样后续如果要扩：

- 导出历史页
- 覆盖差异说明
- 失败重试追踪

都不需要从 UI 反推。

### 3.3 返回最近导出历史

当前导出结果会额外带上：

- `history.latestLogPath`
- `history.recentExports`

默认读取最近 `5` 条记录。

## 4. 前端表现

更新：

- `public/app/renderers.js`

导出结果卡现在会额外展示：

- 这次是“新建草稿”还是“覆盖现有草稿”
- 上次首行
- 上次长度
- 最近导出记录列表
- 本次导出日志路径

这让页面不再只是单次动作反馈，而开始具备轻量维护面板的雏形。

## 5. 当前边界

这次还没有做：

- 历史详情展开
- 覆盖前后 diff 对比
- 手动选择“强制新建副本”或“覆盖当前文件”

这些能力可以后续继续扩，但当前已经先把最重要的数据基础搭好。

## 6. 当前结论

现在这条链路已经形成：

1. 草稿预览
2. 确认导出
3. 写后读回确认
4. 覆盖判断
5. 最近导出历史

这说明真实案例维护链开始从“单次功能”逐步过渡到“可持续维护”的系统结构。
