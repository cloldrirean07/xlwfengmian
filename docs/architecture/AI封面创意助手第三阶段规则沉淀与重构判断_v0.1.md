# AI封面创意助手第三阶段规则沉淀与重构判断 v0.1

## 1. 背景

本文件承接 `AI封面创意助手产品线重做架构计划_v0.1.md` 的第三阶段：

```text
根据真实案例复盘结果调整规则说明，并判断是否需要 Web v2 或完整视觉重构。
```

当前项目已完成：

- 第一段闭环：输入准备、首轮方向判断、工作区建议、采纳反馈、二轮承接
- 第二阶段主路径收束：首轮结果层级重排、案例复盘入口回收到主路径

第三阶段继续采用 PI Engine 维护模式，不新建前端工程，不替换技术栈。

## 2. 当前判断

当前结论：

**暂不启动 Web v2，暂不启动完整视觉重构。**

原因：

1. 现有静态前端、服务端接口、规则引擎、案例复盘和导出体系仍能承接当前产品线复刻。
2. 当前更需要通过真实案例复盘结果确认问题是否稳定重复，而不是提前用新工程掩盖规则和流程问题。
3. 已有复盘看板能够提供 UI readiness、人工复盘趋势、跨批次重复摩擦点和后续动作，足够支撑下一轮局部优化判断。

## 3. 新增判断口径

本阶段在复盘看板中新增“规则沉淀与重构判断”：

- 规则沉淀判断
- Web v2 判断
- 视觉重构判断

判断依据全部来自既有数据：

| 数据来源 | 判断用途 |
| --- | --- |
| `summary.missingManualReviewCount` | 判断是否仍需先补人工复盘 |
| `summary.fullyCoveredBatchCount` | 判断人工复盘是否形成稳定样本 |
| `summary.repeatedCategories` | 判断摩擦点是否具备跨批次重复性 |
| `uiReadiness.readinessLevel` | 判断是否进入 UI 讨论 |
| `coverageTrend.status` | 判断人工复盘覆盖趋势是否稳定 |

## 4. 分支规则

### 4.1 先补人工复盘

触发条件：

- 仍有未写人工结论批次
- 或完整覆盖批次数为 0

判断：

- 规则沉淀：先补人工复盘字段，生成待补任务和安全写回预览
- Web v2：不启动
- 完整视觉重构：不启动

### 4.2 继续积累跨批次证据

触发条件：

- 人工复盘已有基础
- 但 UI readiness 未达到 ready
- 或重复摩擦点类别不足 2

判断：

- 规则沉淀：继续沉淀规则说明，等待重复信号变强
- Web v2：暂不启动
- 视觉优化：仅保留小范围文案与层级优化

### 4.3 进入主链路局部 UI 优化

触发条件：

- `uiReadiness.readinessLevel === "ready"`
- `coverageTrend.status === "stabilizing"`
- `summary.repeatedCategories >= 2`

判断：

- 规则沉淀：提炼重复摩擦点，形成规则修订任务
- Web v2：暂不新建，先验证主链路局部优化
- 视觉优化：允许进入主链路视觉与交互局部重排
