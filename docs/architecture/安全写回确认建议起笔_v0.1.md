# 安全写回确认建议起笔_v0.1

## 1. 目标

当前正式写回前的最后一层摩擦，不是代码能力缺失，而是：

- 安全写回预览里的 3 行人工确认字段完全空白
- 用户每次都要自己从零组织措辞

这次补的是：

- 给安全写回确认区增加“建议起笔”

## 2. 当前新增内容

涉及文件：

- `buildObsidianBatchReviewManualSafeWritePreviewRecord.js`
- `createBatchReviewManualSafeWritePreviewObsidianPreview.js`
- `exportBatchReviewManualSafeWritePreviewToObsidian.js`

具体表现：

- `哪几行你确认可以正式写回` 下新增建议起笔
- `哪几行仍需手改` 下新增建议起笔
- `是否已经可以进入正式写回` 下新增建议起笔

## 3. 当前规则

这次不是自动替用户完成确认，而是只给参考起笔。

也就是说：

- 原来的 3 个正式确认字段依然保持空白
- parser 不会把建议起笔误判成用户已确认
- 正式写回 gate 规则完全不变

## 4. 建议起笔怎么生成

当前建议内容来自本次 patch 本身：

1. 如果本次拟写回字段里已经有明确内容：
   - 系统会把这些字段标签组合成推荐确认项

2. 如果当前是 `suggested-draft`：
   - 会更明确提示“如果你确认建议稿可接受，再填写可以”

3. 如果当前是人工或混合 patch：
   - 会提示“如果你确认当前版本无须再改，再填写可以”

## 5. 为什么这一步有价值

这一步的价值不是更智能，而是更顺手。

因为当前项目已经进入：

- 可生成建议态草稿
- 可生成安全写回预览
- 可判断正式写回状态

最后真正卡住的反而是“确认字段要怎么写”。

所以这里补的是一层很轻的写作支架，帮助你更快推进，而不改变正式写回的安全边界。

## 6. 当前结论

可以把这次补充压缩成一句话：

**安全写回确认区现在不再是完全空白，而是会给出建议起笔，但不会自动替你完成正式确认。**
