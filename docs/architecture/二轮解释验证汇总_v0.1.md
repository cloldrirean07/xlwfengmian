# 二轮解释验证汇总 v0.1

## 本次目的

把单条“二轮解释验证记录”继续推进为可批量复核的汇总看板，帮助你判断先看哪条映射、哪类问题最集中。

## 本次实现

### 1. 新增汇总报告构建器

- `src/domain/refinement/buildRefinementExplanationSummaryReport.js`
- `src/domain/refinement/buildRefinementExplanationSummaryMarkdown.js`

当前会汇总：

- 负向映射 ID 分布
- 正向保留映射 ID 分布
- 兜底规则命中数
- 未命中正向保留信号数
- 接入工作区上下文数
- 每条 case-run 的解释明细

### 2. 新增 Obsidian 汇总包装器

- `src/domain/refinement/buildObsidianRefinementExplanationSummaryRecord.js`

### 3. 新增脚本

- `report:refinement-explanations`
- `export:obsidian-refinement-explanations`

导出目录：

- `05_验证与实验/二轮解释验证记录汇总/已生成记录`

## 为什么这一步重要

- 你终于可以批量看哪些映射最常出现
- 可以更快判断哪类记录值得优先人工复核
- 为后面的“误判样本 -> 规则修订任务”提供统计入口

## 当前边界

- 当前只汇总已运行的 case-runs
- 还没有接入“人工判为不合理”的显式复核结果

## 下一步建议

1. 给单条二轮解释验证记录增加“是否合理”结构化字段。
2. 在汇总里统计“被判为不合理最多的映射 ID”。
3. 自动把高风险映射推入误判样本与规则修订任务单。
