# 规则校验与命中解释接入 v0.1

## 本次目的

在已经完成规则数据层拆分的基础上，再补两层真实产品需要的工程能力：

- 规则文件的结构校验
- 前端首轮结果中的规则命中解释

## 本次实现

### 1. 规则 schema 校验

- 在 `src/infrastructure/rules/loadRuleCatalog.js` 中增加：
  - `validateCoverEffectCatalog`
  - `validateFeedbackCatalog`
  - `getRuleCatalogMeta`
- 当前会在读取本地 JSON 规则时，校验以下内容：
  - 顶层结构是否合法
  - 5 类方向是否都有必填字段
  - 模板数组、提示数组、图片策略映射是否完整
  - 反馈映射和变量标签映射是否完整

### 2. 规则版本元信息

- 基于当前两份规则 JSON 内容计算 `sha1` 截断版本号
- 在分析结果中返回：
  - `source`
  - `version`
  - `effectCount`
  - `negativeMappingCount`
  - `positiveMappingCount`

## 3. 前端命中解释接入

- `createAnalysisSession` 现在会返回 `ruleMeta`
- 首轮分析面板新增：
  - 当前命中主方向
  - 规则版本
  - 内容/素材/平台匹配分
  - 规则来源
  - 当前命中的实际信号

## 这样做的价值

- 你后续手动改规则库时，更不容易因为字段漏写把系统弄坏
- 每次实验都能知道当前命中的是哪套规则，而不是“感觉上差不多”
- 用户或面试官看到结果页时，也能理解系统并不是随便出建议，而是有规则判断依据

## 当前边界

- 目前是代码内手写校验，不是独立 JSON Schema 文件
- 规则版本只反映本地 JSON 内容，不含案例库或 prompt 版本

## 下一步建议

1. 把规则校验拆成独立 schema 模块，便于后续后台化。
2. 在二轮结果里也展示“这次命中了哪条反馈映射”。
3. 增加规则实验记录，把版本号和实验结果一并写入 Obsidian 验证文档。
