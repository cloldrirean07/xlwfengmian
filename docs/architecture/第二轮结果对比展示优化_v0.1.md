# 第二轮结果对比展示优化_v0.1

## 1. 这轮为什么继续优化第二轮结果区

在前两轮 UI 优化之后，我们已经先后把：

- 首屏入口
- 第一轮输入工作台
- 第一轮方向卡比较区

做到了更像真实产品的状态。

接下来最关键的一步，是把第二轮优化结果做得更适合“复盘、展示和继续改”。

因为用户进入第二轮后，最想确认的不是“系统又生成了一堆字段”，而是：

1. 我原来那张卡是什么样
2. 这轮到底改了哪里
3. 改完以后为什么更贴我的反馈
4. 如果还要继续改，下一轮该怎么说

如果第二轮结果区不能回答这 4 个问题，它就仍然更像“结构化返回结果”，而不是“真实可继续推进的产品界面”。

## 2. 原来的问题

原来的第二轮结果区已经有：

- 第二轮标题
- 保留变量
- 修改变量
- 改动动作
- 新的封面大字
- 新的标题建议
- 新的配图方向
- 解释线索

但它仍有两个明显问题。

### 2.1 缺少改前参照

原来的结果区只强调“改后”，但没有把“改前”放在旁边。

这会导致用户需要自己回忆：

- 第一轮的封面大字是什么
- 原来的配图方向是什么
- 原来的构图建议是什么

这对展示、复盘和连续优化都不友好。

### 2.2 “这轮到底改了什么”不够显性

虽然结构里有：

- preservedVariable
- changedVariable
- changedAction
- nextRoundGoal

但它们被分散在数据块里，没有形成一个明确的“这轮实际改动摘要”。

所以用户知道有变化，但不容易一眼读懂变化的主线。

## 3. 这轮设计原则

这轮沿用上一轮的思路：

- 不新增复杂流程
- 不改核心算法
- 只强化最关键的认知层

本轮设计原则是：

1. 先给出改前 / 改后双列对比
2. 再给出本轮修改摘要
3. 最后给出下一轮怎么继续提反馈

这样既能支撑当前产品验证，也能让后续作品集展示和真实 PM 复盘更自然。

## 4. 本轮具体改动

## 4.1 为 refine session 返回 sourceCard

为了让结果区能直接渲染改前参照，本轮在：

- `apps/web/src/application/createRefinementSession.js`

里增加了：

- `sourceCard: selectedCard`

这样前端结果区不需要依赖外部状态推断，就能直接拿到首轮被选中的卡片内容。

## 4.2 第二轮结果区新增“改前 / 改后”双列结构

在 `renderRefinementResult` 中，结果区现在拆成两块：

### 改前方向

展示：

- 原始方向名称
- 原始封面大字
- 原始首条标题建议
- 原始配图方向
- 原始构图建议
- 原始点击逻辑
- 原始风险提醒

### 改后方向

展示：

- 新方向标题
- 新封面大字
- 新首条标题建议
- 新配图方向
- 新构图建议
- 新点击逻辑
- 沿用风险提醒

这让第二轮最核心的问题“改前和改后差在哪里”可以直接在同一屏里回答。

## 4.3 增加第二轮关键摘要区

除了双列对比，本轮也把这轮最核心的 4 个控制项提成单独一行：

- 保留内容
- 保留强项变量
- 重点修改变量
- 改单动作

这一层让用户先抓住当前二轮的主修改逻辑，而不是一开始掉进细节里。

## 4.4 增加“这轮实际改了什么”

本轮新增了一块更接近 PM / 设计复盘语言的总结区，直接把：

- 保留变量
- 重点修改变量
- 改动动作
- 下一轮目标

整理成清晰的清单。

这样做的好处是，用户不需要自己把字段重新翻译成人话。

## 4.5 增加“如果继续提反馈，最值得先说什么”

为了让第三轮或后续迭代更顺，本轮新增一块提示区，明确建议：

- 先说保留什么
- 再说一个最不满意的点
- 一次只改一个主变量

这不是新算法，而是把产品使用方法直接嵌进界面。

## 5. 样式与结构调整

主要新增或强化了这些结构：

- `refinement-kicker-grid`
- `refinement-compare-grid`
- `refinement-compare-card`
- `refinement-compare-card-accent`
- `refinement-copy-box`
- `refinement-copy-box-accent`
- `refinement-mini-grid`

这些结构的目的不是做“更花的设计”，而是让第二轮更像一个真正的对比与修订界面。

## 6. 涉及文件

- `apps/web/src/application/createRefinementSession.js`
- `apps/web/public/app/renderers.js`
- `apps/web/public/styles.css`

没有变动：

- refinement 规则本身
- 第二轮卡片生成逻辑
- API 路由
- Obsidian 导出链路

## 7. 当前效果

这一轮之后，第二轮结果区从“结构化返回”升级成了“可对比的修订结果”。

最直接的提升在于：

- 改前改后能直接对照
- 本轮修改主线更清楚
- 反馈解释链更完整
- 后续继续提反馈时更不容易失焦
- 结果更适合作品集展示与真实复盘

## 8. 下一步建议

如果继续做 UI，下一步更值得做的是：

1. 优化工作区建议区与第二轮结果区之间的视觉连续性
2. 为第二轮结果区增加更轻量的步骤提示或进度感
3. 视情况决定是否把第二轮结果支持导出成更结构化的演示块

当前还不建议的是：

- 把第二轮区做成复杂 tabs
- 引入大型动效
- 提前做全站统一设计系统重构
