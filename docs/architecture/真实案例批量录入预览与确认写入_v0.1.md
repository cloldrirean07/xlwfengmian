# 真实案例批量录入预览与确认写入 v0.1

## 本次目标

在已有“单条真实案例录入预览/确认写入”能力基础上，补齐“批量录入”链路，让产品可以一次准备并写入 2 到 3 条真实案例，用于更高效地沉淀真实案例库。

## 为什么现在做

当前项目已经有：

- 单条真实案例录入预览
- 单条真实案例确认写入
- 真实案例列表重读
- 从真实案例到回填/同步/导出链路的联动

但仍然缺少一条更符合实际运营节奏的路径：

- 一次整理一小批案例
- 先统一检查结构
- 再统一写入

这比现在就进入 UI 重设计更关键，因为它先补的是产品工作流能力，而不是视觉包装。

## 范围

本次纳入：

- 后端批量真实案例确认写入应用层
- 批量写入基础设施层
- 前端批量 JSON 输入区
- 批量预览结果渲染
- 批量确认写入结果渲染
- 写入后刷新真实案例列表
- 自动化测试补齐

本次不纳入：

- 批量录入的表单化编辑器
- 拖拽上传素材
- 批量字段可视化校验器
- UI 视觉层系统优化

## 代码结构

### 应用层

- `src/application/commitRealCaseBatchScaffold.js`
  - 负责读取当前 index
  - 调用 `prepareRealCaseBatchScaffold`
  - 调用批量保存器
  - 提交后重置案例缓存

### 基础设施层

- `src/infrastructure/cases/savePreparedRealCaseBatchScaffold.js`
  - 负责批量落盘真实案例 JSON
  - 在写入前检查目标文件是否已存在
  - 最后统一刷新 `index.json`

### Server API

- `POST /api/real-case-batch-scaffold-preview`
- `POST /api/real-case-batch-scaffold-commit`

### 前端

- `public/index.html`
  - 新增批量录入与批量预览区域
- `public/app/api.js`
  - 新增批量预览/批量确认写入 API
- `public/app/createApp.js`
  - 新增批量模板装载
  - 新增 JSON 解析与错误提示
  - 新增批量预览/确认写入交互
- `public/app/renderers.js`
  - 新增批量预览结果渲染
  - 新增批量确认写入结果渲染
- `public/app/state.js`
  - 新增批量预览与批量提交状态

## 交互流程

1. 用户点击“加载批量模板”
2. 页面填入 2 条默认真实案例 JSON 模板
3. 用户按当前整理目标修改批次内容
4. 点击“预览批量骨架”
5. 页面展示：
   - 本次新增数量
   - 写入后索引数量
   - 待创建案例列表
   - 第一条案例 record 预览
   - 索引尾部预览
6. 点击“确认批量写入真实案例”
7. 后端批量落盘并刷新 index
8. 前端重读真实案例列表，进入后续维护链

## 当前价值

这一步的价值不是让 UI 更好看，而是让“真实案例库沉淀”从单条手工操作，变成可持续的工作台动作：

- 更接近真实产品运营节奏
- 更适合你后续逐批整理案例
- 为后面做批量校验、批量回填、批量同步打基础

## 下一步建议

下一步优先级建议：

1. 继续让这条批量录入链路接真实样例跑 2 到 3 次
2. 补一个“批量字段校验摘要”
3. 等真实案例输入结构稳定后，再讨论 UI 统一优化

## UI 判断

当前仍然不建议做系统级 UI 大改。更合适的时点是：

- 批量录入
- 回填工作单
- 平台同步预览

这三条主链路都至少跑过 2 到 3 个真实案例后，再统一看信息结构和视觉层优化。
