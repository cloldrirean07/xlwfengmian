# 建议态复盘写回前端续推入口_v0.1

## 1. 目标

这次补的是复盘链路里的一个前后端对齐问题：

- 后端已经支持在“还没手填任务卡”时，先走建议态写回草稿与安全写回预览
- 前端之前却把后续按钮只挂在“人工已填写”之后

这会让真实流程停在任务卡导出，和代码实际能力不一致。

## 2. 当前修正内容

前端展示层：

- `renderBatchReviewDashboardResult`

新增行为：

- 只要当前批次已经生成待补任务，就允许继续导出：
  - `导出建议态写回草稿`
  - `导出建议态安全写回预览`
  - `检查正式写回状态`

保留的门控：

- `执行正式写回（需先确认安全预览）` 仍然只在 `partial-ready / ready-to-backfill` 时出现

## 3. 为什么这样更合理

当前复盘链路已经存在两种推进方式：

1. 人工填写后再继续
2. 先看系统建议态草稿，再决定是否值得人工继续改

前一版页面只暴露了第一种，所以会制造一种假象：

- 像是系统“只能先导出任务卡”
- 实际上底层已经能继续推到写回草稿和安全写回预览

所以这次修的是流程表达，不是新增底层能力。

## 4. 当前页面规则

现在 follow-up 区的规则变成：

1. 只要有待补任务：
   - 可以导出任务卡
   - 可以直接导出建议态写回草稿
   - 可以直接导出建议态安全写回预览
   - 可以检查正式写回状态

2. 如果已经有人填写了任务卡字段：
   - 继续开放回流预览

3. 只有达到更高门槛时：
   - 才开放正式写回按钮

## 5. 这一步和 UI 优化的关系

这仍然不是“开始做首页大改版”。

它属于流程 UI 的收口：

- 先让产品链路表达和实际能力一致
- 先减少你在验证阶段的误判
- 再等真实证据更完整后，进入真正的 UI 优化讨论

## 6. 当前结论

可以把这次补充压缩成一句话：

**页面现在已经允许你在未手填任务卡时，直接继续跑建议态写回链路，不会再被前端门控卡住。**
