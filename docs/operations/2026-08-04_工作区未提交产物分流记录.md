# 工作区未提交产物分流记录

## 1. 本轮目的

对上一轮主链路复跑后遗留在 Git 工作区的变更进行分流，判断哪些属于产品有效产物，哪些属于运行缓存或导出日志，避免后续提交范围失焦。

## 2. 当前分流结论

### 建议保留并进入下一次提交

- `apps/web/src/application/runPlatformCaseBatchReview.js`
  - 平台案例批量复核遇到缺失平台笔记时不再整体失败，而是生成一条“待回填”的结构化行。
  - 作用：真实案例库继续扩展后，缺笔记的案例可以进入维护看板，不会阻断整个批量复核。
- `apps/web/data/operations/key-case-rerun-plan.generated.json`
  - `real-002`、`real-003` 进入关键样例复跑计划。
  - 作用：把真实案例纳入规则迭代样例池。
- `apps/web/outputs/case-runs/real-002/*`、`apps/web/outputs/case-runs/real-003/*`
  - 记录真实案例复跑结果，体现人工优选标题进入标题候选首位。
  - 作用：作为真实样例闭环的可回看证据。
- `apps/web/outputs/reports/real-case-readiness/*`
  - 记录 `real-002`、`real-003` 已达到手动验证条件。
  - 作用：作为下一轮产品迭代入口判断。
- `apps/web/outputs/reports/real-case-maintenance-board/*`
  - 记录真实案例维护优先级从 1 条扩展到 3 条。
  - 作用：帮助判断后续先维护哪批真实案例。
- `apps/web/outputs/reports/key-case-rerun/*`
  - 记录关键样例复跑计划扩展后的结果。
  - 作用：保留规则复跑闭环证据。
- `apps/web/outputs/batch-review-manual-formal-write/formal-write-follow-up-plan/*`
  - 记录正式写回后续计划已覆盖 `real-002 / real-003`。
  - 作用：衔接写回后复跑、导出和规则修订任务。
- `apps/web/tests/coverAssistantService.test.js`
  - 增加平台笔记缺失时的批量复核断言。
  - 作用：防止真实案例扩展后批量看板因单条缺失而崩溃。

### 建议不进入仓库

- `apps/web/outputs/obsidian-export-logs/**`
  - 这些文件是每次导出到 Obsidian 时生成的时间戳日志。
  - 单条日志有追溯价值，但数量增长很快，且大多可由稳定报告和操作记录替代。
  - 本轮已将该目录加入 `.gitignore`，后续不再默认出现在 Git 未跟踪清单中。

### 暂不建议提交，需另轮处理

- `apps/web/outputs/batch-fill-sheets/real-601/*`
- `apps/web/outputs/batch-fill-sheets/real-701_to_real-702/*`
- `apps/web/outputs/batch-run-records/real-904/*`

这些文件主要是日期、临时 Obsidian 目标路径或待补案例状态更新，不直接服务当前 `real-002 / real-003` 主链路。建议后续按“批量真实案例维护”主题单独判断，不混入本次产品主链路提交。
