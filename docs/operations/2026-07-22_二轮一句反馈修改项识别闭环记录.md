# 二轮一句反馈修改项识别闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD：`docs/prd/AI封面创意助手_MVP重做_主路径与工作台重做.md`

## 2. 对齐条目

- PRD 4.4：用户输入一句反馈后，系统识别反馈是否有效，并生成二轮结果。
- PRD 4.6：系统应识别用户反馈中的保留项和修改项，并在结果中展示修改依据。

## 3. 本轮实现映射

| Spec / PRD 条目 | 实现位置 | 实现结果 |
| --- | --- | --- |
| 一句反馈识别修改项 | `src/domain/refinement/mapFeedbackToAdjustment.js` | 从反馈文本中识别转折或动作词后的修改请求，并写入 `changeRequest`。 |
| 修改请求来源可解释 | `src/domain/refinement/mapFeedbackToAdjustment.js` | 新增 `changeRequestSource`，当前用于标记修改请求来自反馈文本。 |
| 修改依据展示修改项 | `src/domain/refinement/buildFeedbackMappingExplanation.js` | 解释行补充“修改请求识别为”。 |
| 二轮结果区展示修改请求 | `public/app/renderers.js` | 二轮结果摘要新增“识别到的修改请求”。 |
| 回归测试 | `tests/coverAssistantService.test.js` | 扩展一句反馈测试，验证“降低营销感”被识别为修改项。 |

## 4. 边界

- 未新增二轮表单字段。
- 未改变反馈映射规则目录。
- 未改变工作区采纳上下文接入方式。
- 未改变二轮接口请求结构。

## 5. 验收项

- 反馈“保留误区冲突，但降低营销感”应识别保留项为“误区冲突”。
- 同一句反馈应识别修改项为“降低营销感”。
- 二轮修改依据应展示修改请求识别结果。
- 二轮结果摘要应能直接看到识别到的修改请求。
