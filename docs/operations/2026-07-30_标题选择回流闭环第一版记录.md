# 标题选择回流闭环第一版记录

## 本次目标

[事实] 本轮目标是在首轮方向卡中接入“标题选择回流”第一版，让标题候选从“可查看”推进到“可选择并生成 copyReview 草稿”。

[推断] 这一步的产品意义是：标题风格库不再只是静态推荐列表，而是开始承接人工判断，后续可以把人工优选标题写回真实案例并用于关键样例复跑。

## 实现范围

[事实] 更新 `apps/web/public/app/state.js`：

- 新增 `latestTitleSelection`，记录当前人工优选标题草稿。

[事实] 更新 `apps/web/public/app/createApp.js`：

- 新增 `buildTitleSelectionDraft`，将标题候选转成 `copyReviewDraft`。
- 点击标题候选的“设为优选”后，同步选中对应方向卡。
- 若切换到其他方向卡，清空不匹配的标题选择草稿。
- 若选择标题导致方向切换，既有二轮结果和工作区建议会按原有规则失效。

[事实] 更新 `apps/web/public/app/renderers.js`：

- 标题候选新增“设为优选 / 已设为优选”操作。
- 当前选中的标题会展示“人工优选草稿”。
- 草稿包含 `preferredTitle` 和标题选择理由。

[事实] 更新 `apps/web/public/styles.css`：

- 新增标题选择按钮、选中态和人工优选草稿样式。

[事实] 更新 `apps/web/tests/coverAssistantService.test.js`：

- 增加标题选择草稿生成测试。
- 增加前端标题选择草稿渲染测试。

## 当前边界

[事实] 第一版只生成前端草稿，不直接写回 `real-002` 或 `real-003` 文件。

[推断] 这样更稳：先让人工选择动作可见、可验证，再进入下一段受控写回 API，避免点击一次就不可逆地覆盖真实案例。
