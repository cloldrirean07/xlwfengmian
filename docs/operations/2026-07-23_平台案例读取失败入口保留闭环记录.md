# 平台案例读取失败入口保留闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD 信息架构：`docs/prd/AI封面创意助手_MVP重做_PRD_信息架构确认_v0.1.md`

## 2. 对齐条目

- PRD：真实案例复盘支持平台案例信息同步校验。
- PRD：案例读取失败时展示“案例读取失败，请重试”。
- PRD：案例读取失败后页面保留入口，支持继续重试。

## 3. 当前缺口

平台案例单条复盘、批量复盘、同步预览三个入口在读取失败时只展示失败提示，缺少回到对应结果区的承接。用户能够看到失败状态，但不一定能立即定位到下一次重试和结果查看位置。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 失败文案 | `apps/web/public/app/createApp.js` | 保持 PRD 指定的“案例读取失败，请重试” |
| 可恢复定位 | `apps/web/public/app/createApp.js` | 失败后滚动回对应平台案例结果区 |
| 入口覆盖 | `apps/web/public/app/createApp.js` | 覆盖单条复盘、批量复盘、同步预览三个入口 |
| 回归测试 | `apps/web/tests/coverAssistantService.test.js` | 增加三个入口失败后调用可恢复定位的断言 |

## 5. 边界

- 未改变平台案例读取、批量复盘、同步预览的数据协议
- 未改变失败文案
- 未新增自动重试能力
- 未改变真实案例库筛选和维护动作

## 6. 验收项

- 三个平台案例入口失败时均保留 PRD 失败文案
- 三个平台案例入口失败时均定位回对应结果区
- 回归测试能覆盖失败文案和恢复定位
