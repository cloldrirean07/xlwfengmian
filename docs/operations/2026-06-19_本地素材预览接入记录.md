# 2026-06-19 本地素材预览接入记录

## 本次目标

把 `apps/web` 的首轮输入从“只有文本描述”推进到“支持本地参考图 / 截图预览”的状态，但仍然保持第一版复杂度可控。

## 本次完成

### 1. 输入层新增图片上传占位

当前首轮输入区已经新增：

- 图片选择输入
- 本地预览区
- 清除预览按钮

这让用户现在可以先带着自己的截图或参考图进入流程。

### 2. 前端新增素材预览模块

本次新建：

- `public/app/assetPreview.js`

负责：

- 校验是否为图片文件
- 生成本地 object URL
- 读取图片尺寸
- 返回预览元信息
- 清理 object URL

这样图片预览能力没有塞进主流程文件里，边界是清楚的。

### 3. 前端状态层新增素材预览状态

当前状态里新增：

- `assetPreview`

用于承载当前本地图片的：

- 文件名
- 类型
- 大小
- 尺寸
- object URL

### 4. 页面渲染层新增预览展示

现在页面会根据状态动态展示：

- 空态提示
- 预览图
- 图片基础信息
- 清除按钮显隐

也就是说，这不是一个“只加了 input 的半成品”，而是完整把本地素材上下文挂进了工作台。

## 这次改动后的直接收益

### 1. 首轮输入更像真实产品

现在用户不只是“写内容”，还可以带着素材进入流程，这更接近短视频创作者的真实工作方式。

### 2. 后续图片能力有落点了

以后继续加：

- 图片理解
- OCR
- 候选图推荐
- 生图或改图

都可以围绕当前这块继续长，不用重做页面。

### 3. 当前边界依旧清楚

这轮没有把复杂后端图片链路一起做掉，所以：

- 验证目标单一
- 风险可控
- 代码结构仍然干净

## 下一步建议

最优先继续加的是：

1. 上传图片后自动推断一个 `素材类型建议`
2. 图片旁边补一个 `保留区域 / 待替换区域` 的简单标注输入
3. 在 `/api/analyze` 里增加图片上下文字段占位，但先不做真正图像理解
