# 案例复盘承接入口展开闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD：`docs/prd/AI封面创意助手_MVP重做_主路径与工作台重做.md`

## 2. 对齐条目

- PRD 5.3：用户可从主工作台的案例复盘入口进入，或从二轮结果后的记录入口进入。
- PRD 5.4：进入案例复盘后读取案例状态，并继续生成复盘材料或写回确认。
- Requirement Spec：二轮结果后的记录入口需要承接到案例复盘与规则沉淀区。

## 3. 当前缺口

案例复盘承接区已有“查看案例维护”和“生成复盘看板”入口；二轮结果区也已有“进入案例复盘记录”动作。但复盘看板所在验证复盘组默认折叠，普通锚点跳转后可能只到达折叠区块，缺少可见的下一步动作。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 案例维护入口 | `public/index.html` | 增加 `data-workspace-group-link="cases"` |
| 复盘看板入口 | `public/index.html` | 增加 `data-workspace-group-link="validation"` |
| 目标组展开与滚动 | `public/app/createApp.js` | 新增 `openWorkspaceGroupTarget` |
| 二轮结果进入案例复盘 | `public/app/createApp.js` | 点击后先展开案例组，再滚动到案例维护入口 |
| 回归测试 | `tests/coverAssistantService.test.js` | 增加链接标记和事件分支静态断言 |

## 5. 边界

- 未新增案例字段。
- 未改变案例读取、导出、写回接口。
- 未改变复盘看板生成逻辑。
- 未改变默认展开策略：案例组默认展开，验证复盘组默认折叠。

## 6. 验收项

- 从二轮结果点击“进入案例复盘记录”后，案例沉淀工作台保持展开并滚动到案例维护入口。
- 从案例复盘承接区点击“查看案例维护”后，目标案例组可见。
- 从案例复盘承接区点击“生成复盘看板”后，验证复盘组先展开，再滚动到复盘看板入口。
