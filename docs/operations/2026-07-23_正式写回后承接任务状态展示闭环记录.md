# 正式写回后承接任务状态展示闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD 信息架构：`docs/prd/AI封面创意助手_MVP重做_PRD_信息架构确认_v0.1.md`

## 2. 对齐条目

- Requirement Spec：案例复盘成功后形成规则修订或复跑任务。
- Requirement Spec：批次复盘看板需要包含写回状态和下一步建议。
- Requirement Spec：页面主状态包含正式写回待确认。

## 3. 当前缺口

正式写回后的承接任务数据已经包含 `status` 字段，但任务面板只展示任务类型、执行方式、依据和下一步。用户无法直接判断规则修订任务单与关键样例复跑当前是否仍处于待处理状态。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 承接任务状态 | `apps/web/public/app/renderers.js` | 展示待处理、已完成、需复查或待确认 |
| 任务属性组合 | `apps/web/public/app/renderers.js` | 在同一行展示状态、类型和执行方式 |
| 回归测试 | `apps/web/tests/coverAssistantService.test.js` | 增加待处理状态渲染断言 |

## 5. 边界

- 未新增承接任务状态流转
- 未改变任务生成规则
- 未新增自动规则修订或自动复跑能力
- 未改变正式写回执行和回滚逻辑

## 6. 验收项

- 正式写回后承接任务展示当前状态
- 待处理状态能被明确识别
- 承接任务仍保持人工确认边界
