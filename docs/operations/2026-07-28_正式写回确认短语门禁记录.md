# 正式写回确认短语门禁记录

- 时间：2026-07-28 20:12
- 执行模式：PI Engine 维护模式
- 本轮目标：为正式写回增加独立确认短语门禁，确保正式写回与安全预览确认块写入保持两次分离确认。

## 1. 背景

- 安全预览确认块写入入口已经具备短语确认、按钮解锁和写入后门禁复查。
- 正式写回动作此前依赖 readiness 门禁，但服务端导出函数和前端请求没有独立确认短语。
- PRD 中正式写回前必须有确认状态，本轮将该边界补强为可验证的二次确认。

## 2. 修正

- 更新 `src/application/exportBatchReviewManualFormalWriteToObsidian.js`
  - 新增 `BATCH_REVIEW_MANUAL_FORMAL_WRITE_PHRASE`。
  - 正式写回执行前必须传入 `确认执行正式写回`。
  - 短语不匹配时直接拒绝，不进入 readiness 检查与目标记录写入。
- 更新 `src/server/server.js`
  - 正式写回接口读取请求体，并将确认短语传入应用层。
- 更新 `public/app/api.js`
  - `exportBatchReviewManualFormalWrite` 支持传入确认短语。
- 更新 `public/app/renderers.js`
  - 抽出正式写回受控操作区。
  - 在写回门禁总览和复盘看板正式写回入口中统一展示短语输入、填入短语和执行按钮。
  - 执行按钮默认锁定，等待确认短语匹配后解锁。
- 更新 `public/app/createApp.js`
  - 新增正式写回短语填入、短语匹配解锁和前端拦截。
  - 正式写回请求会携带确认短语。
- 更新 `public/styles.css`
  - 增加正式写回确认区三列布局。
- 更新 `tests/coverAssistantService.test.js`
  - 增加正式写回确认短语缺失拦截测试。
  - 更新正式写回成功与回滚测试，使其显式传入确认短语。
  - 增加前端确认区、短语填入、按钮解锁、API payload 和渲染断言。

## 3. 安全边界

- 本轮只增加正式写回确认门禁。
- 本轮未自动执行安全预览确认块写入。
- 本轮未写入 Obsidian。
- 本轮未执行正式写回。

## 4. 下一步

- 安全预览确认块写入完成并复查门禁通过后，正式写回区会开放。
- 点击“填入短语”后，正式写回按钮解锁。
- 点击“执行正式写回”时，前端与服务端都会校验确认短语。
