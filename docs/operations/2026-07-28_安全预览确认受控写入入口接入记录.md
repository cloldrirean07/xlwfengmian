# 安全预览确认受控写入入口接入记录

- 时间：2026-07-28 19:21
- 执行模式：PI Engine 维护模式
- 本轮目标：将安全预览确认块的受控写入壳接入页面流程，形成可操作、可校验、可回显的入口。

## 1. 背景

- 安全预览确认受控写入壳已具备服务端能力。
- 页面此前只展示写入预检，缺少明确的确认短语输入和执行入口。
- 正式写回仍需保持独立门禁，不能因为接入确认块入口而自动放行。

## 2. 修正

- 更新 `public/app/api.js`
  - 增加 `applyBatchReviewManualConfirmationSafePreviewWrite`，调用受控写入接口。
- 更新 `public/app/state.js`
  - 增加 `latestManualConfirmationSafePreviewWriteApply`，保存确认块写入结果。
- 更新 `public/app/createApp.js`
  - 写回门禁总览纳入确认块写入结果。
  - 新增 `apply-manual-confirmation-safe-preview-write` 动作分支。
  - 执行前校验确认短语，写入成功后刷新正式写回门禁证据。
- 更新 `public/app/renderers.js`
  - 在安全预览确认写入预检卡片中新增受控写入入口。
  - 展示确认短语输入、写入确认块按钮和读回状态。
- 更新 `public/styles.css`
  - 增加受控写入入口与输入区样式。
- 更新 `tests/coverAssistantService.test.js`
  - 增加接口函数、状态字段、动作分支、渲染入口和样式断言。

## 3. 安全边界

- 本轮未自动执行确认块写入。
- 入口必须填写确认短语 `确认写入安全预览确认块`。
- 服务端仍会二次校验确认短语、重新执行预检并读回校验。
- 正式写回按钮仍受原正式写回门禁控制。

## 4. 下一步

- 页面输入确认短语并执行确认块写入。
- 写入成功后重新检查正式写回门禁。
- 门禁进入 `ready-to-formal-write` 后，再单独确认是否执行正式写回。
