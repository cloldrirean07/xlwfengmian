# 安全写回人工确认建议稿生成记录

## 1. 执行背景

[事实] 本轮继续按“AI项目资料”的 PI Engine 维护模式推进真实案例数据闭环。

[事实] 上一轮阶段性收束审查已经确认，当前最有价值的下一步不是继续改 UI，而是推进：

```text
安全预览 -> 人工确认 -> readiness 复查 -> 受控正式写回
```

[事实] 本轮没有直接写入 Obsidian 安全写回预览，也没有执行正式写回。

[事实] 当前安全写回预览目标批次为 `real-002_to_real-003`。

[事实] 当前 readiness 卡在 `awaiting-safe-write-confirmation`。

[事实] 当前卡点是：

- `manualReviewConclusion` 为空。
- `hasManualConfirmation` 为 false。
- `canProceedToFormalWrite` 为 false。

[事实] 代码侧解析规则位于 `apps/web/src/domain/review/parseBatchReviewManualSafeWritePreviewNote.js`。

[事实] 门禁放行需要：

- 人工复盘结论非空且不超过 500 字。
- `哪几行仍需手改` 为空。
- `是否已经可以进入正式写回` 填写“可以”“是”“可进入”“ready”或“yes”等明确许可。

## 3. 本轮生成文件

[事实] 已新增：

`apps/web/outputs/batch-review-manual-safe-write-preview/manual-confirmation-draft.md`

[事实] 该文件包含两个版本：

- 建议填写块：用于人工确认后打开正式写回门禁。
- 保守填写块：用于留下人工判断，但暂不打开正式写回门禁。

## 4. Requirement Spec 映射

| 要求 | 本轮处理 |
| --- | --- |
| 正式写回前必须有写回预览和确认状态 | 只生成确认草稿，不越过人工确认 |
| 未确认写回时不修改目标记录 | 未写入目标批次记录，未执行正式写回 |
| 导出或写回失败时原案例状态保持不变 | 本轮无写回动作，目标记录保持原状态 |
| 批次复盘结果可生成规则修订任务，但不自动修改规则引擎 | 本轮未触发规则修改 |

## 5. 下一步

[需确认] 若采用“建议填写块”，需要人工确认这批拟写回字段可以正式写入。

[需确认] 若采用“保守填写块”，readiness 会继续保持未放行，适合先审措辞。

[事实] 无论采用哪种版本，写入 Obsidian 安全预览后都应重新检查：

```bash
curl -s http://127.0.0.1:3198/api/batch-review-manual-formal-write-readiness
```

[事实] 如果 readiness 进入 `ready-to-formal-write`，仍需再次确认是否执行正式写回。
