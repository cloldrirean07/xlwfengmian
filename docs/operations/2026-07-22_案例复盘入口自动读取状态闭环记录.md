# 案例复盘入口自动读取状态闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD：`docs/prd/AI封面创意助手_MVP重做_主路径与工作台重做.md`

## 2. 对齐条目

- PRD 5.4：进入案例复盘后读取案例状态。
- PRD 5.6：案例复盘默认优先展示待补字段较多或近期待处理的案例。
- PRD 5.8：案例读取失败时展示“案例读取失败，请重试”，页面保留入口。

## 3. 当前缺口

案例沉淀工作台已有真实案例列表刷新按钮，也已有待处理优先排序能力。但从二轮结果或案例复盘承接区进入后，仍需要再次手动点击刷新，主路径承接不够完整。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 进入案例复盘后读取案例状态 | `public/app/createApp.js` | 新增 `enterCaseReviewWorkspace` |
| 二轮结果记录入口 | `public/app/createApp.js` | 点击后展开案例组、滚动入口、刷新真实案例列表 |
| 案例维护链接入口 | `public/app/createApp.js` | 点击“查看案例维护”后复用自动读取流程 |
| 读取反馈 | `public/app/createApp.js` | 读取中提示“正在读取案例状态...” |
| 读取失败 | `public/app/createApp.js` | 失败提示“案例读取失败，请重试” |
| 回归测试 | `tests/coverAssistantService.test.js` | 增加入口流程和状态提示断言 |

## 5. 边界

- 未自动生成复盘材料。
- 未自动执行导出。
- 未自动执行正式写回。
- 未改变真实案例排序、筛选、回填、导出接口。
- 未改变验证复盘组的默认折叠策略。

## 6. 验收项

- 从二轮结果点击“进入案例复盘记录”后，案例沉淀工作台展开，并刷新真实案例列表。
- 从案例复盘承接区点击“查看案例维护”后，案例状态自动读取。
- 案例读取失败时，页面保留入口并展示“案例读取失败，请重试”。
