# 二轮与工作区失败原因透出闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD 信息架构：`docs/prd/AI封面创意助手_MVP重做_PRD_信息架构确认_v0.1.md`

## 2. 对齐条目

- Requirement Spec：路径内建议生成失败后保留路径内输入。
- Requirement Spec：二轮修订失败后保留反馈内容，并提示调整反馈后重试。
- Requirement Spec：生成中和修订中禁用重复提交，失败后回到可继续处理的位置。

## 3. 当前缺口

二轮修订和工作区建议失败时，页面已经能回到反馈输入或路径输入区域，但失败文案只使用固定提示。若底层服务或校验返回更具体的错误原因，用户无法直接看到需要修正的内容。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 二轮修订失败原因 | `apps/web/public/app/createApp.js` | 修订请求失败时优先展示 `Error.message` |
| 工作区建议失败原因 | `apps/web/public/app/createApp.js` | 工作区建议生成失败时优先展示 `Error.message` |
| 可重试入口 | `apps/web/public/app/createApp.js` | 二轮失败仍回到反馈输入，工作区失败仍回到路径输入 |
| 回归测试 | `apps/web/tests/coverAssistantService.test.js` | 增加两个失败分支的错误原因透出断言 |

## 5. 边界

- 未改变二轮修订校验规则
- 未改变工作区路径枚举和输入规则
- 未改变提交中按钮禁用逻辑
- 未新增新的修订或工作区业务流程

## 6. 验收项

- 二轮修订失败时展示底层失败原因
- 工作区建议失败时展示底层失败原因
- 失败后仍保留原输入并回到可重试区域
