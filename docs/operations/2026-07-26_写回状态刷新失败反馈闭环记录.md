# 写回状态刷新失败反馈闭环记录

## 1. 本轮目标

[事实] 继续按 PI Engine 维护模式推进写回态错误状态闭环。

[事实] 本轮目标是让写回态顶部“刷新写回状态”按钮也接入同一套动作反馈，避免刷新失败时只显示空态、无法看到失败动作。

## 2. 实现映射

[事实] Requirement Spec 对应实现范围：

- 页面范围：写回态中的“正式写回门禁总览”。
- 操作范围：顶部“刷新写回状态”按钮。
- 状态归属：复用 `check-manual-review-formal-write-readiness` 动作语义。
- 展示结果：刷新开始显示执行中，成功后根据 readiness 显示执行中或已完成，失败后显示需复查。
- 边界：不新增接口、不新增写回动作、不改变正式写回门禁规则。

## 3. 实现范围

[事实] `public/app/createApp.js` 已更新刷新按钮逻辑：

- 点击后写入 `state.followUpActionStatus["check-manual-review-formal-write-readiness"] = running`。
- 成功后根据 `ready-to-formal-write` 判断 completed 或 running。
- 失败后写入 failed，并刷新写回态总览。
- 当复盘看板已存在时，失败状态也会同步刷新复盘看板。

## 4. 测试覆盖

[事实] `tests/coverAssistantService.test.js` 已新增 `writeback gate refresh button records action progress`：

- 断言刷新按钮复用 `check-manual-review-formal-write-readiness`。
- 断言 running、completed/running、failed 三类状态都被记录。
- 断言刷新流程会多次调用 `renderWritebackGateStatusFromState`。
- 断言刷新失败仍保留复盘看板同步能力。
