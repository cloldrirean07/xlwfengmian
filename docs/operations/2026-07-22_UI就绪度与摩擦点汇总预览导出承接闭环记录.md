# UI就绪度与摩擦点汇总预览导出承接闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD 信息架构：`docs/prd/AI封面创意助手_MVP重做_PRD_信息架构确认_v0.1.md`

## 2. 对齐条目

- Requirement Spec：案例复盘与规则沉淀需包含批次状态、待补任务、人工结论、写回状态和下一步建议。
- Requirement Spec：生成成功后展示导出状态，失败后保留当前补充内容。
- Requirement Spec：成功后形成规则修订或复跑任务。

## 3. 当前缺口

UI 优化进入条件报告和跨批次摩擦点汇总已有预览、导出和失败提示，但页面不稳定定位到对应结果区，用户需要自行寻找导出状态或继续处理入口。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| UI 就绪度预览成功/失败 | `apps/web/public/app/createApp.js` | 定位到 UI 就绪度结果区 |
| UI 就绪度导出成功/失败 | `apps/web/public/app/createApp.js` | 保留在 UI 就绪度结果区 |
| 摩擦点汇总预览成功/失败 | `apps/web/public/app/createApp.js` | 定位到摩擦点汇总结果区 |
| 摩擦点汇总导出成功/失败 | `apps/web/public/app/createApp.js` | 保留在摩擦点汇总结果区 |
| 回归测试 | `apps/web/tests/coverAssistantService.test.js` | 增加预览与导出承接断言 |

## 5. 边界

- 未改变 UI 优化进入条件判断规则
- 未改变跨批次摩擦点汇总规则
- 未改变 Obsidian 导出底层
- 未改变批次复盘看板、正式写回和规则修订任务链路

## 6. 验收项

- UI 就绪度报告预览或导出后，页面进入报告结果区
- 摩擦点汇总预览或导出后，页面进入汇总结果区
- 失败时保留已有内容，并保持可见的重试承接区域
