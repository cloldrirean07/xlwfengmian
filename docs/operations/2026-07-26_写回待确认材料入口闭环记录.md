# 写回待确认材料入口闭环记录

## 1. 本轮目标

[事实] 继续按 PI Engine 维护模式推进写回态门禁提示闭环。

[事实] 本轮目标是在正式写回处于“待人工确认”时，直接展示安全预览材料位置与下一步检查入口，减少用户在路径和操作之间来回查找。

## 2. 实现映射

[事实] Requirement Spec 对应实现范围：

- 页面范围：写回态中的“正式写回门禁总览”。
- 状态范围：已有安全预览、读回一致，但 `hasManualConfirmation` 为 false。
- 信息范围：展示安全预览材料路径、人工复盘结论填写提示、重新检查写回状态入口。
- 交互范围：复用既有 `check-manual-review-formal-write-readiness` 动作。
- 边界：不新增接口、不新增字段、不绕过人工确认、不改变正式写回门禁规则。

## 3. 实现范围

[事实] `public/app/renderers.js` 已新增 `renderWritebackManualConfirmationGuidance`：

- 仅在存在安全预览且未完成人工确认时展示。
- 展示安全预览 `targetPath`。
- 提示在安全预览底部填写人工复盘结论。
- 提供“重新检查写回状态”按钮，复用既有 readiness 检查动作。
- 已完成人工确认后不展示该提示块。

[事实] `public/styles.css` 已新增 `.writeback-confirmation-guidance`：

- 使用轻量提醒样式，与写回门禁总览保持同一视觉体系。
- 路径文本支持长路径换行，避免横向溢出。
- 操作按钮保持可点击高度。

## 4. 测试覆盖

[事实] `tests/coverAssistantService.test.js` 已补充断言：

- 写回态样式体系包含 `.writeback-confirmation-guidance`。
- 待人工确认状态展示人工确认补齐提示。
- 待人工确认状态展示安全预览路径。
- 待人工确认状态展示“重新检查写回状态”入口。
- 已满足正式写回门禁后不再展示人工确认补齐提示。
