# 正式写回成功后承接任务聚焦闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD：`docs/prd/AI封面创意助手_MVP重做_主路径与工作台重做.md`

## 2. 对齐条目

- PRD 5.7：正式写回成功后，目标记录更新，并形成规则修订或关键样例复跑任务。
- PRD 5.6：批次复盘结果可生成规则修订任务，但不自动修改规则引擎。

## 3. 当前缺口

正式写回成功后，页面已经能展示写回结果和承接任务，但成功分支此前聚焦到“当前推荐下一步”卡。对于写回成功场景，更准确的落点应是“写回后承接任务”，让规则修订任务单和关键样例复跑任务成为第一眼可见内容。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 写回后承接任务定位点 | `public/app/renderers.js` | 增加 `data-formal-write-followup-panel` |
| 成功后聚焦承接任务 | `public/app/createApp.js` | 新增 `focusFormalWriteFollowUpPanel` |
| 正式写回成功反馈 | `public/app/createApp.js` | 成功后聚焦承接任务区 |
| 回归测试 | `tests/coverAssistantService.test.js` | 增加渲染标记与成功分支断言 |

## 5. 边界

- 未改变正式写回执行条件。
- 未自动修改规则引擎。
- 未自动执行关键样例复跑。
- 未修改写回后任务的数据结构。
- 未改变正式写回 API。

## 6. 验收项

- 写回后承接任务区具备稳定定位标记。
- 正式写回成功后，页面自动滚动到写回后承接任务区。
- 如果承接任务区尚未渲染，仍回退聚焦到当前推荐下一步卡。
