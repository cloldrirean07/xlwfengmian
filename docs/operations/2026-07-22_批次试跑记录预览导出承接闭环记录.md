# 批次试跑记录预览导出承接闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD 信息架构：`docs/prd/AI封面创意助手_MVP重做_PRD_信息架构确认_v0.1.md`

## 2. 对齐条目

- Requirement Spec：案例复盘与规则沉淀需将真实案例、批次试跑和人工复盘沉淀为后续规则优化依据。
- Requirement Spec：生成成功后展示导出状态，失败后保留当前补充内容。
- Requirement Spec：失败后的去向是提示失败原因，并保留可重试入口。

## 3. 当前缺口

批次试跑记录预览和导出已有状态提示，但成功后不稳定进入试跑记录结果区，失败后也不稳定回到批量输入或保留结果区。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 试跑记录预览成功 | `apps/web/public/app/createApp.js` | 定位到试跑记录结果区 |
| 试跑记录预览失败 | `apps/web/public/app/createApp.js` | 保留批量输入并回到批量输入区 |
| 试跑记录导出成功 | `apps/web/public/app/createApp.js` | 定位到试跑记录结果区 |
| 试跑记录导出失败 | `apps/web/public/app/createApp.js` | 保留已有结果并定位试跑记录结果区 |
| 回归测试 | `apps/web/tests/coverAssistantService.test.js` | 增加预览与导出承接断言 |

## 5. 边界

- 未改变批量案例 JSON 结构
- 未改变批次试跑记录预览或导出 API
- 未改变 Obsidian 写入底层
- 未改变 UI 优化进入条件、摩擦点汇总和批次复盘看板链路

## 6. 验收项

- 批次试跑记录预览成功后，页面进入试跑记录结果区
- 批次试跑记录预览失败后，页面回到批量输入区
- 批次试跑记录导出后，页面保留在试跑记录结果区以便继续检查或重试
