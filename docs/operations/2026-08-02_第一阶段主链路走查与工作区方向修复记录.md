# 2026-08-02 第一阶段主链路走查与工作区方向修复记录

## 本轮目标

把产品第一阶段主链路跑顺：从真实案例加载到主工作台，选择首轮方向卡，进入工作区建议，采纳建议，再进入第二轮优化结果。

## 走查路径

1. 进入 Web 工作台 `http://127.0.0.1:3080`。
2. 在复盘态加载真实案例 `real-002` 到主工作台。
3. 在首轮方向卡选择 B「更清楚重点」。
4. 在「优化现有素材」工作区填写素材保留点、弱化点和当前问题。
5. 生成工作区建议并检查「当前关联方向」。
6. 采纳工作区建议。
7. 填写第二轮反馈并生成二轮优化结果。

## 发现的问题

工作区建议在选择 B「更清楚重点」后，结果里的「当前关联方向」仍显示 A「更有冲击力」。

根因是工作区建议生成逻辑里优先读取 `analysis.cards[0].directionLabelUserFacing`，导致前端已传入的当前选中方向被首卡覆盖。

## 修复范围

- `apps/web/src/domain/workspace/buildActionWorkspaceSuggestion.js`
  - 将 `linkedDirection` 改为优先使用当前工作区携带的 `workspace.linkedCardDirection`。
  - 仅在工作区未携带方向标签时，回退到首卡方向。
- `apps/web/tests/coverAssistantService.test.js`
  - 在工作区建议测试中新增断言：非首卡生成建议时，`suggestion.linkedDirection` 必须等于当前选中卡方向。

  - 结果：`294 pass / 0 fail`

  - 结果：构建通过

## 当前阶段结论

第一阶段主链路已达到可继续产品化的基础状态：真实案例可以进入主工作台，首轮方向选择可以驱动工作区建议，工作区采纳后可以进入第二轮优化。

下一步不宜继续堆规则，建议优先优化真实用户入口和结果确认体验，让「加载案例 -> 选方向 -> 工作区建议 -> 二轮优化」更像一个连续产品流程。
