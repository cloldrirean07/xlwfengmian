# 二轮修订状态规则闭环实现记录

## 基本信息

- 日期：2026-07-21
- 阶段：PI Engine 维护模式 / 主路径状态规则补齐
- 对应 PRD：`docs/prd/AI封面创意助手_MVP重做_主路径与工作台重做.md` 的 `4.6.业务规则` 与 `4.8.功能异常场景`
- 实现范围：`apps/web`

## 需求映射

| PRD 要求 | 当前实现 |
| --- | --- |
| 二轮修订必须基于当前选中方向生成 | 提交前继续校验 `latestAnalysis` 与 `selectedCardId`，缺失时不发起请求 |
| 修订中禁用重复提交 | 新增 `isRefineSubmitting` 状态，提交期间禁用二轮按钮并拦截重复 submit |
| 重新选择首轮方向后，旧二轮结果失效 | 新增 `shouldInvalidateRefinementForCardChange`，切换到不同方向时清空旧结果并隐藏二轮结果面板 |
| 未选择方向展示提示 | 缺失选中方向时同步状态提示“请先选择一个封面方向” |
| 修订失败时反馈内容保留 | catch 分支仅更新状态提示，不清空表单字段 |

## 修改边界

- 未改动二轮生成服务的输入输出结构。
- 未新增业务字段、接口或路由。
- 未改变首轮方向卡、工作区建议和案例复盘入口的既有渲染结构。

## 验证口径

- 语法检查：`node --check public/app/createApp.js`
- 语法检查：`node --check public/app/state.js`
- 单元测试：`npm test`
- 静态服务检查：确认前端脚本包含二轮提交中状态、按钮禁用文案、旧结果失效提示和修订失败提示。

## 结论

[事实] 二轮修订的状态规则已形成可追踪闭环：提交中不会重复请求，方向上下文变化时旧结果不再继续展示，失败场景保留用户填写内容。
