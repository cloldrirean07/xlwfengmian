# 静态构建脚本补齐闭环记录

- 日期：2026-07-23
- 阶段：PI Engine 维护模式
- 对应问题：项目可运行、可测试，但缺少正式 `build` 脚本，无法完成构建与 `dist` 发布产物检查。

## 事实核对

- `apps/web/package.json` 已存在 `start`、`dev`、`test` 等脚本。
- 项目当前是无前端框架依赖的静态页面 + Node HTTP 服务结构。
- 浏览器入口位于 `apps/web/public/index.html`，本地服务从 `public/` 读取静态资源。
- 既有资源路径使用根路径引用：`/styles.css`、`/main.js`。

## 本轮判断

不重做前端技术栈，不引入 Vite、Webpack 或新依赖。

本轮只补最小构建出口：

1. 在 `apps/web/package.json` 增加 `npm run build`。
2. 新增 `scripts/build-static.mjs`。
3. 构建时检查关键静态入口文件是否存在。
4. 将 `public/` 复制到 `dist/`。
5. 写入 `dist/build-manifest.json`，记录构建来源、输出目录和关键文件清单。

## 验收口径

- `npm run build` 能成功执行。
- `apps/web/dist/index.html` 存在。
- `apps/web/dist/main.js`、`apps/web/dist/styles.css` 和 `apps/web/dist/app/createApp.js` 存在。
- `dist/index.html` 保留当前本地根路径资源约定。
- 单元测试锁住 build 脚本和静态输出约定。

## 边界说明

- 本轮不改变部署脚本。
- 本轮不改变线上子目录资源前缀，因为当前项目没有发现明确的子目录部署配置。
- 如后续需要部署到固定子路径，应再补充资源前缀策略与 dist 访问路径验收。
