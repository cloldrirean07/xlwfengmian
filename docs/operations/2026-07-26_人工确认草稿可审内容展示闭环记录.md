# 人工确认草稿可审内容展示闭环记录

## 1. 执行背景

[事实] 本轮继续按“AI项目资料”的 PI Engine 维护模式推进真实案例数据闭环。

[事实] 写回态已能展示人工确认草稿验证结果，但上一版只显示“会打开门禁 / 保持锁定”，人工确认时仍需要回到文件中查看具体填写内容。

## 2. 本轮目标

[事实] 将人工确认草稿的关键填写内容接入写回态总览，只读展示来源路径、人工结论、确认行、仍需手改和写回许可。

[事实] 本轮不写入 Obsidian 安全预览，不修改真实批次试跑记录，不执行正式写回。

## 3. 实现映射

| Requirement Spec / PRD 规则 | 本轮处理 |
| --- | --- |
| 正式写回前必须有人工复盘结论 | 写回态展示每个草稿块的人工结论文本 |
| 正式写回前必须确认写回内容 | 写回态展示每个草稿块的确认行 |
| 仍需手改时不得进入正式写回 | 写回态展示“仍需手改”字段 |
| 写回许可必须明确 | 写回态展示“写回许可”字段 |
| 历史功能保持可用 | 沿用现有写回态总览面板，不新增写回动作 |

## 4. 本轮改动

[事实] 更新 `apps/web/public/app/renderers.js`：

- 人工确认草稿验证面板新增草稿来源路径。
- 每个草稿块展示人工结论、确认行、仍需手改和写回许可。

[事实] 更新 `apps/web/public/styles.css`：

- 补充草稿来源和字段明细的换行、栅格和窄屏排版。

[事实] 更新 `apps/web/tests/coverAssistantService.test.js`：

- 补充来源路径和四项关键字段渲染断言。

## 5. 边界

[事实] 本轮只增强只读展示。

[事实] 没有新增“应用建议块”或“应用保守块”按钮。

[事实] 没有绕过人工确认，也没有打开正式写回门禁。
