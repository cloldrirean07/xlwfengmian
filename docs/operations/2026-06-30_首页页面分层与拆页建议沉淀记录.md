# 2026-06-30_首页页面分层与拆页建议沉淀记录

## 1. 本轮目标

- 继续在“直接做视觉优化”之前，先收口首页信息架构。
- 判断首页哪些模块应该长期保留，哪些应准备拆成独立工作台。

## 2. 本轮完成内容

已完成：

- 按现有页面梳理 4 层内容：主链路、辅助验证、案例维护链、复盘判断链
- 明确首页长期保留内容与不适合长期平铺的内容
- 给出 `/`、`/cases`、`/validation` 三层页面结构建议
- 给出拆页前的过渡方案和 UI 优化顺序

## 3. 产出文件

- `docs/architecture/首页页面分层与拆页建议_v0.1.md`

## 4. 本轮判断

这轮最重要的结论不是“首页太乱”，而是：

- 首页已经开始同时扮演产品前台、案例后台、复盘驾驶舱三种角色
- 继续直接改视觉，只会把问题包得更漂亮，不会真正收口结构

所以这份分层方案的价值在于：

- 让后续 UI 优化知道应该先服务哪条链路
- 让代码结构和页面结构都开始为未来拆页做准备

## 5. 下一步建议

下一步最适合继续做的是：

1. 先在首页做一版“主工作台 / 案例维护 / 验证复盘”的分组收口
2. 结合当前前端标题和按钮规范，统一这些分组的命名与入口语气
3. 如果分组后仍然明显过长，再进入真正的页内导航或拆页实现
