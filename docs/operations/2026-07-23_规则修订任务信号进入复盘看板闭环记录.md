# 规则修订任务信号进入复盘看板闭环记录

- 日期：2026-07-23
- 阶段：PI Engine 维护模式 / 第三阶段
- 对应 Requirement Spec：案例复盘与规则沉淀 / 批次复盘看板

## 本轮目标

把已经生成的规则修订任务单接入复盘驾驶舱，让看板不只展示 UI readiness 和人工复盘覆盖，还能展示规则反哺信号。

## 事实基线

- 已有规则修订任务单 JSON：
  `apps/web/outputs/reports/rule-revision-task-sheet/rule-revision-task-sheet.json`
- 当前任务数：1
- 当前任务：
  `REV-001｜P3｜补强 neg-content-distance 相关关键词：不贴内容`
- 对应人工复盘判断：
  原系统把反馈归为 `neg-too-salesy`，人工建议更贴近 `neg-content-distance`。

## 实现内容

1. `runBatchReviewDashboardPreview` 读取规则修订任务单 JSON。
2. `buildBatchReviewDashboardReport` 新增 `ruleRevisionSignal`：
   - 当前状态
   - 任务数量
   - 来源样本数
   - 优先级分布
   - 前三条规则任务
3. `buildBatchReviewDashboardMarkdown` 新增“规则修订任务信号”章节。
4. 前端复盘看板新增“规则修订任务信号”区，展示建议映射与关联样本。

## 边界

- 不修改 `feedback-catalog.json`。
- 不新增规则 ID。
- 不新增接口契约。
- 不改变正式写回流程。

## 验收口径

- 复盘看板报告中存在 `ruleRevisionSignal`。
- Markdown 包含“规则修订任务信号”章节。
- 前端看板显示规则修订任务数量、优先级分布、建议映射和关联样本。
- 全量测试、构建和本地 HTTP 可达性保持通过。
