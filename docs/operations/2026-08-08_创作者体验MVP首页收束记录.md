# 2026-08-08 创作者体验 MVP 首页收束记录

## 本轮目标

根据产品介绍文档和当前会话判断，首页需要从“内部流程工作台”调整为“创作者体验 MVP 首页”。规则、案例复盘、写回门禁继续保留，但降级为后台支撑，不再作为首屏主要心智。

## 调整前问题

- 首屏强调“输入到二轮”“复盘态”“写回态”“门禁”等内部流程词，容易让产品看起来像后台工具。
- 创作者最关心的动作不够靠前：上传素材、生成封面方向、比较标题、继续优化。
- 视觉系统偏单一米色，后台感较强，主行动、案例验证和高级维护之间缺少清晰区分。

## 本轮调整

- 首页主标题改为“上传素材，快速生成更容易被点开的封面方案”。
- 首屏副文案聚焦小红书、抖音发布前的封面决策，不再解释内部规则链路。
- 主导航改为：
  - 封面生成 / 创作者模式
  - 案例验证 / 效果证据
  - 高级维护 / 规则与写回
- 主链路改为：
  - 上传素材
  - 生成方案
  - 筛选优化
- 表单主按钮改为“生成封面方案”。
- 复盘与写回区域保留结构和功能入口，但统一呈现为后台支撑。
- 色彩系统调整为白色底、暖橙主行动、青绿案例验证、蓝紫高级维护。

## 保留边界

- 未改动真实案例数据结构。
- 未改动规则判断、标题写回、批次复盘和安全写回业务逻辑。
- 未新增运行时依赖。
- 未处理多图上传能力；当前仍是单张参考图预览。

## 后台支撑定位

内部系统不是删除，而是服务于主产品链路：

- 规则判断：支持封面方向生成。
- 案例验证：检验真实素材下的输出质量。
- 写回维护：把人工优选和复盘结论沉淀回案例资产。
- 批次记录：为后续判断效率提升提供证据。

## 后续建议

下一步建议进入“主链路可行性验证”：

1. 用 real-002、real-003 和一条新案例分别跑完整链路。
2. 记录人工从选题到封面方案选择的耗时。
3. 对比无工具情况下的标题数量、可选方向数量和筛选信心。
4. 再决定是否实现多图上传和更完整的视觉预览。
