# 准拆页三视图实施确认单

## 1. 确认目的

本确认单用于承接：

- `docs/architecture/准拆页三视图实施方案_v0.1.md`
- `docs/operations/2026-07-23_AI项目资料执行阶段审计与转段建议.md`

目标是在进入代码实现前，把准拆页的产品命名、默认显示、入口保留和执行边界一次性确认清楚。

## 2. 推荐默认决策

| 确认项 | 推荐选择 | 原因 |
| --- | --- | --- |
| 三视图名称 | 创作主线 / 案例维护 / 复盘驾驶舱 | 与现有产品语义和架构文档一致，能区分前台产品、案例资产、复盘推进 |
| 默认显示 | 只显示创作主线 | 符合 PRD “重新收束为一条清晰主路径”的目标 |
| 顶部入口 | 允许顶部切换进入案例维护和复盘驾驶舱 | 保留内部工作台效率，同时避免首页平铺 |
| Hero 次级入口 | 保留“沉淀案例资产”“进入规则复盘”，但降级为次级入口 | 保留已有深链和工作流承接，不让它们抢主路径首屏权重 |

## 4. 执行后预期变化

### 4.1 用户感知变化

实施后，首页将不再一次性平铺所有工作台，而是先呈现创作主线。

用户可以通过顶部视图切换进入：

- 案例维护
- 复盘驾驶舱

### 4.2 代码结构变化

预计修改：

- `apps/web/public/index.html`
- `apps/web/public/app/createApp.js`
- `apps/web/public/app/dom.js`
- `apps/web/public/styles.css`
- `apps/web/tests/coverAssistantService.test.js`
- `apps/web/updatelog.md`
- 新增一份操作记录

预计不修改：

- 规则引擎
- API 契约
- Obsidian 导出底层
- 真实案例数据结构
- 测试运行入口

## 5. 实施边界

必须保留：

- 当前首轮输入、方向卡、工作区建议、二轮修订链路
- 当前案例维护、平台复核、批次复盘、正式写回能力
- `#real-case-form` 和 `#review-dashboard-section` 等既有锚点语义
- 已上传素材、首轮结果、工作区建议、二轮结果等运行状态

不得新增：

- 新路由
- 新前端项目
- 新依赖
- 自动导出
- 自动写回
- 自动规则修改

## 6. 实施验收口径

下一轮进入代码实现后，验收应至少包含：

- 首页存在三视图入口
- 默认视图为创作主线
- 案例维护不在首屏平铺
- 复盘驾驶舱不在首屏平铺
- 点击案例入口能切换到案例维护并保留原有读取逻辑
- 点击复盘入口能切换到复盘驾驶舱并保留看板生成逻辑
- 原有主链路测试通过
- 本地服务 `/`、`/api/health`、`/app/createApp.js` 可访问
