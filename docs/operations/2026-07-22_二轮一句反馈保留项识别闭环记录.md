# 二轮一句反馈保留项识别闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD：`docs/prd/AI封面创意助手_MVP重做_主路径与工作台重做.md`

## 2. 对齐条目

- PRD 4.4：用户输入一句反馈后，系统识别反馈是否有效，并生成二轮结果。
- PRD 4.6：系统应识别用户反馈中的保留项和修改项，并在结果中展示修改依据。
- Requirement Spec：二轮修订应接住用户对首轮方向或工作区建议的主观反馈，并生成更贴近意图的修订结果。

## 3. 本轮实现映射

| Spec / PRD 条目 | 实现位置 | 实现结果 |
| --- | --- | --- |
| 一句反馈识别保留项 | `src/domain/refinement/mapFeedbackToAdjustment.js` | 当独立保留字段为空时，从反馈文本中识别“保留 / 保持 / 留下 / 延续 / 不要动 / 别改”后的保留项。 |
| 保留项来源可解释 | `src/domain/refinement/mapFeedbackToAdjustment.js` | 新增 `preserveElementSource`，区分字段、反馈文本和兜底方向。 |
| 修改依据展示识别结果 | `src/domain/refinement/buildFeedbackMappingExplanation.js` | 解释行补充“保留项来自哪里”和识别出的保留项。 |
| 回归测试 | `tests/coverAssistantService.test.js` | 增加“保留误区冲突，但降低营销感”的一句反馈识别测试。 |

## 4. 边界

- 未新增二轮表单字段。
- 未改变反馈负向映射和正向保留信号规则目录。
- 未改变二轮接口契约。
- 未改变工作区采纳与不采纳逻辑。

## 5. 验收项

- 当独立保留字段为空，反馈中包含明确“保留”表达时，二轮结果应使用反馈文本中的保留项。
- 修改依据中应说明保留项来自一句反馈。
- 既有字段填写方式继续有效，手动填写的保留字段优先级高于反馈文本抽取。
- 未命中明确保留表达时，仍回落到已选方向作为保留上下文。
