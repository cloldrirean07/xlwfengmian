# 写回未确认后状态面板聚焦闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD：`docs/prd/AI封面创意助手_MVP重做_主路径与工作台重做.md`

## 2. 对齐条目

- PRD 5.5：正式写回前需要人工复盘结论和写回确认。
- PRD 5.6：未确认写回时，不修改目标记录。
- PRD 5.8：写回未确认时展示“请先确认写回内容”，不执行正式写回。

## 3. 当前缺口

正式写回校验失败时，系统已经能阻止写回并提示原因，但页面焦点回到推荐下一步卡。对于“写回未确认”场景，更准确的反馈落点应是正式写回状态区，让用户看到当前状态、状态码、最近安全预览和确认缺口。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 正式写回状态定位点 | `public/app/renderers.js` | 增加 `data-formal-write-status-panel` |
| 写回状态面板聚焦 | `public/app/createApp.js` | 新增 `focusFormalWriteStatusPanel` |
| 写回校验失败反馈 | `public/app/createApp.js` | 校验失败后聚焦状态面板 |
| 回归测试 | `tests/coverAssistantService.test.js` | 增加渲染标记与失败分支断言 |

## 5. 边界

- 未改变正式写回校验条件。
- 未自动确认写回。
- 未自动执行正式写回。
- 未修改目标记录。
- 未改变安全写回预览或正式写回接口。

## 6. 验收项

- 正式写回状态区具备稳定定位标记。
- 正式写回校验失败时，页面提示失败原因并聚焦到正式写回状态区。
- 如果状态区尚未渲染，仍回退聚焦到当前推荐下一步卡。
