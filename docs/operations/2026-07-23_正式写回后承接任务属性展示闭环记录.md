# 正式写回后承接任务属性展示闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD 信息架构：`docs/prd/AI封面创意助手_MVP重做_PRD_信息架构确认_v0.1.md`

## 2. 对齐条目

- Requirement Spec：案例复盘成功后案例状态更新，并形成规则修订或复跑任务。
- Requirement Spec：批次复盘看板包含写回状态和下一步建议。
- PRD 信息架构：保留批次复盘和写回确认能力，正式写回前必须有确认状态。

## 3. 当前缺口

正式写回完成后，写回后承接任务面板只展示任务名称和摘要。规则修订任务单与关键样例复跑已经在数据中包含任务类型和执行方式，但界面未展示这些属性，用户无法直接判断任务边界和处理方式。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 规则修订任务属性 | `apps/web/public/app/renderers.js` | 展示任务类型为规则修订 |
| 关键样例复跑属性 | `apps/web/public/app/renderers.js` | 展示任务类型为关键样例复跑 |
| 执行方式 | `apps/web/public/app/renderers.js` | 展示需人工确认 |
| 回归测试 | `apps/web/tests/coverAssistantService.test.js` | 增加任务类型和执行方式渲染断言 |

## 5. 边界

- 未新增自动执行规则修订能力
- 未新增自动复跑能力
- 未改变正式写回成功、失败和回滚逻辑
- 未改变后续任务生成规则

## 6. 验收项

- 正式写回后承接任务展示任务类型
- 正式写回后承接任务展示执行方式
- 规则修订与关键样例复跑仍保持人工确认边界
