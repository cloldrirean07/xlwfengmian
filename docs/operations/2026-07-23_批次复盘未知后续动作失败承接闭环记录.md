# 批次复盘未知后续动作失败承接闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD 信息架构：`docs/prd/AI封面创意助手_MVP重做_PRD_信息架构确认_v0.1.md`

## 2. 对齐条目

- Requirement Spec：批次复盘看板需要包含批次状态、待补任务、人工结论、写回状态和下一步建议。
- Requirement Spec：失败后页面提示失败原因，并保留可重试入口。
- Requirement Spec：状态规则需要覆盖异常提示。

## 3. 当前缺口

批次复盘看板后续动作只对已知 `actionId` 建立了执行分支。若后续清单出现暂未处理的动作入口，兜底分支只写入失败状态，不重新渲染看板、不提示原因，也不回到下一步区域。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 未知后续动作失败态 | `apps/web/public/app/createApp.js` | 写入失败状态后重新渲染看板 |
| 异常提示 | `apps/web/public/app/createApp.js` | 展示当前动作暂不可执行提示 |
| 下一步承接 | `apps/web/public/app/createApp.js` | 聚焦看板下一步建议区 |
| 回归测试 | `apps/web/tests/coverAssistantService.test.js` | 增加未知后续动作可恢复性断言 |

## 5. 边界

- 未新增业务动作
- 未改变任何已知后续动作的执行逻辑
- 未改变批次复盘清单生成规则
- 未改变正式写回、人工复盘和导出 API

## 6. 验收项

- 未知后续动作触发后，看板显示失败状态
- 页面展示明确异常提示
- 页面回到下一步建议区，保留继续处理入口
