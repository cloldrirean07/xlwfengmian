# 写回态正式写回受控按钮记录

## 1. 本轮目标

[事实] 继续按 PI Engine 维护模式推进写回态，让正式写回入口在总览状态面板中呈现可执行/不可执行状态。

[事实] 本轮不修改正式写回条件，不新增写回接口，不跳过 `validateFormalWriteReadiness`。

## 2. 实现范围

[事实] `renderWritebackGateOverviewStatus` 已新增受控正式写回按钮：

- readiness 未满足时显示“正式写回待解锁”，并保持禁用。
- readiness 满足时显示“执行正式写回”，并复用 `export-manual-review-formal-write` 动作。

[事实] 受控按钮的文案会说明当前是否满足门禁。

[事实] 样式层新增 `writeback-controlled-action`，使按钮和状态说明保持同一面板层级。

[事实] 门禁总览静态操作区已将原“执行正式写回”锚点调整为“查看正式写回入口”，避免静态跳转入口被误解为可直接执行正式写回。

## 3. 边界说明

[事实] 即使按钮进入可执行状态，点击后仍会走既有 action handler，并再次执行正式写回 readiness 校验。

[事实] 当前真实环境仍未完成人工确认，因此接口状态保持 `awaiting-safe-write-confirmation`。
