# 2026-06-26 真实案例确认写入链路接入记录

## 1. 本轮目标

把真实案例录入页从“只做预览”推进到“确认后正式写入代码侧真实案例数据”。

## 2. 本轮完成内容

### 2.1 新增正式写入用例

新增：

- `src/application/commitRealCaseScaffold.js`

作用：

- 读取当前 index
- 生成真实案例脚手架
- 触发写入
- 刷新 case cache

### 2.2 新增真实案例持久化层

新增：

- `src/infrastructure/cases/resolveRealCaseStoragePaths.js`
- `src/infrastructure/cases/savePreparedRealCaseScaffold.js`

作用：

- 管理真实案例写入路径
- 写入 index 与 item 文件
- 避免重复覆盖已有 item

### 2.3 新增服务接口

新增：

- `POST /api/real-case-scaffold-commit`

### 2.4 新增前端确认写入入口

前端新增：

- “确认写入真实案例”按钮
- 写入结果展示区

并在页面编排层接入：

- 未预览前禁止直接写入
- 写入成功后展示文件路径与下一步建议

## 5. 当前关于 UI 的判断

当前不建议立刻花时间做完整 UI 重构。

更合理的时机是：

- 至少有 2~3 条真实案例实际跑过录入页
- 确认输入区字段不会再大改
- 确认结果区展示块不会再大幅变形

那时候再和用户一起讨论 UI，能围绕真实流程痛点优化，而不是只做视觉修饰。

## 6. 下一步建议

下一步最顺的是：

1. 让前端可以重新读取新写入的真实案例
2. 给真实案例录入页补更完整的内容字段
3. 再决定是否同步生成 Obsidian 待补草稿

这样就会从“可写入”继续推进到“可持续维护”。
