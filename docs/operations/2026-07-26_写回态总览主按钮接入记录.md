# 写回态总览主按钮接入记录

## 1. 本轮目标

[事实] 继续按 PI Engine 维护模式推进写回态，将门禁总览中的关键动作从跳转说明升级为可直接触发既有动作。

[事实] 本轮只复用已有复盘看板 action handler，不新增正式写回接口、不改写回门禁规则。

## 2. 实现范围

[事实] 写回态总览中的“导出安全预览”和“检查正式写回状态”已改为按钮。

[事实] 两个按钮分别复用既有动作：

- `export-manual-review-safe-write`
- `check-manual-review-formal-write-readiness`

[事实] 原复盘看板结果区的点击处理已提取为 `handleReviewFollowupAction`，并同时绑定到复盘看板结果区和写回态总览区。

[事实] 安全预览导出成功后，会同步刷新写回态门禁状态面板。

## 3. 边界说明

[事实] “执行正式写回”仍保持为跳转入口，不在总览中直接触发。

[事实] 正式写回仍必须通过 readiness 校验，且安全预览未完成人工确认时不会进入正式写回。

## 4. 验证结果

[事实] 目标测试已通过：

- `public UI copy avoids conversational task phrasing`
- `case review bridge links expand their target workspace groups`
- `renderWritebackGateOverviewStatus shows empty and readiness states`

[事实] 语法检查已通过：`node --check public/app/createApp.js`。

## 5. 下一步

[推断] 下一步可以把“执行正式写回”在总览中做成受 readiness 控制的禁用/可执行状态，但需要继续保持正式写回前置校验。
