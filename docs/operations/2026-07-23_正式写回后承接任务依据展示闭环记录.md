# 正式写回后承接任务依据展示闭环记录

## 1. 执行依据

- Skill：`ai-pi-engine`
- 模式：维护模式
- Requirement Spec：`docs/prd/AI封面创意助手重做_Requirement_Spec_v0.1.md`
- PRD 信息架构：`docs/prd/AI封面创意助手_MVP重做_PRD_信息架构确认_v0.1.md`

## 2. 对齐条目

- Requirement Spec：案例复盘成功后形成规则修订或复跑任务。
- Requirement Spec：批次复盘看板用于跨多个案例判断重复问题，并决定是否进入规则修订。
- Requirement Spec：规则沉淀需要保留人工复盘、写回状态和下一步建议。

## 3. 当前缺口

正式写回后的承接任务数据已经包含 `evidence`，但界面只展示任务名称、摘要、任务类型和执行方式。用户无法在任务面板内直接看到规则修订或关键样例复跑的形成依据。

## 4. 本轮实现映射

| 条目 | 位置 | 结果 |
| --- | --- | --- |
| 任务依据展示 | `apps/web/public/app/renderers.js` | 展示承接任务中的有效依据 |
| 展示边界 | `apps/web/public/app/renderers.js` | 最多展示前两条有效依据，避免面板过长 |
| 回归测试 | `apps/web/tests/coverAssistantService.test.js` | 增加任务依据渲染断言 |

## 5. 边界

- 未新增承接任务字段
- 未改变正式写回任务生成规则
- 未新增自动规则修订或自动复跑能力
- 未改变正式写回执行和回滚逻辑

## 6. 验收项

- 正式写回后承接任务展示形成依据
- 空依据不渲染冗余占位
- 规则修订与关键样例复跑仍保持人工确认边界
