# 写回态首屏主路径可读性闭环记录

## 1. 本轮目标

[事实] 继续按 PI Engine 维护模式推进写回态信息架构细节闭环。

[事实] 本轮目标是让写回态首屏操作优先级更清楚，把“刷新门禁状态、导出安全预览、检查写回门禁、查看复盘看板写回状态”收束到同一组主操作顺序中。

## 2. 实现映射

[事实] Requirement Spec 对应实现范围：

- 页面范围：写回态中的“正式写回门禁总览”首屏。
- 信息范围：正式写回门禁操作顺序。
- 交互范围：保留既有 `refresh-writeback-gate-status-button` 与 `data-review-followup-action`。
- 边界：不新增接口、不新增路由、不新增写回动作、不改变正式写回门禁规则。

## 3. 实现范围

[事实] `public/index.html` 已完成首屏主路径收束：

- 将 `refresh-writeback-gate-status-button` 从面板头部移动到“正式写回门禁操作顺序”第一位。
- 按钮文案由“刷新写回状态”调整为“刷新门禁状态”。
- 静态操作入口由“检查正式写回状态”调整为“检查写回门禁”。
- 复盘看板动态结果中的同类入口同步调整为“检查写回门禁”。

[事实] `public/app/renderers.js` 已同步复盘看板动态入口文案：

- `check-manual-review-formal-write-readiness` 的按钮文案统一为“检查写回门禁”。
- action id 保持不变，业务动作不变。

## 4. 测试覆盖

[事实] `tests/coverAssistantService.test.js` 已补充断言：

- 静态页面仍包含 `refresh-writeback-gate-status-button`。
