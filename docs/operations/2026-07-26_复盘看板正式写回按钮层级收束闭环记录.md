# 复盘看板正式写回按钮层级收束闭环记录

## 1. 本轮目标

[事实] 继续按 PI Engine 维护模式推进写回链路的产品化收束。

[事实] 本轮目标是减少复盘看板与写回态总览之间的正式写回按钮竞争，让复盘看板中的正式写回动作只在 readiness 明确放行后出现。

## 2. 实现映射

[事实] Requirement Spec 对应实现范围：

- 页面范围：复盘看板结果区。
- 动作范围：`export-manual-review-formal-write`。
- 状态依据：`formalWriteReadiness.latestSafeWriteStatus.canProceedToFormalWrite`。
- 展示规则：未放行时不展示复盘看板直写按钮；放行时展示“执行正式写回”。
- 边界：不新增接口、不改变正式写回条件、不绕过 `validateFormalWriteReadiness`。

## 3. 实现范围

[事实] `public/app/renderers.js` 已新增 `canShowFormalWriteAction`：

- 仅当 `safeWriteStatus?.canProceedToFormalWrite` 为 `true` 时展示复盘看板正式写回按钮。
- 原“执行正式写回（需先确认安全预览）”文案已移除，避免按钮和门禁状态自相矛盾。

## 4. 测试覆盖

[事实] `tests/coverAssistantService.test.js` 已补充断言：

- 未满足 readiness 时，复盘看板不展示正式写回按钮。
- 满足 readiness 时，复盘看板展示“执行正式写回”按钮。
- 旧文案“执行正式写回（需先确认安全预览）”不再出现。
