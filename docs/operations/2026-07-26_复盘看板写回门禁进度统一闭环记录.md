# 复盘看板写回门禁进度统一闭环记录

## 1. 本轮目标

[事实] 继续按 PI Engine 维护模式推进写回态与复盘态的状态口径统一。

[事实] 本轮目标是让复盘看板中的“正式写回状态”复用写回态总览中的四段门禁进度，避免同一写回链路在两个入口显示不同结构。

## 2. 实现映射

[事实] Requirement Spec 对应实现范围：

- 页面范围：复盘看板结果区中的“正式写回状态”。
- 复用组件：`buildWritebackGateProgress` 与 `renderWritebackGateProgress`。
- 数据来源：复用既有 `formalWriteReadiness.latestSafeWriteStatus`。
- 状态口径：安全预览、人工确认、状态检查、正式写回四段进度。
- 边界：不新增接口、不新增写回权限、不改变 `canProceedToFormalWrite` 的判断。

## 3. 实现范围

[事实] `public/app/renderers.js` 已在 `renderBatchReviewDashboardResult` 中新增 `formalWriteGateProgress`：

- 有 `formalWriteReadiness` 时，在正式写回状态详情下展示同一套门禁进度。
- 无 `formalWriteReadiness` 时保持原有看板展示，不生成额外空状态。
- 进度状态仍由既有安全预览读回、人工确认和写回许可字段决定。

## 4. 测试覆盖

[事实] `tests/coverAssistantService.test.js` 已补充断言：

- 复盘看板正式写回状态区包含 `aria-label="正式写回门禁进度"`。
- 正常读回但未人工确认时展示“预览已读回 / 等待结论 / 门禁未满足 / 保持锁定”。
- 安全预览内容不一致时展示“预览需复查”与 `writeback-gate-step-attention`。
