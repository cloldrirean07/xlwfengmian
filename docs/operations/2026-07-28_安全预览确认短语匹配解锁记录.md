# 安全预览确认短语匹配解锁记录

- 时间：2026-07-28 19:45
- 执行模式：PI Engine 维护模式
- 本轮目标：将安全预览确认块写入按钮改为确认短语匹配后才解锁，减少误点击和无效请求。

## 1. 背景

- 受控写入入口已支持填入固定确认短语。
- 写入按钮此前在预检通过后直接可点，短语错误时由点击后的校验拦截。
- 当前更稳妥的交互是：按钮默认锁定，确认短语匹配后再开放写入动作。

## 2. 修正

- 更新 `public/app/renderers.js`
  - 为写入按钮增加 `data-safe-preview-write-submit` 标记。
  - 写入按钮默认禁用，初始 `aria-disabled="true"`。
- 更新 `public/app/createApp.js`
  - 新增 `syncManualConfirmationSafePreviewWriteButton`。
  - 输入框内容等于 `确认写入安全预览确认块` 时，写入按钮切换为可用。
  - 点击“填入短语”后立即同步按钮状态。
  - 在写回门禁总览和复盘看板结果区同时监听输入变化。
- 更新 `tests/coverAssistantService.test.js`
  - 增加按钮默认锁定、输入事件绑定、短语匹配解锁函数和 `aria-disabled` 切换断言。

## 3. 安全边界

- 本轮只调整入口解锁条件。
- 本轮未自动执行安全预览确认块写入。
- 本轮未写入 Obsidian。
- 本轮未执行正式写回。

## 4. 下一步

- 点击“填入短语”后，写入按钮将进入可用状态。
- 点击“写入确认块”时，服务端仍会重新执行确认短语校验、写入预检和读回校验。
- 写入完成后再重新检查正式写回门禁。
