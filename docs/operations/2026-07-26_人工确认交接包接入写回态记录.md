# 人工确认交接包接入写回态记录

## 1. 本轮定位

[事实] 本轮继续按 PI Engine 维护模式推进真实案例数据闭环。

[事实] 上一轮已经生成项目内人工确认交接包，状态为 `ready-for-manual-transfer`。

[事实] 本轮目标是把交接包接入前端写回态总览，作为只读证据面板展示。

[事实] 本轮不写入 Obsidian，不执行正式写回，不新增写入按钮。

## 2. 新增只读接口

[事实] 新增接口：

```http
GET /api/batch-review-manual-confirmation-handoff-packet
```

[事实] 接口返回：

- 交接状态
- 目标批次
- 目标记录
- 推荐确认块
- 推荐版本门禁预期
- 保守版本门禁预期
- 后续复查步骤
- 交接包输出路径

## 3. 页面接入

[事实] 写回态总览新增“人工确认交接包”面板。

[事实] 面板展示：

- 目标批次
- 目标记录
- 推荐版本写入后是否打开门禁
- 保守版本写入后是否保持锁定
- 推荐确认块
- 后续复查步骤
- 交接包文件路径

[事实] 面板不提供直接写入 Obsidian 或执行正式写回的操作。

## 4. 边界

[事实] 本轮只把已生成的项目内交接证据展示到页面。

[事实] 当前正式写回门禁仍需人工确认后再推进。

## 5. 下一步

[需确认] 若继续推进，应由人工确认是否采用推荐确认块，并将该块写入 Obsidian 安全预览记录底部。
