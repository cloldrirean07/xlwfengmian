# 页面交互说明

### 页面：创作者主工作台

- 页面入口：
  用户进入 AI 封面创意助手后默认展示。
- 页面用途：
  承接用户的内容想法、目标平台、内容目标和本地参考素材，帮助用户快速开始封面创意方案生成。
- 页面主区块：
  内容输入区、目标平台区、素材上传与预览区、素材理解提示区、生成动作区。
- 页面主状态：
  待输入、填写中、素材已预览、可生成、生成中、生成失败、已生成三案。
- 页面主链路：
  用户输入内容主题或上传参考素材，补充目标平台和内容目标后，点击生成动作，系统进入素材理解和封面创意方案生成。
- 成功后的去向：
  页面展示首轮三方案结果，并引导用户比较和选择方向。
- 失败后的去向：
  页面保留已填内容和已选素材，并提示用户补充必要线索或重新生成。

#### 功能：封面创意开始区

- 功能入口：
  创作者主工作台首屏输入区域。
- 用户场景：
  用户已有图片、截图、内容想法或素材说明，但不知道应该做什么封面更容易吸引点击。
- 信息架构：
  包含内容主题、目标平台、内容目标、素材类型、素材说明、本地参考图和补充偏好。
- 交互流程：
  用户填写内容主题，选择目标平台，补充内容目标；用户可上传一张或多张本地参考图，也可只填写素材说明后生成。
- 页面反馈与状态变化：
  内容主题、素材图片、素材说明至少提供一项；缺少内容目标时使用默认目标“提升点击意愿”；输入满足条件后进入可生成状态。

#### 功能：本地参考图预览

- 功能入口：
  素材上传与预览区。
- 用户场景：
  用户希望把已有图片、截图或内容素材交给系统理解，但这些图片不一定都是候选封面图。
- 信息架构：
  包含图片缩略图、文件名、素材数量、清除动作和素材用途提示。
- 交互流程：
  用户选择一张或多张图片后，页面在本地展示预览；用户可清除单张素材或清空全部素材后重新选择。
- 页面反馈与状态变化：
  上传图片后进入素材已预览状态；非图片文件给出格式提示；当前阶段只做浏览器本地预览，不上传服务器。

#### 功能：素材理解提示

- 功能入口：
  本地参考图预览下方。
- 用户场景：
  用户需要知道当前素材是否适合直接做封面，还是只能作为内容理解参考。
- 信息架构：
  包含素材用途判断、可用程度、补图建议和生成前提示。
- 交互流程：
  系统根据素材类型和素材说明展示判断结果；图片信息不足时，引导用户补充素材描述。
- 页面反馈与状态变化：
  素材可直接使用时进入可生成状态；素材仅作参考时仍允许生成，但在结果中必须给出补图方向；信息不足时提示补充描述。

#### 功能：生成封面创意方案

- 功能入口：
  创作者主工作台生成动作区。
- 用户场景：
  用户完成最小输入后，希望一次得到多个可比较的封面创意方向。
- 信息架构：
  包含生成动作、生成中状态、失败反馈和结果承接提示。
- 交互流程：
  用户点击生成动作后，系统基于内容主题、素材说明、目标平台和本地参考图状态生成三套封面创意方案。
- 页面反馈与状态变化：
  生成中禁用重复提交；生成成功后进入首轮三方案结果；生成失败后保留当前输入并提供重试动作。

### 页面：首轮三方案结果

- 页面入口：
  创作者主工作台生成成功后展示。
- 页面用途：
  让用户比较三个差异化封面创意方案，并判断哪个方向最适合当前内容。
- 页面主区块：
  三方案卡片、素材适用判断、标题方向、图像题材建议、构图建议、点击理由、风险提醒、选择动作。
- 页面主状态：
  无结果、三案已生成、方案已选择、切换选择、结果生成失败。
- 页面主链路：
  用户查看三个方案卡，比较不同点击心理和图像题材，选择一个方案作为二轮微调基础。
- 成功后的去向：
  进入二轮微调区，保留已选方案和原始输入上下文。
- 失败后的去向：
  返回创作者主工作台修改输入后重新生成。

#### 功能：三方案卡片

- 功能入口：
  首轮三方案结果区。
- 用户场景：
  用户需要从多个创意方向中快速判断哪个封面方案更有点击感。
- 信息架构：
  每个方案包含方案名称、推荐封面图题材、当前素材适用判断、标题方向、构图建议、点击理由和风险提醒。
- 交互流程：
  系统一次输出三张方向卡；用户横向比较后点击选择某个方案，当前方案进入选中态。
- 页面反馈与状态变化：
  被选择的方案高亮；未选择方案保持可切换；切换方案时同步更新二轮微调承接信息。

#### 功能：素材适用判断

- 功能入口：
  每张方案卡内部。
- 用户场景：
  用户需要知道已有素材能不能直接做封面，以及是否需要补拍、补找或换图。
- 信息架构：
  包含可直接使用、建议裁切优化、建议补图、仅作内容参考四类判断。
- 交互流程：
  系统结合素材类型、素材说明和方案方向，对当前素材给出适用结论，并说明下一步处理建议。
- 页面反馈与状态变化：
  可直接使用时突出当前素材；建议补图时展示补图题材；仅作参考时避免把原图误导为最终封面。

#### 功能：点击理由与风险提醒

- 功能入口：
  每张方案卡说明区。
- 用户场景：
  用户希望理解方案为什么值得尝试，同时避免标题或画面过度夸张。
- 信息架构：
  包含点击心理、内容适配理由、可能风险和规避建议。
- 交互流程：
  用户阅读方案说明后，可以选择当前方案，也可以切换其他方案比较。
- 页面反馈与状态变化：
  风险提醒保持就近展示；风险不阻断选择，但需要让用户理解方案边界。

### 页面：二轮微调区

- 页面入口：
  用户在首轮三方案结果中选择某个方案后展示。
- 页面用途：
  接住用户对已选方案的一句话反馈，并围绕标题风格、图像题材或构图重点继续微调。
- 页面主区块：
  已选方案摘要、原始素材摘要、一句话反馈输入、微调动作、微调结果。
- 页面主状态：
  待选择方案、待反馈、反馈填写中、微调中、微调成功、微调失败。
- 页面主链路：
  用户选择方案后输入一句反馈，系统基于已选方案进行局部调整，输出更贴近用户意图的微调结果。
- 成功后的去向：
  展示二轮微调结果，并允许用户记录为真实案例或返回方案区重新选择。
- 失败后的去向：
  保留用户反馈和已选方案，提示用户调整反馈后重试。

#### 功能：一句反馈微调

- 功能入口：
  二轮微调区反馈输入框。
- 用户场景：
  用户认可某个方案的大方向，但希望它更贴合自己的审美、平台风格或内容重点。
- 信息架构：
  包含已选方案、反馈文本、微调动作和反馈示例提示。
- 交互流程：
  用户输入一句反馈并点击微调；系统识别用户希望保留和调整的部分，并输出更新后的标题方向、图像题材和构图建议。
- 页面反馈与状态变化：
  反馈为空时提示补充修改意见；微调中禁用重复提交；微调成功后展示调整依据和新结果。

#### 功能：二轮结果展示

- 功能入口：
  一句反馈微调成功后自动展示。
- 用户场景：
  用户需要看到调整后的方案是否回应了自己的反馈。
- 信息架构：
  包含新版标题方向、新版图像建议、新版构图建议、保留项、调整项和风险提醒。
- 交互流程：
  用户查看二轮结果后，可以记录案例、返回修改反馈，或回到首轮三方案重新选择方向。
- 页面反馈与状态变化：
  二轮结果突出本次调整点；保留已选方案作为对照；重新选择方案时重置二轮结果。

### 页面：真实案例区

- 页面入口：
  创作者主工作台中的真实案例入口。
- 页面用途：
  将 real-002、real-003 等真实素材案例载入主工作台，用于验证封面创意素材匹配模块是否能产出具体、贴合素材的方案。
- 页面主区块：
  案例列表、案例摘要、加载到主工作台动作、案例复跑状态、优选方案记录入口。
- 页面主状态：
  未选择案例、案例已加载、已生成三案、已选择方案、已记录优选、待复盘。
- 页面主链路：
  用户选择真实案例，将案例字段带入创作者主工作台，生成三方案并记录人工选择结果。
- 成功后的去向：
  主工作台带入案例内容，用户可继续生成、选择和二轮微调。
- 失败后的去向：
  保留案例列表，并提示案例字段缺失或加载失败。

#### 功能：加载真实案例

- 功能入口：
  真实案例区中的案例操作。
- 用户场景：
  用户希望用已补充字段的真实案例验证当前产品链路。
- 信息架构：
  包含案例编号、内容主题、素材描述、内容目标、素材路径或截图说明、加载动作。
- 交互流程：
  用户点击加载真实案例后，系统把案例字段带入主工作台输入区，并保留本地素材预览状态。
- 页面反馈与状态变化：
  加载成功后主工作台显示案例来源；案例字段缺失时提示需要补充来源、主题、素材描述或内容目标。

#### 功能：优选方案记录

- 功能入口：
  首轮三方案结果或二轮微调结果后的记录动作。
- 用户场景：
  用户希望把人工选择的方案、优选标题或微调结果沉淀为后续样例。
- 信息架构：
  包含案例编号、已选方案、人工优选标题、选择理由和待复盘状态。
- 交互流程：
  用户选择方案后记录优选结果；系统将结果标记为案例验证样本，供后续规则复盘使用。
- 页面反馈与状态变化：
  记录成功后展示已记录状态；记录失败时保留选择结果并提示重试。

### 页面：后台支撑区

- 页面入口：
  主工作台低频维护入口。
- 页面用途：
  承接规则复盘、样例复跑和写回能力，让前台创作者体验保持简单。
- 页面主区块：
  规则复盘入口、真实案例复跑入口、写回状态入口、待处理样例提示。
- 页面主状态：
  无待处理、存在待复盘案例、写回待确认、写回完成、写回失败。
- 页面主链路：
  用户在真实案例验证后进入后台支撑区，查看待复盘样例，执行必要的规则或案例维护动作。
- 成功后的去向：
  更新案例状态，并回到主工作台继续验证。
- 失败后的去向：
  保留待处理状态，并提示用户检查缺失字段或写回确认。

#### 功能：规则与复盘沉淀

- 功能入口：
  后台支撑区维护入口。
- 用户场景：
  用户需要把真实案例中的人工判断转化为后续规则和样例库依据。
- 信息架构：
  包含待复盘案例、输出偏差、人工优选结果、复跑动作和写回状态。
- 交互流程：
  用户查看待复盘样例，确认偏差来源，必要时进入已有复盘或写回链路。
- 页面反馈与状态变化：
  复盘完成后更新案例状态；写回需要保留确认门；后台维护入口不作为新用户第一屏主内容。
