# UI优化前检查表 v0.1

## 目的

这份检查表不是为了让你“马上美化页面”，而是帮助你判断：

- 当前是不是已经到适合讨论 UI 优化的时点
- 现在最该优化的是信息结构、交互路径，还是视觉层

## 一、先判断是不是“功能还没跑顺”

如果下面任意 1 条为“否”，说明还不适合先做大 UI：

- [ ] 已经至少跑过 `2-3` 批真实案例
- [ ] 批量录入链路可以稳定走通
- [ ] 批量工作单可以稳定导出
- [ ] 工作单回看链路可以稳定看到最近记录
- [ ] 批次试跑记录可以稳定导出

如果这部分还没满足，优先继续跑真实案例，不优先做 UI 大改。

## 二、再判断是不是“已经知道用户卡在哪”

- [ ] 你已经能明确说出用户最卡的一步
- [ ] 你已经能明确说出哪段说明太长
- [ ] 你已经能明确说出哪个按钮应该前置
- [ ] 你已经能明确说出哪个输出块其实不常看
- [ ] 你已经能明确说出哪个结果块值得合并

如果这部分答不出来，说明 UI 优化还会偏猜测。

## 三、判断当前更该优化哪一层

### 1. 信息结构层

如果你发现这些问题更明显，先做信息结构：

- 模块太多，不知道先看哪
- 结果区块层级不清
- 用户看不出先做什么后做什么
- 页面像后台拼装，不像一条明确流程

### 2. 交互路径层

如果你发现这些问题更明显，先做交互路径：

- 按钮顺序不合理
- 用户总要回头找上一步结果
- 一个动作完成后，不知道下一步去哪
- 重复点击、重复读取太多

### 3. 视觉层

如果前两层已经比较清楚，再做视觉层：

- 版面密度过高
- 强弱关系不明显
- 重点不够突出
- 页面缺少产品感

## 四、当前项目推荐的 UI 优化顺序

### 第一阶段：只动结构，不动大视觉

优先改：

- 模块顺序
- 区块折叠/展开
- 主次按钮层级
- 状态提示文案

### 第二阶段：再动交互引导

优先改：

- 一步完成后的下一步提示
- 关键结果自动滚动到视图
- 历史记录和当前结果的切换
- 常用动作整合

### 第三阶段：最后做视觉统一

优先改：

- 视觉层级
- 卡片样式
- 字体与留白
- 产品感和统一性

## 五、进入正式 UI 讨论前，你最好准备好的材料

- `2-3` 批真实试跑记录
- 每批的批量工作单
- 每批最卡步骤的简短结论
- 你认为最该优化的 3 个模块
- 你认为最可以砍掉或合并的 2 个区块

## 六、当前判断

按照当前项目进度，你已经非常接近适合做 UI 讨论的时点。  
但最稳的方式仍然是：

1. 先跑 `2-3` 批真实案例
2. 用批次试跑记录沉淀真实摩擦
3. 再正式开始 UI 优化讨论

这样讨论出来的 UI 才是基于真实使用，而不是空想。
