# 页面交互说明

### 页面：主工作台

- 页面入口：
  用户进入 AI 封面创意助手后默认展示。
- 页面用途：
  承接用户的内容主题、内容目标、平台、素材状态和封面倾向，帮助用户快速开始首轮方向判断。
- 页面主区块：
  输入准备区、素材预览区、生成动作区、轻量说明区。
- 页面主状态：
  初始待输入、输入填写中、素材已上传、生成中、生成失败、已生成首轮结果。
- 页面主链路：
  用户补充内容信息和素材信息后，点击生成动作，系统进入首轮方向判断。
- 成功后的去向：
  页面展示首轮方向结果，并自动引导用户查看三个方向卡。
- 失败后的去向：
  页面保留已填内容，并在输入区附近提示需要调整的字段或重试动作。

#### 功能：输入准备

- 功能入口：
  主工作台输入准备区。
- 用户场景：
  用户已有内容想法或素材，但还没有明确封面方案，需要先把基础信息交给系统判断。
- 信息架构：
  包含内容主题、内容目标、目标平台、素材类型、素材描述、封面倾向、补充说明。
- 交互流程：
  用户按字段填写信息；上传本地参考图后，素材预览区展示文件名、尺寸或预览图；用户可清除素材并重新选择。
- 页面反馈与状态变化：
  必填信息缺失时，点击生成后在字段附近提示补充；素材上传失败时保留其他已填内容；生成中禁用重复提交。

#### 功能：首轮生成动作

- 功能入口：
  输入准备区底部的生成动作。
- 用户场景：
  用户完成最小输入后，希望获得可比较的封面方向。
- 信息架构：
  展示生成动作、生成中状态、生成失败反馈和结果承接提示。
- 交互流程：
  用户点击生成动作后，系统基于输入信息判断点击机制，并生成三个方向结果。
- 页面反馈与状态变化：
  生成中展示明确等待状态；生成成功后进入首轮方向结果；生成失败后提示重新生成并保留输入内容。

### 页面：首轮方向结果

- 页面入口：
  主工作台生成首轮结果后展示。
- 页面用途：
  让用户比较三个封面方向，并理解每个方向为什么成立。
- 页面主区块：
  方向卡列表、方向解释、标题建议、配图路径、风险提醒、下一步动作。
- 页面主状态：
  无结果、结果已生成、方向已选择、结果生成失败。
- 页面主链路：
  用户查看三个方向卡，选择一个方向作为后续深化基础。
- 成功后的去向：
  进入工作区深化或二轮修订。
- 失败后的去向：
  返回主工作台修改输入后重新生成。

#### 功能：三方向卡比较

- 功能入口：
  首轮方向结果区。
- 用户场景：
  用户需要从多个封面策略中选择一个最适合当前内容的方向。
- 信息架构：
  每张方向卡包含方向名称、点击机制、封面大字、标题建议、配图建议、适用理由和风险提醒。
- 交互流程：
  用户横向比较三个方向，点击某个方向后，该方向进入选中态，并显示后续可执行动作。
- 页面反馈与状态变化：
  方向选中后突出当前卡片；未选中方向保持可切换；风险提醒在卡片内就近展示。

#### 功能：方向解释

- 功能入口：
  每张方向卡内部。
- 用户场景：
  用户希望知道系统为什么推荐该方向，而不是只看到一句结论。
- 信息架构：
  包含适合内容、命中信号、点击理由、潜在风险。
- 交互流程：
  用户阅读方向解释后，可以决定选择当前方向或切换其他方向。
- 页面反馈与状态变化：
  解释内容保持简短可扫读，不遮挡主要选择动作。

### 页面：工作区深化

- 页面入口：
  首轮方向结果中的下一步工作区入口。
- 页面用途：
  把已选择的封面方向转化为更具体的素材处理、补图或概念生成任务。
- 页面主区块：
  工作区类型、路径内输入、建议生成动作、建议结果、反馈动作。
- 页面主状态：
  未进入工作区、待填写、建议生成中、建议已生成、建议已采纳、建议暂不采纳。
- 页面主链路：
  用户进入某个工作区，填写路径内关键信息，生成下一步建议，并标记是否采纳。
- 成功后的去向：
  已采纳建议可进入二轮修订或作为中间决策保存。
- 失败后的去向：
  保留工作区输入，并提示用户调整信息后重新生成。

#### 功能：工作区路径选择

- 功能入口：
  首轮方向结果后的工作区入口。
- 用户场景：
  用户已经选择一个方向，需要决定是优化现有素材、补内容贴合图，还是做创意概念图。
- 信息架构：
  包含优化现有素材、补内容贴合图、做创意概念图三个路径。
- 交互流程：
  用户选择路径后，页面展示该路径对应的输入项和建议生成动作。
- 页面反馈与状态变化：
  当前路径高亮；切换路径时保留首轮方向信息，路径内输入按当前路径重置或更新。

#### 功能：路径内建议生成

- 功能入口：
  工作区路径内的建议生成动作。
- 用户场景：
  用户补充路径内信息后，需要获得更具体的下一步操作建议。
- 信息架构：
  包含建议摘要、细化任务、下一步建议、风险检查、提示语草稿。
- 交互流程：
  用户填写路径内信息，点击生成建议，系统输出对应路径的下一步建议。
- 页面反馈与状态变化：
  生成中禁用重复点击；生成成功后展示建议结果；失败后保留路径内输入。

#### 功能：建议采纳反馈

- 功能入口：
  工作区建议结果区。
- 用户场景：
  用户需要标记当前建议是否可以作为后续修订基础。
- 信息架构：
  包含采纳、暂不采纳、当前反馈状态、继续调整入口。
- 交互流程：
  用户点击采纳后，建议进入已采纳状态，并出现进入后续调整的动作；用户点击暂不采纳后，页面提示可修改路径输入后重新生成。
- 页面反馈与状态变化：
  已采纳状态展示明确确认反馈；暂不采纳状态保留建议内容并强调可重新生成；未生成建议前不展示反馈动作。

### 页面：二轮修订

- 页面入口：
  方向卡选中后的一句话反馈入口，或工作区建议已采纳后的继续调整入口。
- 页面用途：
  接住用户对首轮方向或工作区建议的主观反馈，并生成更贴近意图的修订结果。
- 页面主区块：
  已选方向摘要、已采纳建议摘要、反馈输入、修订动作、二轮结果。
- 页面主状态：
  待反馈、反馈填写中、修订中、修订成功、修订失败。
- 页面主链路：
  用户输入一句反馈，系统识别保留项与修改项，并生成二轮修订结果。
- 成功后的去向：
  展示二轮结果，并允许用户继续记录案例或进入复盘。
- 失败后的去向：
  保留反馈内容，并提示用户调整反馈后重试。

#### 功能：一句话反馈

- 功能入口：
  二轮修订区反馈输入框。
- 用户场景：
  用户认可部分结果，但希望调整风格、强度、质感或点击感。
- 信息架构：
  包含已选方向、已采纳工作区建议、反馈文本、修订动作。
- 交互流程：
  用户输入一句反馈并点击修订，系统识别用户想保留和想调整的部分。
- 页面反馈与状态变化：
  反馈为空时提示补充修改意见；修订中禁用重复提交；修订成功后展示二轮结果。

#### 功能：二轮结果展示

- 功能入口：
  二轮修订完成后自动展示。
- 用户场景：
  用户需要看到修改后的封面方向，并理解这次修改回应了哪些反馈。
- 信息架构：
  包含新版封面大字、标题建议、配图方向、修改依据、风险提醒。
- 交互流程：
  用户查看二轮结果后，可继续记录案例或返回工作区重新调整。
- 页面反馈与状态变化：
  二轮结果突出修改点；原方向摘要保留为对比参照。

### 页面：案例复盘与规则沉淀

- 页面入口：
  主工作台的案例复盘入口，或二轮结果后的记录入口。
- 页面用途：
  将真实案例、批次试跑和人工复盘沉淀为后续规则优化依据。
- 页面主区块：
  真实案例入口、批次复盘入口、人工待补任务、导出状态、规则修订提示。
- 页面主状态：
  无待处理、存在待补字段、复盘进行中、导出已生成、正式写回待确认。
- 页面主链路：
  用户从真实案例或批次复盘进入，补充必要字段，生成复盘材料，并完成导出或写回确认。
- 成功后的去向：
  案例状态更新，并形成规则修订或复跑任务。
- 失败后的去向：
  页面提示失败原因，并保留可重试入口。

#### 功能：真实案例复盘

- 功能入口：
  案例复盘区中的真实案例入口。
- 用户场景：
  用户希望把实际封面案例补充完整，用于验证方向判断是否准确。
- 信息架构：
  包含案例状态、缺失字段、优先补充项、复盘材料生成动作。
- 交互流程：
  用户查看案例缺口，补充关键字段，生成复盘或回填材料。
- 页面反馈与状态变化：
  缺失字段按优先级展示；生成成功后展示导出状态；失败后保留当前补充内容。

#### 功能：批次复盘看板

- 功能入口：
  案例复盘区中的批次复盘入口。
- 用户场景：
  用户需要跨多个案例判断重复问题，并决定是否进入规则修订。
- 信息架构：
  包含批次状态、待补任务、人工结论、写回状态、下一步建议。
- 交互流程：
  用户查看批次复盘结果，补充人工结论，生成写回预览或规则修订任务。
- 页面反馈与状态变化：
  待补任务优先展示；正式写回前展示确认状态；未确认时不执行正式写回。
