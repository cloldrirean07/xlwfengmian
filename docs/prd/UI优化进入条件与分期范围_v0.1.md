# UI 优化进入条件与分期范围 v0.1

## 1. 文档目的

这份文档用于回答一个很实际的问题：

`AI 封面创意助手` 什么时候应该进入 UI 优化，以及优化时应该先改什么、后改什么。

当前结论不是“不做 UI”，而是：

- 先把产品主链路跑通
- 再进入有目标的 UI 优化
- 避免在规则、输入结构、工作台分区还在变化时，过早做大面积视觉返工

## 2. 当前阶段判断

截至目前，前端工作台已经具备以下核心能力：

- 第一轮输入与方向判断
- 三张方向卡输出
- 第二轮 refinement
- Prompt / LLM Draft 预览
- 真实案例录入预览
- 真实案例写入后的重读概览
- 从案例概览进入同步预览、回填优先项预览、完整回填工作单预览

这说明产品已经不再是单页 demo，而是进入了“可持续扩展的工作台”阶段。

但与此同时，下面几件事仍在收敛：

- 输入字段边界仍可能调整
- 规则系统还会继续补案例与反馈词映射
- 真实案例链路还在补强
- 后续还会接更真实的模型输出和结果解释

因此，当前最合理的判断是：

**现在可以继续写代码，但不适合立刻做大规模 UI 精修。**

## 3. 进入 UI 优化前，必须先稳定的主链路

只有当下面这条主链路稳定后，UI 优化才值得正式展开：

`输入内容/素材 -> 系统判断方向 -> 输出 3 个方向 -> 用户选中并二轮优化 -> 形成案例记录 -> 回看案例并继续维护`

换成当前系统内可验证的具体模块，就是：

1. 第一轮输入页稳定
2. 第一轮方向卡字段稳定
3. 第二轮优化字段稳定
4. Prompt / LLM Draft 结果区结构稳定
5. 真实案例录入、写入、重读、回填预览链路稳定

这里的“稳定”不是完全不改，而是指：

- 连续用至少 `2-3` 条真实案例跑完整流程
- 期间没有出现“整个分区要重拆”这类结构性返工
- 能明确知道哪些模块是高频核心区，哪些只是辅助区

## 4. 建议的 UI 启动时机

建议在以下条件同时满足后，再专门开一次 UI 优化讨论：

### 4.1 业务条件

- 已跑通至少 `2-3` 条真实案例完整链路
- 用户输入字段已经基本稳定
- 3 张方向卡的核心展示字段已经基本稳定
- 二轮 refinement 的输入输出结构已经基本稳定

### 4.2 产品条件

- 能明确区分“高频使用区”和“低频运维区”
- 能判断手机端最短路径和电脑端专业路径是否要分层
- 已经知道用户最容易卡在哪一步

### 4.3 代码条件

- 前端状态管理和渲染模块不再频繁大改
- API 返回结构短期内不会大改
- 现有工作台分区名称和顺序基本确定

## 5. UI 优化时应先改什么

进入 UI 阶段后，优先顺序建议如下：

### 第一优先级：信息结构优化

目标不是先“变好看”，而是先“更易用”。

优先处理：

- 页面主路径是否过长
- 哪些区块应该默认展开，哪些应该收起
- 第一轮结果、第二轮结果、案例维护区是否抢注意力
- 用户是否能快速看懂下一步该做什么

### 第二优先级：操作效率优化

优先处理：

- 高频输入是否能更短路径完成
- 图片上传、参考图预览、方向选择是否顺手
- 结果卡片之间的比较是否足够直观
- 二轮反馈输入是否足够自然

### 第三优先级：视觉风格优化

在信息结构与交互顺序稳定后，再统一处理：

- 视觉层级
- 颜色体系
- 字体与模块节奏
- 卡片样式一致性
- 移动端与桌面端的视觉差异

## 6. 当前阶段不建议做的 UI 工作

现在先不建议投入较多时间做下面这些事：

- 大面积重写视觉风格
- 过早做高保真营销页
- 先做大量动画或复杂过渡
- 在真实高频路径不明确前，先做复杂导航体系
- 为尚未稳定的模块做精细组件化皮肤

原因很简单：

这些工作会消耗大量时间，但当前产品的主要不确定性还在“能力与链路”，不在“装饰与包装”。

## 7. 当前阶段最合理的并行做法

当前更建议采用“轻结构、重链路”的并行方式：

1. 继续补真实案例和规则系统
2. 继续完善输入 -> 建议 -> 反馈 -> 案例沉淀的闭环
3. 仅做必要的轻量界面整理

这里的“轻量整理”包括：

- 分区标题更清楚
- 高低频区块适度分层
- 结果区更容易扫描
- 按钮文案更明确

这类优化可以做，因为它们不会造成大规模返工。

## 8. 推荐的 UI 讨论切入点

当进入正式 UI 优化阶段时，建议不要直接讨论“什么颜色更好看”，而是先讨论这四件事：

1. 首页是不是工作台，还是应该拆成入口页 + 工作页
2. 手机端和电脑端是不是同一套信息结构
3. 第一轮、第二轮、案例维护是否要拆成分步流
4. 用户真正高频的路径到底是“从零想方向”，还是“基于已有素材改封面”

只有这四件事先定了，视觉优化才不会做偏。

## 9. 当前结论

当前最合适的节奏是：

- **现在继续写代码，继续补主链路**
- **先做必要的轻量 UI 整理**
- **等 2-3 条真实案例跑通后，再专门讨论系统性 UI 优化**

一句话概括：

**UI 要优化，但应该在产品主链路稳定之后，以信息结构优先、视觉风格后置的方式进入。**
